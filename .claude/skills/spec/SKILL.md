# /spec — 기능 명세 작성 스킬

## 역할
기능 명세(Specification)를 작성한다.
사용자가 `/spec {기능명}` 형태로 호출하면, `spec/spec-{nnn}-{title}.md` 파일을 생성한다.

## 절차

1. `spec/` 디렉토리의 기존 Spec 번호를 확인해 다음 번호를 결정한다.
2. 기능에 맞는 **구체적인** 제목을 결정한다.
3. 아래 템플릿으로 Spec 파일을 작성한다. 날짜는 오늘 날짜를 사용한다.
4. 파일 경로와 핵심 내용을 사용자에게 요약한다.

## Spec 작성 규칙

- **간결하게**: 각 섹션은 핵심만.
- **구체적 제목**: ❌ "운동 기능" → ✅ "Zone 2 심박수 실시간 피드백"
- **검증 가능한 기준**: AC(수락 기준)는 테스트 가능한 형태로 작성.
- **범위 명확화**: 이 Spec에 포함되지 않는 것도 명시.
- **기호 규칙**: `·` 기호 사용 금지. 열거는 `,` 또는 `/`, 강조는 `-` 사용.

## 템플릿

```markdown
# Spec-{nnn}: {구체적 제목}

- **상태**: Draft | Review | Approved | Implemented
- **날짜**: YYYY-MM-DD
- **관련 ADR**: `arch/adr-{nnn}-{title}.md` *(있을 경우)*

## 목표
(이 기능이 해결하는 문제. 1~3문장)

## 범위
**포함**: …
**제외**: …

## 기능 명세

### 주요 흐름
1. …
2. …

### 예외 처리
- …

## 수락 기준 (AC)
- [ ] AC-1: …
- [ ] AC-2: …
- [ ] AC-3: …

## 미해결 사항
- [ ] …
```
