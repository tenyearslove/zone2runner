# /adr — ADR 문서 작성 스킬

## 역할
아키텍처 결정 기록(Architecture Decision Record)을 작성한다.
사용자가 `/adr {주제}` 형태로 호출하면, `arch/adr-{nnn}-{title}.md` 파일을 생성한다.

## 절차

1. `arch/` 디렉토리의 기존 ADR 번호를 확인해 다음 번호를 결정한다.
2. 주제에 맞는 **구체적인** 제목을 결정한다 (포괄적 제목 금지).
3. 아래 템플릿으로 ADR 파일을 작성한다. 날짜는 오늘 날짜를 사용한다.
4. 파일 경로와 핵심 결정 포인트를 사용자에게 요약한다.

## ADR 작성 규칙

- **간결하게**: 각 섹션은 핵심만. 불필요한 배경 설명 지양.
- **구체적 제목**: ❌ "데이터 레이어 설계" → ✅ "심박수 로컬 캐시 전략"
- **대안 필수**: 반드시 2~3개 대안을 비교한 후 결정. 대안 없는 ADR은 작성하지 않는다.
- **결정 유보 가능**: 정보 부족 시 상태를 `Proposed`로 유지하고 결정 보류.
- **기호 규칙**: `·` 기호 사용 금지. 열거는 `,` 또는 `/`, 강조는 `-` 사용.

## 템플릿

```markdown
# ADR-{nnn}: {구체적 제목}

- **상태**: Proposed | Accepted | Rejected | Deprecated
- **날짜**: YYYY-MM-DD
- **결정자**: (이름 또는 팀)

## 맥락
(이 결정이 필요한 이유. 2~4문장)

## 결정

### 대안 비교

| 기준 | 대안 A | 대안 B | 대안 C |
|------|--------|--------|--------|
| 항목1 | | | |
| 항목2 | | | |
| 항목3 | | | |

### 대안 A: {이름}
- 장점: …
- 단점: …

### 대안 B: {이름}
- 장점: …
- 단점: …

### 대안 C: {이름} *(있을 경우)*
- 장점: …
- 단점: …

### 채택: 대안 {X}
(선택 이유 1~3문장)

## 결과
(이 결정으로 인한 영향. 긍정/부정 모두 기술)

## 관련 문서
- Spec: `spec/spec-{nnn}-{title}.md`
- ADR: `arch/adr-{nnn}-{title}.md`
```
