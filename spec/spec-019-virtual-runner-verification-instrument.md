# Spec-019: VirtualRunner 강화 — 검증 계측기(사람 같은 폐루프 러너)

- **상태**: Draft
- **날짜**: 2026-07-06
- **관련 요구**: spec-002 QA5 테스트가능성/QA3 제어가능성(판정/코칭 방향)/QA2 기능적응성(개인화 수렴), adr-025(AI 방법 선택 — AI≠NN), `spec/archive/`(예측/동역학 계열 폐기 — adr-024로 분석 엔진 대체)
- **구현 위치**: `app/` domain/VirtualRunner.kt, sim/SimRunnerSource.kt, RunActivity(선택 UI)

## 배경과 목적

실주행 데이터 수집이 어렵다(참값 라벨도 없다, C04). 그래서 **가상러너 폐루프 시뮬이 이 앱의 주
검증 계측기**다 — 앱 코칭 → 러너 반응 → 심박 변화 → 토크테스트 응답 → 개인화 학습의 루프를 시뮬
안에서 돌려, 실기기/실주행 없이 판정과 코칭 방향(QA4 제어가능성)/개인화 수렴(QA2 기능적응성)/예측 보정(구 spec-018, spec/archive)을 검증한다(§12 실적 — 구 지표 서술은 당시 체계 기준).

현재 VirtualRunner는 (1) 고정 파라미터 소수, (2) 미미한 노이즈, (3) **경사가 항상 0**(경사 판정/코칭
미검증), (4) 피로/컨디션/센서 아티팩트 없음 — 실사람과 거리가 있다. 본 스펙은 이를 **"설정 가능한
조건 + 그 범위 안에서 사람처럼 발현되는 randomness"**로 강화한다.

## 설계 원칙

1. **모집단 샘플링**: 러너는 점값이 아니라 **범위/분포**로 정의(`VirtualRunnerSpec`). 세션 시작 시
   `sample(rng)`로 구체 러너를 뽑는다 → 같은 아키타입도 매번 다른 개인이 나온다(다양성 + 재현성=seed).
2. **결정적 재현성**: 모든 randomness는 seed 기반. 같은 seed = 같은 세션(회귀 테스트 가능).
3. **정직성**: 시뮬은 앱 파이프라인과 **독립**(같은 물리를 공유하지 않음). 러너의 "진짜 임계"
   (trueUpperBpm)만 정답으로 쓰고, 앱이 그걸 모른 채 수렴하는지가 검증. 시뮬로 학습한 모델을 시뮬로
   채점하는 자기참조를 피한다(EXPERIMENT_LOG §8 교훈).

## 러너 특성 (VirtualRunner 필드)

### 신체 (physiology)
| 필드 | 의미 | 예 범위 |
|------|------|------|
| age/restingHr/maxHr | 기본 신체 | — |
| trueZone2UpperHrmaxFrac | **진짜 유산소 임계(%HRmax) = 정답** | 0.60~0.75 |
| hrLagSec | 심박 1차 지연(체력) | 18~40s |
| driftRate | 카디악 드리프트 계수 | 0.25~0.6 |
| driftHeatK | 기온 민감도(더울수록 드리프트↑) | 0~0.4 |
| fatigueRate | 세션 후반 같은 강도의 HR 비용 상승 | 0~0.06 |
| hrNoiseSd | 박동 관측 노이즈(bpm) | 0.5~2.0 |

### 스타일/행동 (behavior)
| 필드 | 의미 | 예 범위 |
|------|------|------|
| basePaceMinKm | 편한 기준 페이스 | 4.5~7.5 |
| pacingDiscipline | 0=초반 과속/진동, 1=일정 유지 | 0.2~0.95 |
| cadenceBase | 케이던스 기준 | 155~185 |
| coachingResponsiveness | 코칭 순응(0~1) | 0.05~0.95 |
| coachingLagSec | 코칭 반응까지 지연 | 3~20s |
| surgeProneness | 돌발 서지(신호/추월) 빈도 | 0~1 |
| talkBias | 토크테스트 개인 편향(과대/과소 보고) | -0.1~0.1 (HRR frac) |
| talkNoise | 토크테스트 주관 흔들림 | 0.05~0.3 |

### 세션 환경/컨디션 (session)
| 필드 | 의미 | 예 범위 |
|------|------|------|
| terrainHilliness | 코스 언덕 정도(0=평지, 1=산악) | 0~1 |
| tempC | 기온(더위=드리프트↑) | 5~32℃ |
| dayCondition | 그날 컨디션(-1 나쁨~+1 좋음, 임계/RHR 미세 이동) | N(0,0.5) |

## 세션 내 확률 과정 (사람 같은 randomness)

매 초 다음이 겹쳐 실사람 같은 시계열을 만든다(모두 seed 기반):
1. **워밍업**: 초반 HR 상승 + 저discipline 러너의 초반 과속(시간 감쇠).
2. **경사(신규)**: `terrainHilliness`로 언덕 프로파일 생성 → 매 초 slope(%)를 Sample에 실어보냄.
   오르막은 같은 페이스에 effort↑→HR↑(앱 경사 판정/코칭 검증), 내리막은 반대.
3. **카디악 드리프트**: 임계 초과분 + 기온(driftHeatK)으로 누적, 회복 시상수.
4. **피로**: 경과시간×fatigueRate로 같은 effort의 HR 비용을 점증(후반 페이스 처짐/HR 상승).
5. **미세 변동**: 호흡/보폭 노이즈(effort gaussian), 케이던스 흔들림.
6. **돌발 서지/감속**: surgeProneness 확률로 수초간 페이스 급변(신호등/추월/오르막 회피) 후 복귀.
7. **코칭 반응**: coachingLagSec 지연 후 coachingResponsiveness만큼 목표 강도 조정(무시형도 존재).
8. **자기조절**: 진짜 임계 훨씬 위 지속 시 스스로 감속.
9. **센서 아티팩트(신규)**: 낮은 확률로 (a) HR 드롭아웃(접촉 불량 → 무효/-1, OutlierGuard/브리지 검증),
   (b) 스파이크(순간 튐 → 이상치 기각 검증).
10. **토크테스트 응답**: 진짜 임계 대비 현재 심박 + talkBias + talkNoise → 3단계(편함/보통/벅참, spec-016 개정).

## 프리셋 + 랜덤 생성

- **아키타입 프리셋**(범위 spec) 확대: 균형형/초보 과속형/베테랑 절제형/코칭 순응/코칭 무시/
  **더위 취약형/언덕 코스/불안정 센서(테스트)** 등.
- **랜덤 러너**: `VirtualRunner.randomHuman(seed)` — 모집단 범위에서 상관을 고려해 그럴듯한 사람을
  샘플(예: 체력 좋으면 hrLag↓/discipline↑/임계↑ 경향). UI "🎲 랜덤 러너"로 매번 새 사람.

## UI (RunActivity, 자동 시나리오 모드)

- 가상러너 피커에 **랜덤 러너** 항목 추가(누를 때마다 새 사람 샘플, 이름에 요약 표기).
- **환경 조건**: 코스(평지/완만/언덕/산악)와 기온을 고르는 칩(선택) — 러너와 독립적으로 조합.
- UI엔 설계 용어(spec/trait명) 노출 금지 — 친근한 라벨만.

## 수락 기준 (AC)

- AC1: `VirtualRunnerSpec.sample(rng)`가 모든 필드를 정의 범위 안에서 뽑는다(전 필드 자동 검증).
- AC2: 같은 seed → 동일 세션(샘플 시퀀스 일치), 다른 seed → 유의미하게 다른 세션.
- AC3: terrainHilliness>0면 slope가 0이 아닌 값으로 Sample에 실린다(경사 판정 경로 활성).
- AC4: 센서 아티팩트가 설정 확률대로 발생하고 OutlierGuard가 그 무효/스파이크를 걸러낸다.
- AC5: 기존 PRESETS 기반 검증(§12 예측 보정 하네스)이 계속 통과한다(하위 호환).
- AC6: randomHuman 100명 샘플이 모두 생리적으로 타당(범위 내, maxHr>restingHr 등).

## 검증 계획

- 단위 테스트: AC1~6.
- 활용(후속): 이 강화된 러너로 (a) 개인화 수렴(QA2 기능적응성: uFrac→trueUpper) (b) 경사 코칭 방향(QA4 제어가능성)
  (c) 예측 보정(§12 재실행)을 폐루프로 정량 검증 → report 근거.
