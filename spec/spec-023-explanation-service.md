# spec-023 설명 서비스 (설명용이성 QA 강화)

- 상태: 구현 완료(FR1~FR6). 빌드/테스트 통과, 폰 설치
- 관련: report-007(QA 척추, 설명용이성=정체성), 강의 AI System 아키텍처의 "설명 서비스(Explanation Service)",
  spec-020(개인화 시각화/설명), adr-002(코칭 무결성), adr-020(예측 분해), adr-013(규칙 판정)

## 배경 / 목적

설명용이성은 우리 프로젝트의 정체성 QA다(report-007). "왜 이렇게 판단/코칭했는지"를, 러닝 중 실시간이
어렵더라도 **사후에라도** 사용자에게 충분히 전달한다. 흩어진 설명 기능을 **"설명 서비스" 컴포넌트**로 묶어
강화한다(강의 아키텍처의 설명 서비스 = 설명 생성 → 설명 결과 저장).

## 관통 원칙 (무결성 + 생성 시점)

- **사실은 규칙/물리가 확정, LLM은 표현만**(지어낸 수치 0). 기존 DirectionGuard/PersonalizationExplainer 원칙 유지.
- **LLM 생성은 "리포트 생성(세션 종료)" 시점에 1회만.** 생성 결과를 저장하고, 이후 조회(프로필/리포트 재열람)는
  **저장된 텍스트를 표시할 뿐 LLM을 재호출하지 않는다**(사용자 요청, 비용/지연/가용성 회피).
- **러닝 중이 아니면 TTS 없음.** 정지 상태의 모든 설명은 텍스트로 제공(TTS는 러닝 중 음성 코칭 전용).

## 기능 요구 (FR)

- FR1 (기반) 개인화 설명을 **세션 종료 시 1회 생성**(LLM 가용 시 풀이, 미가용 시 규칙 팩트)해 **프로필별 저장**.
  프로필 화면은 저장된 텍스트만 표시. **온디바이스 LLM 온-디맨드 버튼/TTS 제거.**
- FR2 (#1) **세션 스토리("이번 러닝 왜 이렇게 코칭했나")**: 리포트 생성 시 규칙 팩트 시트(존 이탈 구간/각 코칭
  트리거/드리프트/개인화 변화)를 근거로 LLM이 한국어 스토리 2~4문장 생성 → 리포트에 표시 + 세션에 저장(재사용).
  LLM 미가용 시 규칙 요약 폴백.
- FR3 (#2) **코칭 로그 "왜" 태그**: 각 코칭 줄에 발화 사유(초과/미달/곧 초과(예측)/정지/드리프트↑ 등)를 규칙으로 부착.
- FR4 (#4) **판정 "왜 이 존" 미니 설명**: 러닝/리포트에서 "지속심박 138 vs 상한 140 → 유지"처럼 경계 비교를 노출.
- FR5 (#5) **드리프트→코칭 인과**: 리포트 유산소 분석에서 후반 드리프트가 코칭을 유발한 관계를 문장으로 연결.
- FR6 (#3) **개인화 시각화 확장**: 경계 밴드/스파크라인에 더해 **예측 개인화(τ/드리프트)** 요약 + 스파크라인 각
  세션 점에 무엇이 바꿨는지(말하기 방향/횟수) 주석.

## 비목표
- 러닝 중 실시간 LLM 설명(포그라운드/지연/배터리 제약, adr-007). 실시간은 규칙 분해(추세/드리프트)로 충분.
- 설명 편집 UI. 다국어(한국어 우선).

## 설계
- `coaching/SessionExplainer.kt`: 세션 팩트 시트(규칙) + LLM 프롬프트 + 규칙 폴백. (PersonalizationExplainer와 형제.)
- 저장: 개인화 설명 → `LearnedZone`(프로필별). 세션 스토리 → 세션 리포트(SessionStore/RunReport)에 필드 추가.
- 생성 시점: `RunActivity.finalizeSession`에서 규칙 팩트 조립 후 LLM 1회(백그라운드) → 저장.
- 표시: ProfileActivity(개인화 설명, 텍스트) / ReportActivity(세션 스토리 + 코칭 why + 드리프트 인과 + 판정 why).

## 수용 기준 (AC)
- AC1 프로필에서 LLM 온-디맨드 호출/TTS 없음. 저장된 설명(또는 규칙 팩트) 텍스트만 표시.
- AC2 리포트에 세션 스토리 표시. 재열람 시 LLM 재호출 없이 저장본 표시.
- AC3 코칭 로그 각 줄에 사유 태그. 판정 미니 설명(경계 비교) 노출.
- AC4 LLM 미가용 시 모든 설명이 규칙 문장으로 폴백(공백 없음).
