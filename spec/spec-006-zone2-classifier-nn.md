# Spec-006: Zone 2 분류 NN 설계 및 학습

- **상태**: Superseded by spec-014 (2026-07-03, adr-013)
- **날짜**: 2026-07-01
- **관련 ADR**: `arch/adr-005-zone2-classifier-nn.md` (DP4, Superseded)

> **Supersede 경위(2026-07-03)**: 시뮬레이터 라벨 순환으로 실기기 판정 결함 발생(adr-013 맥락 참조).
> 판정은 규칙 전환, NN은 심박 동역학 모델(`spec/spec-014-hr-dynamics-model.md`)로 재조준.
> 본 문서의 특징 정의/학습 파이프라인 구조는 spec-014가 계승한다.

## 목표

다변량 러닝 신호를 Zone 2 상태(미달/유지/초과)로 분류하는 경량 MLP를 설계, 학습, 평가, 온디바이스 배포한다. 이 문서는 구현 직전 단계로 아키텍처/특징/라벨/학습절차/평가/배포/연동을 정의한다.

## 범위

**포함**: 특징 정의, MLP 아키텍처, 학습 데이터/라벨 생성, 학습 절차, 평가 프로토콜, TFLite 배포, 규칙/Bayesian 연동.

**제외**: 실제 학습 코드, 판정 히스테리시스 상수(adr-003), 개인화 갱신식(spec-004).

## 1. 입력 특징 (feature)

| 특징 | 설명 | QA 연결 |
|------|------|------|
| hr_norm_u | 지속 HR을 개인 **상한** 경계로 정규화 (hr_frac - u_est) | QA3 (개인화) |
| hr_norm_l | 지속 HR을 개인 **하한** 경계로 정규화 (hr_frac - l_est) | QA3 (개인화) |
| dHR | HR 변화율 (bpm/s) | 추세 |
| pace | 지속 페이스 (윈도우 평균) | 다신호 |
| spm | 케이던스 (steps/min) | 다신호 |
| decoupling | 최근 윈도우 Pw:HR 디커플링 | Drift 반영 |
| slope | 고도 경사 (%) | 오르막 보정 |

HR을 개인 Bayesian 경계(상한 μ, 하한 = μ - band)로 정규화하므로 **분류기가 개인화된다**
(QA3는 DP3가, 판정은 DP4가 담당하되 입력으로 물림). 지속(윈도우 평균) 값을 쓰는 이유는
Zone 상태가 순간이 아니라 지속 강도 개념이기 때문 (PoC에서 순간값 대비 정확도 향상 확인).

## 2. 모델 아키텍처

경량 MLP (온디바이스 목표):

```
입력(7) → FC(32) → ReLU → Dropout → FC(16) → ReLU → FC(3) → softmax
출력: [P(미달), P(유지), P(초과)]
```

- 파라미터 수 천 단위 → 추론 ms급, TFLite 수십 KB
- 시계열 표현이 필요하면 향후 1D-CNN/GRU로 확장 여지(현재는 순간 특징 벡터)

## 3. 학습 데이터 및 라벨

지도학습이며, 라벨은 **물리 시뮬레이터(spec-004 §8)**가 생성한다. 참 경계 θ*를 알고 생성하므로 라벨이 정확하다.

```
데이터 생성:
  다양한 가상 러너 프로파일 × 조건(평지/오르막/내리막, drift 강/약, 노이즈 수준)
  각 시점: 특징 벡터 추출 + 참 Zone 라벨(θ* 기준 미달/유지/초과)
  분할: train / val / test (러너 단위 분할로 누수 방지)
증강(QA2):
  센서 노이즈, 이상값 스파이크, 결측 주입 샘플 추가
(선택) 공개 러닝/HR 데이터셋으로 현실성 sanity check
```

## 4. 학습 절차

```
손실: cross-entropy (클래스 불균형 시 가중치)
옵티마이저: Adam
정규화: dropout / early stopping (val loss 기준)
epoch: 수십 회 규모
프레임워크: PyTorch (오프라인 학습)
산출물: 학습된 모델 → ONNX/TFLite 변환
```

## 5. 평가 프로토콜

| 지표 | 목표 | QA |
|------|------|-----|
| 전체 정확도 | ≥ 85% (계획서 지표) | QA1 |
| 혼동행렬 | 인접 오분류(유지↔초과) 중심 | QA1 |
| 조건별 정확도 | 오르막/Drift 구간에서도 유지 | QA1 |
| 노이즈 스트레스 정확도 | 노이즈 주입 시 정확도 저하 한계 이내 | QA2 |
| 규칙 대비 향상폭 | 단일 임계값 baseline 대비 정확도 향상 | 설계 정당성 |

**규칙 baseline 대비 향상폭**은 "왜 NN이 필요했나"의 실증 근거가 된다(보고서 구현·검증).

## 6. 온디바이스 배포 및 후처리

```
TFLite 모델 온디바이스 로드
실시간: 특징 벡터 → MLP 추론 → 3클래스 확률
후처리:
  규칙 안전 가드: 출력이 생리 안전범위와 모순되면 규칙으로 보정 (QA2)
  히스테리시스: 경계 근처 떨림 억제
  콜드스타트: 개인 데이터/신뢰도 부족 시 규칙 baseline 판정으로 폴백
```

## 7. 다른 컴포넌트와의 연동

| 컴포넌트 | 관계 |
|------|------|
| DP3 Bayesian 개인화 (spec-004) | 개인 경계로 HR_norm 정규화 제공 → 분류기 개인화 |
| DP1 규칙 (adr-003) | prior/폴백/안전 가드 제공 |
| HR 파이프라인 (spec-003) | 특징 입력 소스(HrSource) |
| 코칭 (spec-005) | 분류 결과(상태)를 코칭 의도 결정 입력으로 전달 |

## PoC 검증 결과 (2026-07-02, ml/ 구현)

시뮬레이터 150명/1200세션(약 40만 샘플), 러너 단위 분할. 상세/튜닝여정은 `ml/README.md`, `ml/EXPERIMENT_LOG.md`.
Zone2 판정은 실측 정답이 없어 QA는 판정 정확도가 아니라 **코칭 방향 정확성**으로 평가한다.

| 지표 | 결과 | 목표 | 달성 |
|------|:---:|:---:|:---:|
| **QA1 코칭 방향 정확성** (반대방향 오판 없음) | 0.996 | 0.95 | O |
| **QA2 이상치(40~220밖) 기각율** | 1.000 | 1.0 | O |
| 오르막 / 고드리프트 구간 정확도 | 0.831 / 0.831 | - | 유지 |
| (참고) 3분류 개발 정확도 | 0.828 | - | 내부 지표 |

설계 결정 기여도: 규칙 0.544 → +MLP(DP4) 0.802 → +개인화(DP3) 0.828. NN이 규칙 대비 +26%p,
개인화가 +3%p로 각 결정의 정당성 실증. 센서 측정 노이즈는 범위 밖(센서 소관)으로 제외,
강건성(QA2)은 이상치 필터링으로 달성.

## 수락 기준 (AC)
- [ ] AC-1: 코칭 방향 정확성(반대방향 오판 없음) 95% 이상 (QA1). 판정 실측 정답이 없으므로 이 지표로 평가
- [ ] AC-2: 생리범위(40~220) 밖 이상치 기각율 100% (QA2). 센서 측정 노이즈는 범위 밖
- [ ] AC-3: 단일 HR 임계값 baseline 대비 정확도 향상 실측 (NN 도입 정당성)
- [ ] AC-4: 콜드스타트에서 규칙 baseline 폴백으로 정상 판정 (C02)
- [ ] AC-5: TFLite 모델이 온디바이스에서 ms급 추론 (QA4)
