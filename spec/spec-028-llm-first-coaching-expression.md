# Spec-028: LLM 우선 코칭 표현 — 직생성 + 간결 프롬프트 + 단어 수준 폴백

- **상태**: Approved (2026-07-23, 사용자 결정 기반) / Implemented
- **관련**: `arch/adr-028`(결정 정본), `arch/adr-002`(방향=규칙 골격), `spec/spec-005`(구 경로 — 본 spec이 표현 경로 대체), `spec/spec-024`(페르소나 — LLM 전용으로 축소), `spec/spec-027`(감사 기록 = 본 기능 실측 수단), `spec/spec-008`(안전 가드 불변)

## 목표

코칭 문장의 정본을 **LLM 직생성**으로 옮긴다. 규칙은 판단(방향/사실/타이밍)만 확정하고, 언어는 LLM이 만든다. 사람이 조합하는 언어는 (1) 간결 프롬프트 템플릿, (2) 단어 수준 폴백 큐 10여 개, (3) 안전 가드 고정 문구만 남긴다.

## 기능 명세

### FR1 — LLM 직생성 경로 (지원 단말 1순위)

- 입력: `CoachContext`(규칙이 확정한 판단/사실 숫자) + 페르소나 키 + 언어.
- 프롬프트(간결 구조화, `CoachPrompt` 재작성): `러닝 코치. 말투: {말투 한 단어}. 상황: {사실 목록 — 심박 145(목표 117~132), 오르막, 기온 31도…}. 임무: {임무 한 문장}. 한국어 한 문장, 35자 내외, 따옴표/이모지 없이, 숫자는 상황에 준 것만.`
- 임무 종류: 방향 3종(가속/감속/유지 — 방향어 포함 강제) + 특수 6종(마일스톤/워밍업/회복/오르막 예방/관절 보호/드리프트 여유). **특수 코칭도 LLM 직생성**.
- 템플릿은 `assets/coach_prompt.json` 외부화 유지(adr-002), 실패 시 내장 기본.

### FR2 — 출력 가드레일

1. 형식 가드: 최대 2문장/90자/이모지·따옴표 제거(기존 유지).
2. **숫자 무결성 가드(신설, 언어 무관)**: 출력의 모든 숫자가 허용 집합(컨텍스트의 심박/경계/케이던스/기온/마일스톤/페이스/경과분 + 상수 2[Zone 2])의 부분집합이 아니면 기각. "없는 숫자 금지" 제1원칙의 기계 검증.
3. 방향 가드(DirectionGuard, 한국어): 방향 코칭에 기존 검사 유지. 특수 코칭 중 워밍업/오르막 예방/관절 보호는 **가속 명령어 금지 검사만**(방향이 없으므로), 마일스톤/회복은 형식+숫자 가드만.

### FR3 — 폴백: 단어 수준 큐

- 페르소나 4벌 문장 세트 폐기 → 중립 큐로 대체(전량):

| 상황 | 큐 |
|---|---|
| 미달 | "속도 올리기" |
| 초과 | "속도 줄이기" |
| 유지 | "좋아요, 유지" |
| 드리프트 여유 / 후반 | "심박 오르는 중, 여유" / "후반, 페이스 유지" |
| 마일스톤 | "Zone 2 {n}분 유지 성공" |
| 워밍업 / 회복 | "천천히 시작" / "회복 중" |
| 오르막 예방 | "오르막 앞, 미리 감속" |
| 관절 보호 | "내리막, 무릎 보호, 보폭 줄이기" |

- 발동 조건: LLM 미지원 단말(기능 UNAVAILABLE/미다운로드) 또는 해당 호출의 실패/기각(그 1회 한정). 지원 단말에서 폴백이 상시화되면 결함으로 본다(감사 기록으로 검출).
- **로딩 보류(2026-07-23 사용자 결정)**: 세션 시작 직후 모델 준비(상태 확인+워밍업, 최대 ~30초) 중에는 **코칭을 보류(무음)** 한다 — 로딩 중 폴백 문구를 내지 않고, 준비 확정 후 LLM(가용) 또는 단어 폴백(미가용)으로 재개. 보류된 시도는 코칭 라인/감사 기록을 만들지 않고 코칭 슬롯을 반환해 다음 틱에 재시도한다. 시뮬 디버그 뷰에 "LLM 모델 준비 중…" 표시.
- 케이던스/더위 부가 조언은 폴백에서 제거(LLM 경로가 사실로 반영) — 문장 조합 소멸.

### FR4 — 페르소나/다국어

- 페르소나 = 프롬프트의 말투 단어(보통/짧고 단호한 명령형/친한 친구 반말/차분한 존댓말)로만 존재. 폴백은 중립.
- 다국어(후속): 프롬프트의 언어 지시 교체 + 폴백 큐/UI의 표준 리소스 번역. 방향 가드는 한국어 외 언어에서 형식+숫자 가드로 대신(정직한 한계, adr-028).

### FR5 — 폐지/불변

- 폐지: 코칭 경로의 Nano Rewriting(`NanoRewriter` 제거), 페르소나 문장 세트, 규칙 문장 조합(케이던스/더위 절 접합).
- 불변: 판단=규칙(방향/타이밍/안전), SafetyGuard LLM 미경유, NanoSummarizer(리포트 요약), 감사 기록(spec-027 — engine/path 라벨은 새 경로 반영).

## 수락 기준 (AC)

- AC-1: LLM 지원 단말에서 방향/특수 코칭 문장이 LLM 직생성으로 나가고(감사 기록 engine=nano-prompt), 프롬프트 길이가 기존 대비 유의미하게 짧다(감사 기록 promptChars로 확인).
- AC-2: 출력에 입력 사실에 없는 숫자가 포함되면 기각되고 단어 큐로 폴백한다(단위 테스트).
- AC-3: 방향 코칭의 방향 모순 기각(DirectionGuard) 동작 유지. 워밍업/오르막 예방/관절 보호에서 가속 명령어가 나오면 기각.
- AC-4: LLM 미지원/실패 시 코칭이 끊기지 않고 단어 큐가 나간다(무중단 폴백 유지).
- AC-5: 전체 단위 테스트 그린. 폴백 큐 전량이 해당 방향의 DirectionGuard를 통과한다.

## 검증

- 단위: NumberGuard/폴백 큐/새 프롬프트 렌더 테스트. 통합: 기존 RunEngine 테스트 그린.
- 실기기: 모델 다운로드 완료 후 시뮬 세션 → 리포트 "LLM 사용" 카드에서 nano-prompt 채택률/기각 사유 확인(spec-027).
- **실시간 비교 도구**: 시뮬 대시보드의 **LLM on/off 토글** — 끄면 다음 코칭부터 단어 폴백이 나가고 감사 기록에 `rule(LLM 꺼짐)`으로 남아, 같은 세션 안에서 LLM 직생성 대 단어 폴백을 구간별로 비교할 수 있다.
