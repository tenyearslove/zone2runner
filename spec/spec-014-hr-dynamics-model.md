# Spec-014: 개인 심박 동역학 모델 — 예측 NN과 목표 페이스 제안

- **상태**: Draft (adr-013 Accepted에 따른 명세)
- **날짜**: 2026-07-03
- **관련 ADR**: `arch/adr-013-zone2-judgment-role-separation.md` (판정 역할 재분리)
- **대체**: `spec/spec-006-zone2-classifier-nn.md` (판정 MLP - Superseded)

## 목표

30~60초 뒤 심박을 예측하는 회귀 NN(개인 심박 동역학 모델)을 설계/학습/평가/온디바이스 배포하고,
이를 역질의해 "지금 Zone2에 머무는 페이스"를 제안한다. 동시에 Zone 판정을 규칙(지속 심박 vs
개인화 경계 + 히스테리시스)으로 전환해 판정-밴드 모순을 구조적으로 제거한다.

라벨 원칙(adr-013): 정답 = 실제(시뮬 관측) 미래 심박. 시뮬레이터가 라벨을 "정의"하지 않고
"관측"만 제공한다 - spec-006의 라벨 순환 결함 재발 방지.

## FR

- FR1 (판정): Zone 판정 = 지속 심박(60초 평균) vs 개인화 경계(bpm)의 결정적 비교.
  히스테리시스: 상태 전환은 새 상태 방향으로 경계 ±2bpm을 넘을 때만(채터링 억제).
  판정과 밴드 표시가 같은 경계를 참조하므로 모순 불가능.
- FR2 (예측): 현재 상태 + 유지할 페이스를 입력으로 30초/60초 뒤 심박(HRR 비율)을 회귀 예측.
- FR3 (페이스 제안): 후보 페이스를 모델에 스윕해 60초 뒤 예측 심박이 밴드 중심에 가장 가까운
  페이스를 "Zone2 목표 페이스"로 제시. 경사/경과시간(피로)이 입력이므로 제안이 상황을 따라 조정됨.
- FR4 (선제 코칭): 판정이 IN이라도 현재 페이스 유지 시 60초 뒤 예측이 상한+2bpm 초과면
  "곧 넘어요" 선제 감속 코칭(방향=SLOW_DOWN, adr-002 방향 잠금 그대로). 하한 미달 예측은 대칭.
- FR5 (표시): 시뮬/목/라이브 공통으로 추천 페이스와 60초 뒤 예측 심박을 대시보드에 표시.

유보(후속, adr-013 용도 3/4): 예측 오차 -> Bayesian prior 관측 채널, 심박 드롭아웃 브리지.

## 모델 설계

### 입력 특징 8종 (추론 시점에 관측 가능한 것만)

| # | 이름 | 정의 | 추론 시 공급 |
|---|------|------|------------|
| 0 | hr_now_frac | 최근 10초 평균 HR의 HRR 비율 (hr-RHR)/HRR | 관측 |
| 1 | hr_sus_frac | 최근 60초 평균 HR의 HRR 비율(드리프트 상태) | 관측 |
| 2 | dHR | (hr[t]-hr[t-30])/30 (bpm/s) | 관측 |
| 3 | pace_plan | 앞으로 유지할 페이스(min/km). 학습=미래 60초 실제 평균 페이스 | 후보/현재 페이스 |
| 4 | slope | 경사(%). 학습=미래 60초 평균 | 현재 경사(한계: 전방 지형 미지 - 문서화) |
| 5 | spm | 케이던스 | 관측 |
| 6 | elapsed_min | 세션 경과(분) - 피로/드리프트 대리 | 관측 |
| 7 | decoupling | 세션 baseline 대비 hr/pace 상승률 | 관측 |

HR을 프로필(RHR/HRR)로 정규화해 러너 간 전이 가능하게 한다. pace_plan을 "미래 구간 실제 평균"
으로 학습하는 것은 what-if 조건화("이 페이스를 유지하면")의 의미론과 일치시키기 위함이다.

### 출력 2종 (회귀)

- y = [hr_frac(t+30), hr_frac(t+60)] - 각 시점 ±5초 평균으로 경미하게 잡음 완화(여전히 관측값)

### 아키텍처/학습

- MLP 8 -> 32 -> 16 -> 2 (ReLU, 회귀 헤드 - softmax 없음). PyTorch 학습(Adam, MSE, early stopping).
- 데이터: simulator.generate_session (물리 시뮬레이터 - 관측 제공자 역할). 러너 단위 train/val/test 분할.
- 배포: 가중치+StandardScaler를 JSON export -> 순수 Kotlin 순전파(adr-011 방식 재사용, TFLite 없음).

### 페이스 역질의 (온디바이스)

- 후보 페이스 4.0~12.0 min/km, 0.25 간격 스윕. 각 후보로 hr_frac(t+60) 예측.
- 예측이 밴드 [lo, hi] 중심에 가장 가까운 후보를 추천. 밴드 안 예측이 없으면 가장 가까운 경계 기준.
- 표시 안정화: 추천은 5초 간격 갱신 + 직전 추천과 0.25 이내면 유지(표시 채터링 억제).

## 평가 (정직한 채점 - adr-013)

Baseline 대비 RMSE(bpm, 테스트 러너):

- B0 지속(persistence): hr(t+H) = hr_now
- B1 선형 외삽: hr_now + dHR x H (생리 범위로 clamp)

| AC | 기준 |
|----|------|
| AC1 | export 모델을 Kotlin 순전파로 로드, sklearn/torch 예측과 일치(허용오차 1e-4) - 단위 테스트 |
| AC2 | RMSE@30s와 @60s 모두 B0, B1보다 낮음 |
| AC3 | 페이스 응답 방향성: pace_plan 증가(느려짐) 시 예측 HR 단조 감소, 위반율 5% 미만(스윕 grid) |
| AC4 | 판정 규칙: "지속 심박이 경계 밖인데 반대 판정" 발생 불가 - 단위 테스트(히스테리시스 포함) |
| AC5 | 시뮬 모드 화면에 추천 페이스/예측 심박 표시 + 선제 코칭 발화 - 실기기 확인 |

지표 기록: `ml/EXPERIMENT_LOG.md`에 RMSE 표(모델 vs B0/B1) 추가. 기존 판정 지표는
"시뮬 라벨 기준(폐기)"으로 명시 유지.

## 앱 통합

- `RunEngine`: 판정 = ZoneJudge(규칙+히스테리시스, FR1). MLP 분류기 호출 제거(가드레일 포함 -
  가드가 필요 없는 구조가 됨). 동역학 모델은 5초 간격 예측 + 페이스 역질의.
- `LiveState` 추가 필드: predictedHr60(bpm), recommendedPaceMinKm.
- 코칭: 기존 판정 변화 트리거 + FR4 선제 트리거. CoachContext에 preemptive 플래그,
  LLM 프롬프트에 "아직 넘지 않았지만 곧 넘을 것" 맥락 전달. DirectionGuard 그대로.
- 기존 `Zone2Classifier`/`assets/zone2_mlp.json`은 기록 보존용으로 유지(판정 경로에서 제거),
  관련 테스트는 legacy 표기.

## 한계 (설계 판단으로 명시)

- 전방 지형 미지: slope 입력은 현재값으로 근사. 경로 고도 프로파일 연동은 후속.
- 시뮬 학습의 한계: 시뮬 동역학(1차 지연+드리프트)이 실제 생리보다 단순. 필드 로그(spec-012)가
  쌓이면 같은 파이프라인으로 실데이터 미세조정 가능 - 라벨이 관측값이므로 추가 라벨링 불필요.
- 페이스 제안은 GPS 페이스 노이즈에 민감할 수 있음 - 표시 안정화로 완화, 필드에서 검증.
