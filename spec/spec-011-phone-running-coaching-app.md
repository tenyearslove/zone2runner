# Spec-011: 폰 러닝 코칭 앱 (Phone 앱)

- **상태**: Draft
- **날짜**: 2026-07-03
- **관련 요구**: spec-001 FR1(프로필/RHR)/FR2(실시간 표시)/FR3(존 판정)/FR4(코칭)/FR5(지도)/FR6(세션 기록), adr-001(Phone=AI), adr-002(LLM 코칭), adr-003/004(개인화), adr-005/spec-006(MLP 판정), adr-007(온디바이스 LLM), adr-010(지도), adr-011(순수 Kotlin 추론)
- **구현 위치**: `app/` (독립 Gradle 모듈, applicationId `com.zone2runner.app`)

## 목표

러너가 폰 하나로 유산소(Zone 2) 러닝의 전체 흐름을 경험한다: 프로필 설정 → 러닝 시작(실시간 지도/심박/존 판정/음성 코칭) → 종료 후 리포트(경로 지도/시계열 차트/유산소 분석) → 기록 관리. 우리가 설계/학습한 AI(다변량 MLP 판정 + Bayesian 개인화 + 온디바이스 LLM 코칭)를 온디바이스로 적용해 개인화된 판정과 코칭을 제공한다.

## 범위

**포함**
- 화면 네비게이션: 홈 → 러닝 → 리포트, 홈 ↔ 기록/프로필 (5개 Activity)
- 실시간 러닝 대시보드: 지도(경로 추적), HR/존 판정, 페이스/거리/시간, 코칭 문구 + 음성(TTS)
- 입력 소스 2종: 시뮬레이션(물리 시뮬레이터 가속 재생) / 실센서(실 GPS + 워치 HR)
- 온디바이스 AI 파이프라인: 이상치 가드 → 특징 추출 → MLP 판정(규칙 폴백) → Bayesian 개인화 → 코칭
- 코칭: 규칙이 방향 결정 + LLM(Gemini Nano) 표현, 실패 시 규칙 폴백 (adr-002)
- 리포트: 요약 지표, 존 체류 분포, HR/페이스 시계열 차트, 존 타임라인, 유산소 분석(심혈관 드리프트), 개인화 결과, 존 색 경로 지도, 코칭 로그
- 세션 영속화(JSON) + 기록 목록/상세/삭제
- 프로필(나이/안정HR/최대HR) 저장, Zone 2 목표 심박 산정

**제외 (후속/한계)**
- 워치 HR 실기기 수신 검증(코드는 sensor-poc 프로토콜로 구현, 실기기 미검증)
- 백그라운드/화면off 지속 수집(adr-009, sensor-poc에 구현. 폰 앱 통합은 후속)
- Gemini Nano 모델 자동 다운로드/포그라운드off 코칭(모델 AVAILABLE일 때만 사용, 미가용 시 규칙 폴백)
- 개인 임계 추출 편향 개선(HANDOFF 한계로 명시) — 앱은 관측 갱신 훅만 제공

## 기능 명세

### 화면
| 화면 | 역할 | 핵심 |
|------|------|------|
| HomeActivity | 진입점 | 프로필/목표심박 요약, 최근 세션, 러닝(시뮬/실센서)/기록/프로필 이동 |
| RunActivity | 라이브 러닝 | 지도 추적 + HR/존/페이스/거리/시간 + 코칭(문구+음성), 시작/정지 저장 |
| ReportActivity | 세션 리포트 | 요약 + 존 분포 + 시계열 차트 + 유산소 분석 + 개인화 + 경로 지도 + 코칭 로그 |
| HistoryActivity | 기록 | 저장 세션 목록(탭 상세, 롱프레스 삭제) |
| ProfileActivity | 프로필 | 나이/안정HR/최대HR(0=Tanaka 자동) 입력, Zone2 목표 미리보기 |

### AI 파이프라인 (RunEngine, 1Hz)
```
Sample → OutlierGuard(40~220 가드) → FeatureExtractor(7특징)
      → Zone2Classifier(MLP 순전파) | 규칙 폴백 → Personalization(Bayesian 경계 갱신)
      → Coach(규칙 방향 + LLM 표현) → 세션 누적(지표/경로/시계열/코칭)
```
- 특징 7종: `[hr_norm_u, hr_norm_l, dHR, pace, spm, decoupling, slope]` (spec-006 동일 규약)
- MLP: 7→32→16→3 ReLU, `assets/zone2_mlp.json`(export_model.py 산출) 순수 Kotlin 순전파(adr-011)
- 개인화: 공식(HRR 70%) 사전 + decoupling 임계 부근 지속 HR 관측으로 켤레 가우시안 갱신(adr-004)
- 콜드스타트/모델 미로드 시 규칙 판정으로 폴백

### 입력 소스 (RunSource 추상화)
- `SimulatedRunSource`: 물리 시뮬레이터 세션을 가속 재생(≈70배). 실기기 없이 전 파이프라인 구동.
- `LiveRunSource`: FusedLocation 실 GPS(속도→페이스, 고도→경사, 페이스→케이던스 추정) + `HrProvider`.
  - `WatchHrProvider`: 워치가 Data Layer(`/hr`)로 보낸 HR 수신(sensor-poc 프로토콜, 워치 HrForwarder와 짝).

### 코칭 (adr-002)
- 방향(의도)은 규칙이 결정: 미달→SPEED_UP, 유지→MAINTAIN, 초과→SLOW_DOWN.
- 표현은 `LlmCoach`(Gemini Nano)가 방향 잠금 프롬프트로 생성 + 출력 가드(문장/길이/따옴표). 실패/미가용 시 `RuleCoach`.
- 코칭 문구는 화면 표시 + TTS 음성 출력(한국어). 판정이 바뀌고 20초 이상 지났을 때만 갱신.

### 리포트 유산소 분석
- HR 추이 라인차트(Zone 2 목표 밴드 음영), 페이스 추이, 존 타임라인(시간순 판정 색띠).
- 심혈관 드리프트(%): 세션 전반부 대비 후반부 HR/페이스 비율 상승률 → 피로/탈수 신호 해석.
- Zone 2 유지 비율 + 평균/최대 심박 기반 세션 평가 문장.

### 영속화
- 세션: `filesDir/sessions/<id>.json` (RunReport 직렬화 — 지표/경로/시계열/코칭).
- 프로필: SharedPreferences(나이/안정HR/최대HR override).

## 수락 기준 (AC)
- [ ] AC-1: 홈에서 러닝(시뮬레이션)을 시작하면 지도에 경로가 그려지고 HR/존/페이스/거리/시간이 실시간 갱신된다.
- [ ] AC-2: 판정이 바뀔 때 코칭 문구가 갱신되고, 방향(미달→올리기/초과→낮추기)이 판정과 일치하며 음성으로 안내된다.
- [ ] AC-3: 종료 시 세션이 저장되고 리포트로 이동하며, 리포트에 시계열 차트/존 타임라인/유산소 분석/경로 지도가 표시된다.
- [ ] AC-4: 기록 화면에 저장된 세션이 나열되고, 탭하면 리포트가 열리고 롱프레스로 삭제된다.
- [ ] AC-5: 프로필(나이/안정HR/최대HR)을 저장하면 홈의 Zone 2 목표 심박과 판정 기준에 반영된다.
- [ ] AC-6: MLP 모델 로드 시 MLP 판정, 미로드 시 규칙 폴백으로 동작한다(둘 다 크래시 없음).
- [ ] AC-7: 실센서 모드 진입 시 위치 권한을 요청하고, 워치 HR 미수신 시에도 앱이 안정적으로 동작한다.
- [ ] AC-8 (검증됨): 순수 Kotlin MLP 순전파가 export된 모델을 로드해 학습 모델과 동일 방향으로 추론한다(단위 테스트 8건 통과, mlp_acc=0.826/QA1=0.996/QA2=1.0 재현).
