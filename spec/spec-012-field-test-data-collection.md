# Spec-012: 필드 테스트 데이터 수집 (러닝 세션 원시 로그)

- **상태**: Draft
- **날짜**: 2026-07-03
- **관련 요구**: spec-002 QA1(판정 정확)/QA2(강건성)/QA3(개인화), spec-003(파이프라인), spec-011(폰 앱), adr-009(백그라운드)
- **구현 위치**: `app/` `data/RunLogger.kt` + `RunActivity` 연동

## 목표

실기기 필드 테스트(실제 야외 러닝)에서 파이프라인의 입력과 출력을 **1Hz 원시 수준으로 기록**해,
테스트 후 오프라인 분석으로 설계 검증과 결함 수정의 근거 데이터를 확보한다.
시뮬레이터로는 볼 수 없는 것(실제 워치 HR 전송 끊김, GPS 페이스 노이즈, 경사 산출 품질,
LLM 코칭 실기기 지연)을 측정하는 것이 목적이다.

## 왜 필요한가 (QA 매핑)

| 수집 항목 | 분석 | 검증 대상 |
|-----------|------|-----------|
| 워치 HR 수신 시각/staleness | 수신 간격 히스토그램, 끊김 구간 | adr-009 백그라운드 전송, QA2 |
| 원시 HR vs 정제 HR | 이상치 가드 동작 빈도/정당성 | QA2 이상치 기각 |
| GPS 페이스/경사 시계열 | 노이즈 수준, 스무딩 적정성 | 특징 품질(QA1 간접) |
| 판정 시계열 | 존 전환 빈도/안정성(채터링 여부) | QA1 판정 안정성 |
| 개인화 uEst 궤적 | 세션 내 수렴/발산 | QA3 개인화 메커니즘 |
| 코칭 이벤트(시각/문구/소스) | LLM 실기기 지연, 방향 적합성 | QA5/adr-002 출력 가드 |

## 기능 명세

### FR1. 세션별 JSONL 로그
- 러닝 시작 시 `getExternalFilesDir("runlogs")/run-{yyyyMMdd-HHmmss}.jsonl` 생성.
  외부 앱 전용 디렉터리인 이유: 권한 없이 `adb pull`로 회수 가능.
- 첫 줄 meta 레코드, 이후 1Hz sample 레코드, 비정기 event 레코드. 종료 시 close.

### FR2. 레코드 스키마 (한 줄 = JSON 객체)
```jsonc
// meta (세션당 1회, 첫 줄)
{"type":"meta","wall":1720000000000,"mode":"live","profile":{"age":35,"rhr":58,"maxHr":183},
 "model":{"loaded":true,"mlp_acc":0.826},"appVersion":"...","uEst0":0.70}
// s = 1Hz 샘플 (입력 원시값 + 파이프라인 출력)
{"type":"s","t":123,"wall":...,"hrRaw":141,"hrClean":141,"watchAgeMs":850,
 "pace":6.2,"spm":167,"slope":1.2,"lat":37.56,"lon":126.97,"judg":1,"uEst":0.702}
// e = 이벤트 (코칭/세션 종료/오류)
{"type":"e","wall":...,"kind":"coach","text":"...","tookMs":2100}
{"type":"e","wall":...,"kind":"end","summary":{"durationSec":1800,"savedId":"..."}}
```
- `judg`: -1 판정없음 / 0 미달 / 1 유지 / 2 초과. `watchAgeMs`: 워치HR 마지막 수신 후 경과(라이브 모드만, 아니면 -1).
- 모든 모드(sim/mock/live)에서 기록 — 시뮬 로그는 실측 로그와의 비교 기준선.

### FR3. 성능/안전
- 파일 쓰기는 전용 단일 스레드(메인/샘플 루프 비차단). 30줄마다 flush(중단 대비).
- 로그 실패는 러닝을 절대 방해하지 않는다(모든 IO runCatching).
- 용량: 1Hz JSON 약 200B/s = 시간당 약 0.7MB. 정리 정책은 당분간 불요(수동 삭제).

### FR4. 회수/분석 절차
- 회수: `adb pull /sdcard/Android/data/com.zone2runner.app/files/runlogs ./fieldlogs`
- 분석: `ml/` 파이썬 환경에서 pandas로 로드(스키마가 곧 계약). 분석 산출은
  EXPERIMENT_LOG 또는 report에 환류.

## 수락 기준 (AC)
- AC1: 시뮬 모드로 세션 1회 완주 시 로그 파일이 생성되고, meta 1줄 + 세션 길이만큼의 s 레코드 + end 이벤트가 존재한다.
- AC2: 라이브 모드에서 워치 HR 미수신 구간의 s 레코드가 `hrRaw:-1` + `watchAgeMs` 증가로 기록된다.
- AC3: 코칭 발생 시 coach 이벤트에 문구와 생성 소요(tookMs)가 남는다.
- AC4: 로거 예외(디스크 등)가 발생해도 러닝 세션은 정상 진행/저장된다.

## 프라이버시
GPS 좌표가 포함되므로 로그는 기기 밖으로 자동 전송하지 않는다(로컬 파일 + 수동 adb 회수만).
분석 후 repo에 커밋할 때는 좌표를 제거하거나 상대화한다.

## 구현 시 확정(유보)
