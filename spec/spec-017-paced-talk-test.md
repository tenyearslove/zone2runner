# Spec-017: 페이스 강제 낭독 Talk Test — 숨당 발화 길이로 VT1 감별

- **상태**: Draft (voice-poc 실험)
- **날짜**: 2026-07-05
- **관련**: `arch/archive/adr-018-ondevice-speech-talk-test.md`(객관 음성 측정 재개), `spec/spec-016`(주관 5단계, 현 배포), `arch/adr-016`(도구 선택)
- **위치**: `voice-poc/phone`

## 배경 — 왜 이 프로토콜인가

Zone 2 상단 = **VT1**(1차 환기역치)이다. 검증된 Talk Test 연구([PMC3772610])는 정해진 문구를 낭독시키고
"편하게 말할 수 있나(예/예…근데/아니오)"의 **"마지막 예" 지점이 VT1과 일치**함을 보였다. 핵심 물리는:
**말이 환기 부하를 얹어 VT1 근처에서 여유가 먼저 바닥난다.** 수동 호흡 청취(adr-018에서 기각)는 VT1엔
둔감하고 VT2/탈진에서야 반응하므로 부적합. VT1을 잡으려면 **말 부하**가 필요하다.

측정 지표는 언어병리학의 **발화 길이(utterance length) = 두 호흡 사이 음절 수**([Rainbow Passage/ASHA]).
호흡 여유가 줄면 더 자주 들이쉬어 발화가 짧아진다 = 환기 여유의 직접 측정. VT1에 다가갈수록 뚝 떨어진다.

초기 실패(spec-016 Tier2 탐색) 교훈: 짧은 문장 ❌(한 숨에 끝남), 자유 속도 ❌(느리게 읽어 회피),
"완독 여부" ❌(틀린 지표). → **길게 + 페이스 강제 + 숨당 음절 수** 로 교정.

## 프로토콜 (FR) — 시간제한 카운팅(처리량)

> 초기안(페이스 강제 낭독 + 호흡 끊김 검출)은 실기기에서 **박자 간격이 호흡으로 오검출**돼(숫자
> 세기의 규칙적 gap) 강도와 무관하게 값이 고정됐다. → **호흡을 검출하지 않고 "처리량"을 재는** 방식으로
> 교정. 고정 시간에 얼마나 말했나를 보면, 숨쉬는 시간이 말하는 시간을 자동으로 깎으므로 벅찰수록 처리량↓.

- **FR1 (프로토콜)**: 고정 시간(WINDOW, 예 20s) 동안 숫자를 최대한 이어서 세게 한다(하나 둘 셋…).
  숨차면 쉬어도 되지만 계속 이어간다. 검증된 Counting Talk Test 변형.
- **FR2 (측정 — 처리량)**: 에너지 VAD로 발화/비발화만 나눈다(호흡 vs 어절 간격 구분 불필요).
  - **말한 비율(speakingRatio)** = 소리낸 시간 / 창 전체. 주 지표.
  - **발화 덩어리 수(voicedSegments)** ≈ 센 개수. 짧은 gap(<120ms)은 병합.
  - (부차) 긴 gap(≥350ms) = 들숨 수/분당 호흡수.
- **FR3 (자가보고 라벨)**: 측정 후 **예 / 예…근데 / 아니오** 3답(검증된 TT 라벨). "예…근데"≈VT1.
- **FR4 (데이터 저장)**: `(원본 WAV + 특징 + 3답 라벨 + 창/시각)` 저장. 오프라인 학습용.
  온디바이스는 v1(에너지 VAD), 저장 WAV로 추후 정교화(MFCC/소형 모델).
- **FR5 (실시간 표시)**: 센 개수/말한 비율 표시 + 잠정 편함도(보정 전).

## 측정 정의

- 프레임 20ms RMS → 적응 임계로 발화/비발화 분리.
- speakingRatio = 발화 프레임 / 전체 프레임. voicedSegments = 발화 런 수(gap<120ms 병합).
- 해석: **말한 비율 ↓ / 센 개수 ↓ = 환기 부담 ↑ = VT1에 근접.** (숨쉬는 시간이 처리량을 깎음)

## 학습 계획 (후속)

- 라벨: 3답(예=below VT1, 예…근데≈VT1, 아니오=above). HR(워치)로 보조 라벨 가능.
- 특징: 발화 길이, 분당 호흡수, 발화/휴지 비율, (오프라인) MFCC/호흡 템플릿 유사도.
- 모델: 소형 분류기(few-shot). 온디바이스 배포는 경량 헤드.
- 검증: held-out 3답 예측 정확도, HR과 상관.

## AC

- [ ] AC-1: 페이스 하이라이트가 일정 간격으로 진행되고, 그동안 오디오가 녹음된다.
- [ ] AC-2: 낭독에서 호흡 끊김이 검출되어 호흡 수/평균 발화 길이가 산출된다(단위 테스트로 검증).
- [ ] AC-3: 편하게 길게 읽으면 발화 길이가 길고, 일부러 자주 끊어 숨쉬면 짧아진다(방향 검증).
- [ ] AC-4: 3답 라벨과 원본 WAV/특징이 저장되고, adb로 회수 가능하다.

## Non-goals

- 실제 러닝 중 상시 측정(소음 문제, adr-018)은 범위 밖. 통제 낭독으로 알고리즘/데이터 우선 확보.
- 정확한 단어 인식(ASR) 불필요 — 호흡 끊김 타이밍만 필요.
