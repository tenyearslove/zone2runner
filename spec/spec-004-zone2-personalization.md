# Spec-004: Zone 2 개인화 모델 상세 설계

- **상태**: Draft
- **날짜**: 2026-07-01
- **관련 ADR**: `arch/adr-003-zone2-classification-approach.md` (DP1), `arch/adr-004-personalization-model-approach.md` (DP3)

## 목표

누적 세션 데이터로 개인의 Zone 2 심박 경계를 온라인 Bayesian 추정한다. 이 문서는 구현 직전 단계로, 상태 표현/사전분포/관측 추출/갱신식/강건성/규칙 연동/온디바이스 실행/검증 데이터 전략을 구체 수식과 의사코드로 정의한다.

## 범위

**포함**: 개인 경계 추정 모델의 수학적 정의, 세션에서 관측 추출 알고리즘, Bayesian 갱신, 콜드스타트/강건성 정책, 규칙 연동, 온디바이스 실행 형태, 검증용 데이터 생성 전략.

**제외**: 실제 Kotlin/Python 코드, 실시간 판정의 히스테리시스 상수(adr-003 규칙 레이어), 코칭/TTS(spec-005).

## 1. 상태 표현

개인의 Zone 2 **상한 경계** `U`를 1차 추정 대상으로 삼는다(이탈-초과 판정에 가장 직접적). 하한 `L`은 상한에서 개인 밴드폭으로 유도한다.

- 상태: `U ~ Normal(μ, σ²)` — 개인 Zone 2 상한의 추정 분포
- `μ`: 현재 최선 추정 (bpm), `σ`: 불확실성 (bpm). 세션이 쌓일수록 σ 감소
- 하한: `L = μ - band`, `band`는 프로필 기반 고정 밴드폭(예: HRR 10%p 상당). 초기엔 공식값

저장 상태(온디바이스): `{ μ, σ, band, sessionCount }` — float 4개.

## 2. 사전분포 (Prior) = 규칙 baseline

콜드스타트에서 공식(HRR)이 prior를 제공한다(규칙 연동의 핵심).

```
maxHR    = 208 - 0.7 * age          # Tanaka 공식 (220-age 대안)
HRR      = maxHR - restingHR
μ0       = restingHR + 0.70 * HRR    # Zone 2 상한 초기 추정
σ0       = 8                         # 공식 오차 반영 인구 분산 (bpm)
band0    = 0.10 * HRR                # 초기 밴드폭
```

restingHR 미확보 시 spec-003/FR1의 폴백(%HRmax)으로 μ0 산정.

## 3. 관측 모델 (세션 → 증거 추출)

각 세션 종료 시 그 세션이 시사하는 개인 Zone 2 상한 증거 `z`와 관측 신뢰도(노이즈 σ_obs)를 추출한다. 물리 기반이라 라벨이 필요 없다.

핵심 원리: **유산소 디커플링(Cardiac Drift)**. 동일 페이스에서 HR이 과도히 상승하기 시작하는 지점이 유산소(Zone 2) 상한 부근이다.

```
관측 추출(session):
  안정 구간들 = 페이스 변동계수 < ε_pace 인 윈도우(예 3분)들
  각 안정 구간에서 Pw:Hr 디커플링 = (후반부 HR/페이스) / (전반부 HR/페이스) - 1
  z = 디커플링이 임계 δ(예 5%) 미만으로 유지된 "최고 평균 HR"
  세션 품질(안정구간 길이·수)로 σ_obs 결정:
      품질 높음 → σ_obs 작게(예 4), 낮음 → 크게(예 12)
  안정 구간이 없거나 이상 → 관측 기각(이번 세션 갱신 안 함)
```

## 4. Bayesian 갱신 (켤레 가우시안)

세션 종료 시 posterior 갱신 (칼만 필터의 스칼라 형태):

```
precision_prior = 1 / σ²
precision_obs   = 1 / σ_obs²
μ' = (μ * precision_prior + z * precision_obs) / (precision_prior + precision_obs)
σ'² = 1 / (precision_prior + precision_obs)
sessionCount += 1
```

효과: 관측이 정확할수록(σ_obs↓) μ가 z 쪽으로 크게 이동, 세션 누적으로 σ 감소(확신 증가) → 공식에서 실측으로 수렴(QA3).

## 5. 콜드스타트 & 강건성

- **콜드스타트(C02)**: 세션이 적으면 σ가 커 자연히 prior(공식)에 가깝다. "5회" 같은 하드 임계 대신 σ(확신도)로 부드럽게 전환. spec-002 QA3의 5회 기준은 "σ가 임계 이하로 좁아지는 시점"으로 재해석.
- **관측 이상치(QA2)**: z가 생리 범위(40~220) 밖이거나 세션 품질 미달이면 기각 또는 σ_obs 상향(다운웨이트).
- **급변 방지**: 단일 세션 갱신량 `|μ'-μ|`에 상한(예 3 bpm) clamp.
- **안전 가드(규칙 우선)**: μ는 항상 `[μ0 - Δ, μ0 + Δ]`(예 Δ=15 bpm) 내로 clamp. 개인화가 규칙 안전범위를 못 벗어남.

## 6. 규칙(adr-003)과의 연동

| 역할 | 담당 |
|------|------|
| prior(μ0, σ0, band0) 제공 | 규칙(공식 HRR) |
| 안전 clamp 범위 제공 | 규칙 |
| 실시간 판정 (HR vs 경계+히스테리시스) | 규칙 레이어가 posterior μ/L 사용 |
| posterior 갱신 (세션 종료 배치) | 개인화 모델 (이 문서) |

즉 **판정은 실시간으로 posterior를 읽고, 개인화는 세션 종료 시 posterior를 쓴다.** 읽기/쓰기 시점이 분리돼 실시간 경로는 가볍다.

## 7. 온디바이스 실행

- 상태 float 4개 + 위 산술식뿐 → TFLite/ONNX/PyTorch Mobile 불필요. Kotlin 순수 구현.
- 저장: 로컬 DB(Room) 또는 DataStore. 세션 종료 시 1회 갱신.
- 실시간 판정은 저장된 μ/L 조회 + 비교뿐이라 배터리/지연 무시 가능.

## 8. 검증 데이터 전략 (전역 학습 없음)

지도학습이 없으므로 "훈련 데이터"가 아니라 **검증 데이터**를 준비한다.

### 8-1. 합성 세션 시뮬레이터 (주 검증 수단)
```
가상 러너 생성: 참 경계 θ*(U*, L*), drift 특성, 노이즈 수준
세션 생성: 목표 페이스 → HR 시계열(θ* 초과 시 drift 증가 모델) + 센서 노이즈
검증:
  - 수렴(QA3): N세션 진행 시 μ → U* 수렴, σ 감소 확인
  - 강건(QA2): 이상값/센서오류 주입 세션에도 μ 안정 확인
  - 콜드스타트: 0→N 세션 경계 이동 곡선
```
이 시뮬레이터+추정기 수렴 그래프가 보고서 "구현 및 검증"의 근거가 된다.

### 8-2. (선택) 공개 데이터 sanity check
공개 러닝/웨어러블 HR-Pace 데이터셋으로 관측 추출 로직(3절)의 현실성 점검. 구체 데이터셋은 구현 시 확정.

### 8-3. 도구
시뮬레이터/추정기 검증 하네스는 Python+NumPy로 오프라인 작성(그래프 산출용). 온디바이스 추정기 로직과 수식 동일성 유지.

## PoC 검증 결과 (2026-07-02, ml/personalization.py)

세션 누적 시 개인 상한 경계 추정의 수렴을 검증. 관측 품질을 두 조건으로 분리.

| 관측 조건 | 세션1→10 오차 | σ(불확실성) | 공식(9~10bpm) 대비 |
|------|:---:|:---:|:---:|
| 메커니즘(관측=참값+노이즈) | 5.1 → **2.2** bpm | 8→1.85 | **개선(수렴 O)** |
| 실제(decoupling 관측) | 11.4 → 15.3 bpm | 8→3.49 | 악화(발산) |

- **Bayesian 갱신 메커니즘은 정상**: 관측이 편향 없이 노이즈만 있으면 세션 누적으로 참값에 수렴하고 σ가 감소(QA3 적응 루프 실증).
- **핵심 병목 = 관측(개인 임계 추출)**: decoupling 기반 관측이 편향(임계보다 높게 잡힘, Conconi 편향과 동일)되어 Bayesian이 확신을 갖고 틀린 값으로 수렴. → 임계 추출 개선이 개인화의 진짜 과제(향후 작업/한계로 명시).
