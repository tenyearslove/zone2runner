## 0. 선정 요약 (과제 규정 충족)

강의 **AI 8대 QA** 중 6개 선정 = **AI 특화 4개 + 일반 SW 2개**.

| # | QA | 분류 | 역할 |
|:--:|------|------|------|
| QA1 | **설명용이성** | AI 8대 (신뢰성) | ★정체성 — 왜 이렇게 판단/코칭했는지 사후에라도 전달 |
| QA2 | **기능적응성** | AI 8대 (기능) | ★정체성 — 변화 감지→적응→안정(진화적 적응) |
| QA3 | **제어가능성** | AI 8대 (신뢰성) | 규칙/사용자가 AI를 통제(가드레일/안전전환) |
| QA4 | **강건성** | AI 8대 (기능) | 노이즈 심한 손목HR/GPS 입력 방어(입력 가드레일) |
| QA5 | **테스트가능성** | 일반 SW | 참값 없는 문제를 폐루프 서로게이트로 검증 |
| QA6 | **수행효율성** | 일반 SW | 심박 변화를 지연 없이 판정/코칭에 반영 |

- 규정: 품질속성 4개 이상 ✅(6개), 그중 **AI 특화 2개 이상 ✅**(4개: QA1~QA4).
- 명칭은 강의 8대 QA 공식 용어를 그대로 사용(`framework/ai-8-qa.md`).

## 1. QA 시나리오 + 측정 지표

각 QA를 자극→반응 시나리오와 측정(목표치/최소허용치)으로 정의한다. 중요도/난이도: 상=H(8~10)/중=M(6~7)/하=L(1~5).

| ID | QA | 내용 | 시나리오 → [측정] | 중요도 | 난이도 |
|:---:|:---|:---|:---|:---:|:---:|
| QA1 | 설명용이성 (AI) | AI가 왜 그렇게 판정/코칭/개인화했는지를 사람이 납득 가능한 형태(인과/정당성/충실성)로 표현한다. | 판정·코칭·개인화가 일어난 세션에서 "왜 이렇게 판단했나"를 요청한다. 규칙이 확정한 사실(경계 비교, 드리프트→코칭 인과, 세션 수·관측·이동량)을 근거로 설명을 생성한다.<br>[측정] 설명이 실제 사실에 근거(무결성: 규칙이 사실 확정, LLM은 표현만) + 지어낸 수치 0 + 동일 입력 설명 일치율 100% | 9 | 6 |
| QA2 | 기능적응성 (AI) | 개인/컨디션 변화를 감지→적응→회복→안정한다(진화적 적응, 관측으로 온라인 학습). | 세션 누적 + 변화 신호(후반 드리프트 급증/기온/말하기 테스트 응답)를 적응 트리거로 승격 → 개인 Zone 2 경계를 온라인 Bayesian 갱신하고 최대·안정심박 프로필을 갱신한다.<br>[측정] 참임계 대비 수렴오차↓ vs 세션수(Quality Recovery), Time to Stabilization(안착 세션수), Stability Index(세션 간 경계 진동폭) | 9 | 8 |
| QA3 | 제어가능성 (AI) | 규칙/사용자가 AI 출력에 개입해 안전·신뢰 상태로 전환한다(교정/보완/안전전환, 입출력 가드레일). | LLM이 판정과 어긋난/무방향 코칭을 내면 규칙(DirectionGuard)이 기각·폴백한다. 위험 고심박엔 안전 가드가 LLM을 거치지 않고 규칙 권고. Nano 미가용 시 RuleCoach 자동 폴백.<br>[측정] 방향위반 기각율(목표 100%), 폴백 시 코칭 연속성(무중단), 세션 경계이동 ≤10bpm 보장률 | 8 | 6 |
| QA4 | 강건성 (AI) | 노이즈/이상 입력에도 판정이 무너지지 않는다(입력 가드레일). | 생리범위(40~220) 밖 이상치/GPS 고도 튐/경계 근처 떨림을 연속 입력한다. OutlierGuard 기각 + 히스테리시스 + 창 회귀 평탄화 + 분석 엔진 노이즈 구간 게이팅으로 방어.<br>[측정] 이상치 기각율 100%, Flicker Rate(인접 프레임 판정 번복), Robustness Score(정상 대비 판정 유지율) 폐루프 | 8 | 5 |
| QA5 | 테스트가능성 (일반) | 참값 없는 문제(C03)를 폐루프 서로게이트로 검증할 수 있다. | 워치 없이 RunSource를 교체(가상러너/수동)해 판정/개인화/분석/코칭 전 파이프라인을 실행하고, 참임계를 아는 가상러너로 개인화 수렴을 정량 검증한다.<br>[측정] Watch 없이 독립 실행 비율 100%, 단위 테스트 통과, 수렴 곡선(시뮬=구조 검증/디버거이지 실인간 정확도 아님) | 7 | 6 |
| QA6 | 수행효율성 (일반) | 심박 변화를 지연 없이 판정/코칭에 반영한다(시간 반응성). | 1Hz 샘플을 한 주기 내에 판정/화면에 반영하고, 코칭 LLM 생성은 비동기로 화면/판정을 멈추지 않는다.<br>[측정] 반영 지연 한 주기 이내, 이탈 감지→TTS 음성 5초 이내(Watch-Phone 전송 포함), 코칭 생성 중 프레임 멈춤 0 | 8 | 6 |

## 2. Utility Tree

```
유용성(Utility)
├─ [정체성] 설명용이성(AI)
│   └─ QA1 왜 이렇게 판단/코칭했는지 사실 근거로 설명       (H, M)
├─ [정체성] 기능적응성(AI)
│   └─ QA2 변화 감지→경계/프로필 적응→수렴·안정            (H, H)
├─ 제어가능성(AI)
│   └─ QA3 가드레일/안전전환으로 규칙·사용자가 AI 통제      (H, M)
├─ 강건성(AI)
│   └─ QA4 노이즈 입력에도 판정 유지(Flicker/Robustness)   (H, L)
├─ 테스트가능성(일반)
│   └─ QA5 참값 없이 폐루프 서로게이트로 검증               (M, M)
└─ 수행효율성(일반)
    └─ QA6 변화→판정→코칭 지연 없이 실시간 반영            (H, M)
```

## 3. ASR 선정 및 설계결정 매핑

ASR(Architecturally Significant Requirement) = 중요도 7 이상. QA1~QA6 모두 7 이상이라 전부 ASR. 우선순위(중요도·난이도 종합): QA2 > QA1 = QA6 > QA3 > QA4 > QA5.

| ASR | 핵심 요구 | 해소 설계결정 |
|:---:|------|------|
| QA1 설명용이성 | 판단 근거를 사실로 설명 | 판정=규칙 경계비교(adr-013) + 분석 엔진 파생지표 인과분해(adr-024) + 설명 서비스(spec-023) + 무결성(규칙이 사실 확정, LLM 표현만) |
| QA2 기능적응성 | 개인 경계/프로필 적응 | 온라인 Bayesian 경계 갱신(adr-004) + 말하기 테스트 실라벨(spec-016) + 최대·안정심박 갱신(adr-012) + 기존 신호(드리프트/기온)를 적응 트리거로 승격 |
| QA3 제어가능성 | 출력 통제/안전전환 | DirectionGuard 출력 가드레일(adr-002) + 안전 가드 규칙 권고(spec-008) + Nano 미가용 폴백 + 개인화 clamp(±10bpm) |
| QA4 강건성 | 이상 입력 방어 | OutlierGuard 입력 가드레일(spec-003) + 히스테리시스(adr-013/023) + 창 회귀 평탄화 + 분석 엔진 노이즈 게이팅(adr-024) |
| QA5 테스트가능성 | 참값 없는 검증 | RunSource 추상화(spec-003) + VirtualRunner 폐루프(spec-019) + 수동 가상러너(spec-022) + 단위 테스트 |
| QA6 수행효율성 | 실시간 응답성 | 끊김 없는 1Hz 파이프라인 + 비동기 코칭(무중단) + 규칙 판정 즉시(무 추론) |

### 평가 관점 (중요)
- **참값 부재(C03)**: 개인 Zone 2/유산소 역치의 랩 참값이 없다 → **절대 정확도를 QA로 세우지 않는다.** 대신 판정의 결정론적 정확성(모순 불가, 방향 정확)은 제어가능성에, 악조건 유지는 강건성에, 서로게이트 검증은 테스트가능성에 녹인다.
- **분석 엔진의 검증(FR3)**: 파생지표는 관측에 대한 자기참조 fit이라 참값 없이 검증 가능(자기참조/개인 추세). 말하기 테스트(FR4)는 사용자 실라벨이라 실주행 검증 가능(spec-012).

## 4. 선정/제외 근거 (정직성 — 구 report-007 흡수)

**정체성 논지**: 대량 사전학습 데이터가 없어(C02) 블랙박스 NN을 버렸고(예측 NN → 관측 분석 엔진, adr-024; 판정 NN → 규칙, adr-013; 개인화 → Bayesian, adr-004), 그 자리를 **분해 가능한 모델/규칙**으로 채웠다. 그래서 **①설명용이성 + ②기능적응성**이 정체성 QA다. ③제어가능성이 사실을 잠가 설명이 환각이 안 되고 적응이 폭주 안 하게 하며, ④강건성이 노이즈를 방어하고, ⑤테스트가능성이 참값 없이 검증하며, ⑥수행효율성이 지연 없이 전달한다.

**의도적으로 뺀 QA**:
- **기능정확성** — 개인 참값이 소비자 환경에 없어(C03/C04) 절대 정확도를 헤드라인으로 주장하면 "어떻게 검증했나"에서 무너진다. 강의 Trade-off "설명용이성 vs 기능정확성"에서 설명 쪽을 택함. 판정의 결정론적/방향 정확성은 제어가능성에 흡수.
- **신뢰성** — "안 죽고 잘 돈다"는 비차별적이고, 그 증거(폴백/결함허용)가 제어가능성(안전전환)/강건성과 중복 → 대신 실시간 응답성(수행효율성)으로 교체.
- **프라이버시/공정성** — 강의 앱유형표상 개인화/추천/생성형에서 중요하나, 우리는 단일 사용자 생리모델 적응이라 집단 차별/데이터 노출 이슈가 구조적으로 약함 → 헤드라인 부적합. 온디바이스 비업로드는 DP0 부수효과로만 기록.

> 외부 근거: 강의 앱유형표(우리 유형=예측/진단 분석 + 의사결정/에이전트의 중요 QA 합집합 = 강건성 ∪ 기능적응성 ∪ 제어가능성 ∪ 설명용이성 = 우리 AI 4개와 일치). 상세 = `framework/ai-8-qa.md`(10-우선순위/Trade-off).
