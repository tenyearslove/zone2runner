# Spec-002: 품질 속성 (Quality Attributes)

- **상태**: Approved (2026-07-08 갱신 — 강의 AI 8대 QA 상세 반영, 6대 QA 확정)
- **관련**: report-007(선정 근거/척추), references/강의요약-AI-8대QA-상세.md(강의 정의/지표), spec-001(요구/제약)

우리 앱 유형 = **예측/진단 분석 AI + 의사결정/에이전트 AI**. 강의 앱유형표상 이 두 유형의 중요 QA 합집합
(강건성/기능적응성/제어가능성/설명용이성)이 우리 AI 4개와 일치한다. 여기에 일반 SW QA 2개(테스트가능성/수행효율성)를 더한다.

---

## 1. 품질 속성 선정 (QAW / Utility Tree / ASR)

시나리오는 "자극 → 반응. [측정] 대표 지표"로 쓴다(상세 지표는 §4 Appendix). 중요도/난이도는 상 H(8~10)/중 M(6~7)/하 L(1~5).

| ID | QA (분류) | 내용 | 시나리오 (자극 → 반응. [측정]) | 중요도 | 난이도 |
|:--:|:--|:--|:--|:--:|:--:|
| QA1 | 설명용이성 (AI) | 판정/코칭/예측/개인화에 이해 가능한 근거 제공 | 사용자가 결과에 "왜"인지 확인 → 규칙/물리모델 근거로 쉽게 설명. [측정] 근거 제공률 95% 이상 | 8.5 | 7 |
| QA2 | 기능적응성 (AI) | 실주행 관측으로 개인 경계를 갱신, 쓸수록 수렴 | 관측(토크/드리프트/기온) 변화 → 경계를 옳은 방향으로 갱신/수렴. [측정] 적응 방향 정확률 90% 이상 | 8.3 | 8 |
| QA3 | 강건성 (AI) | 노이즈 심한 손목HR/GPS에도 판정 유지 | 이상치/급변 입력 유입 → 입력 가드가 거르고 판정 유지. [측정] 판정 유지율 90% 이상 | 8.0 | 7 |
| QA4 | 제어가능성 (AI) | 규칙/사용자가 AI에 개입해 신뢰 상태 유지 | LLM이 판정과 어긋나거나 AI 미가용 → 규칙이 기각/폴백. [측정] 방향위반 기각률 98% 이상 | 7.8 | 6 |
| QA5 | 테스트가능성 (일반) | 실주행 없이 로직을 체계적으로 검증 | 실기기/실데이터 없이 검증 필요 → 가상러너 폐루프로 입력 주입/자동검증. [측정] 핵심 로직 커버리지 80% 이상 | 7.5 | 6 |
| QA6 | 수행효율성 (일반, ISO 25010) | 심박 변화를 지연 없이 반영 + 예측 보상 | 매초 심박 유입/코칭 생성 → 한 주기 내 반영, 화면 안 멈춤. [측정] 반영 지연 1초 이내 | 7.2 | 6 |

- **규정 충족**: 총 6개(최소 4개 이상), **AI 특화 4개**(설명용이성/기능적응성/제어가능성/강건성, 최소 2개 이상), **일반 SW 2개**(테스트가능성/수행효율성).
- QA6 수행효율성은 ISO 25010 일반 SW 특성이 뿌리다(AI 8대에도 겹쳐 실림). 여기선 일반 SW(성능/시간 반응성) 관점으로 잡는다.

## 2. Utility Tree

```
유용성(Utility)
├─ 설명용이성(AI) ★정체성
│   └─ QA1 판정/코칭/예측/개인화의 근거 제공          (H, M)
├─ 기능적응성(AI) ★정체성
│   └─ QA2 관측으로 개인 경계 갱신/수렴               (H, H)
├─ 강건성(AI)
│   └─ QA3 노이즈/이상치에도 판정 유지               (H, M)
├─ 제어가능성(AI)
│   └─ QA4 규칙/사용자 개입으로 신뢰 상태 유지        (H, M)
├─ 테스트가능성(일반)
│   └─ QA5 실주행 없이 폐루프로 자동 검증             (M, M)
└─ 수행효율성(일반)
    └─ QA6 지연 없는 반영 + 예측 보상                 (M, M)
```

## 3. ASR 선정 및 설계결정(DP) 매핑

ASR(Architecturally Significant Requirement)은 **중요도 7 이상**을 기준으로 선정 → QA1~QA6 전부 ASR.
각 ASR을 해소하는 핵심 설계 메커니즘(정식 DP 번호는 설계 단계에서 확정):

| ASR | 핵심 요구 | 해소 설계 메커니즘 |
|:--:|:--|:--|
| QA1 | 결과의 근거 제공(투명성) | 예측=생리 ODE 항목분해(adr-020) + 규칙 판정(adr-013) + 설명 서비스(spec-023) |
| QA2 | 개인 경계 진화적 적응 | 온라인 Bayesian 경계 + ODE 파라미터 추정(adr-004/020) + 토크테스트(spec-016) |
| QA3 | 악조건 판정 유지(입력 가드레일) | OutlierGuard/창회귀/히스테리시스(spec-003) |
| QA4 | 규칙/사용자 개입 통제 | DirectionGuard(출력 가드레일) + 규칙 폴백 + 물리/세션 clamp(adr-002) |
| QA5 | 소스 교체 검증성 | RunSource 추상화 + VirtualRunner 폐루프(spec-003/019/022) |
| QA6 | 실시간 응답성 | 비동기 코칭 + 1Hz 파이프라인 + 선제 예측(adr-002/020) |

## 4. 측정 지표 (Appendix — 목표치 / 최소허용치)

목표치/최소허용치는 씬스틸러 샘플 형식을 따른다. 자연스러운 완전성/안전 항목만 100%, 나머지는 격차 있는 현실적 수치.
*(시뮬)* 표시 지표는 폐루프 시뮬레이션(C04) 평가 = 소프트웨어/알고리즘 검증 범위.

| QA | 지표명 | 측정 방법 | 목표치 | 최소허용치 |
|:--|:--|:--|:--:|:--:|
| 설명용이성 | 근거 제공률 | 근거 표시된 AI 출력 / 전체 출력 | 95% | 90% |
| 설명용이성 | 설명 재현율 | 동일 입력 반복 시 동일 설명 비율(결정론) | 100% | 99% |
| 기능적응성 | 적응 방향 정확률 | 관측에 경계가 옳은 방향 이동한 비율 *(시뮬)* | 90% | 80% |
| 기능적응성 | 수렴 오차 | 반복 세션 후 개인 경계와 목표의 차 *(시뮬)* | ≤5 bpm | ≤8 bpm |
| 강건성 | 이상치 차단율 | 범위 밖/비생리 입력이 판정에 반영 안 된 비율 | 99% | 95% |
| 강건성 | 판정 유지율 | 노이즈 주입 시 깨끗한 입력과 판정 일치 비율 *(시뮬)* | 90% | 80% |
| 제어가능성 | 방향위반 기각률 | 판정과 어긋난 LLM 문장을 규칙이 기각한 비율 | 98% | 95% |
| 제어가능성 | 한계 준수율 | 개인화 변화가 설계 한계 내에 머문 비율 | 100% | 99% |
| 제어가능성 | 폴백 성공률 | AI 미가용 시 규칙 코칭으로 이어져 끊김 없는 비율 | 100% | 99% |
| 테스트가능성 | 핵심 로직 커버리지 | 판정/개인화/예측/가드 코드의 테스트 커버율 | 80% | 70% |
| 테스트가능성 | 입력 재현 커버율 | 시뮬 주입 가능 입력 / 전체 입력 종류 | 100% | 90% |
| 수행효율성 | 반영 지연 | 심박 샘플 도착 → 판정/화면 반영 시간 | ≤1초 | ≤2초 |
| 수행효율성 | 무중단률 | 코칭(LLM) 생성 중 화면/판정 유지 비율 | 100% | 99% |

## 5. 평가 방법 (검증 전략)

- **정량 평가는 폐루프 시뮬레이션(C04)**: VirtualRunner가 참 임계를 아는 상태에서 개인화 수렴/판정 유지/강건성을 정량 측정.
  이는 **소프트웨어/알고리즘 검증**이지 실인간 정확도의 증거가 아니다(가상러너의 참값은 가상러너에 대한 참값).
- 그래서 절대 "판정 정확도"(기능정확성)는 목표에서 제외하고(C03 참값부재), 방향 정확성/유지율/재현율로 평가한다.
- 검증 결과 표(달성 여부)는 구현/검증 문서에서 채운다.
