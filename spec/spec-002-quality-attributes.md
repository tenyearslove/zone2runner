## Utility Tree

품질속성을 상위 개념에서 구체 시나리오(ASR 후보)로 세분하고, 각 잎에 (중요도, 난이도)를 표기한다. 중요도/난이도는 상=H(8~10), 중=M(6~7), 하=L(1~5)로 환산.

```
유용성(Utility)
├─ 기능 정확성(AI)
│   └─ QA1 Zone 상태에 맞는 코칭 방향 생성            (H, M)
├─ 강건성(AI)
│   └─ QA2 센서 이상값에도 정상 범위 출력 유지        (H, L)
├─ 기능 적응성(AI)
│   └─ QA3 누적 데이터로 개인 Zone 2 경계 보정         (H, H)
├─ 수행 효율성(AI)
│   └─ QA4 이탈 감지→음성 코칭 5초 이내               (H, M)
└─ 테스트 가능성
    └─ QA5 Watch 없이 HR 소스 교체로 전체 검증         (M, M)
```

## ASR 선정

ASR(Architecturally Significant Requirement)은 아키텍처를 좌우하는 핵심 요구로, **중요도 중(7) 이상**을 기준으로 선정한다. QA1~QA5 모두 중요도 7 이상이므로 전부 ASR이며, 우선순위(중요도·난이도 종합)는 QA3 > QA1 = QA4 > QA2 > QA5 순이다.

## ASR → 설계결정(DP) 매핑

각 ASR이 어떤 설계결정으로 해소되는지 추적한다. 이 매핑이 DP1/DP2 설계의 근거다.

| ASR | 핵심 요구 | 해소 설계결정 |
|:---:|------|------|
| QA1 | 코칭 방향 정확성 (현재 수치 대비, 측정 지표) | **DP4** 3분류 판정기가 상태 제공 (adr-005) → **DP2** 방향 결정 (adr-002) |
| QA2 | 이상값 강건성 (40~220 밖 이상치 기각) | **DP1** 규칙 가드 (adr-003) + HR 파이프라인 이상치 필터 (spec-003) |
| QA3 | 개인 Zone 2 경계 적응 | **DP1/DP3** 개인화 레이어 = Bayesian (adr-003/004, spec-004) |
| QA4 | 5초 이내 응답 | **DP2** 프롬프트 최소화 (adr-002) + 경량 MLP 추론 (adr-005) |
| QA5 | 소스 교체 검증성 | HrSource 추상화 (spec-003) |

### 평가 관점 (중요)
- **Zone 2 판정은 실측 정답(ground truth)이 없다** (개인별 진짜 경계는 랩 검사 없이는 모름). 따라서 판정 자체의 정확도로 QA를 평가할 수 없다.
- 그래서 **QA1은 현재 심박 수치 대비 코칭 방향의 정확성(일치율 95%)으로 측정**한다. 코칭은 방향(가속/감속)이 정확해야 하므로 판정기는 3분류(미달/유지/초과)여야 하며 이진(유지/이탈)으로는 방향을 낼 수 없다.
- 단일 HR 임계값(선형·단변량)은 오르막/Drift 등 다신호 상황에서 방향 오판을 낳으므로 비선형 다변량 판정기(DP4 MLP)를 도입한다.
- **센서 측정 노이즈는 프로젝트 범위 밖**(센서 하드웨어 소관)이다. QA2 강건성은 생리범위(40~220 bpm)를 벗어나는 **이상치 기각(필터링)**으로 달성한다.

## 비고
- AI QA (QA1~QA4): 기능 정확성 / 강건성 / 기능 적응성 / 수행 효율성
- 일반 QA (QA5): 테스트 가능성
- QA3의 초기 누적 기준(5회)은 FR5 설계 시 조정 가능
- 중요도 / 난이도: 1~10점 기준
