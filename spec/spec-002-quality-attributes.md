> 이 문서는 Zone2Runner가 선택한 AI 품질과 합격 기준의 정본이다.

## 1. 선정 결과

Zone2Runner는 네 가지 AI 품질에 집중한다.

| ID | AI 품질 | 쉬운 뜻 | 역할 |
|---|---|---|---|
| QA1 | 설명용이성 | 코칭이 실제로 가진 사실에서 벗어나지 않는다. | 핵심 ASR |
| QA2 | 기능적응성 | 사용자 응답을 받아 개인 경계를 갱신하고 안정시킨다. | 핵심 ASR |
| QA3 | 제어가능성 | 잘못된 LLM 출력을 규칙이 막고 기본 문구로 바꾼다. | 핵심 ASR |
| QA4 | 강건성 | 이상 심박과 경계 부근의 흔들림에도 판정을 안정적으로 유지한다. | 지원 QA |

과제 규정은 품질속성 4개 이상, 그중 AI 품질 2개 이상이다. 네 항목 모두 강의의 AI 8대 품질에 속하므로 규정을 충족한다.

### 왜 이 네 가지인가

이 프로젝트에는 세 가지 현실적인 제약이 있다.

1. 개인의 정확한 유산소 역치를 실험실에서 측정할 수 없다.
2. 많은 사람의 학습 데이터를 모을 수 없다.
3. 자체 서버와 유료 추론 API를 운영할 수 없다.

따라서 평균 공식이 항상 정확하다고 주장하는 대신, 사용자 응답으로 개인 값을 조정하고(QA2), 판단 근거를 남기며(QA1), 생성 문장의 권한을 제한하고(QA3), 센서 입력의 흔들림을 방어한다(QA4).

## 2. QAS

QAS는 누가 상황을 만들고, 시스템의 어느 부분이, 어떤 조건에서, 어떻게 대응하며, 무엇으로 성공을 판단하는지 정의한다.

### QA1. 설명용이성 — 사실과 다른 설명을 내보내지 않는다

| 요소 | 내용 |
|---|---|
| 출처 | 사용자 또는 코칭 기능 |
| 자극 | 판정 이유를 요청하거나 LLM 코칭 문장을 생성한다. |
| 대상 | 규칙 판정, 설명 데이터, LLM 출력 가드 |
| 상황 | 정상 사용 중이며 LLM이 근거와 다른 숫자를 만들 수도 있다. |
| 대응 | 규칙이 판단에 사용한 사실을 먼저 확정한다. LLM은 표현만 담당한다. 허용된 사실에 없는 숫자가 있으면 문장을 버리고 기본 문구로 바꾼다. 코칭과 근거 기록을 함께 저장한다. |
| 합격 기준 | 자동 검증 문장 집합에서 미등록 숫자 문장 5/5 차단, 사실 문장 3/3 통과, 관련 기록 저장·복원 시험 통과 |

이 QAS가 확인하는 것은 설명의 전체 품질이 아니라 사실 충실성이다. 사용자 이해도는 사람을 대상으로 평가해야 하므로 이번 과제의 합격 기준에 넣지 않는다.

### QA2. 기능적응성 — 사용자 응답으로 개인 경계를 갱신한다

| 요소 | 내용 |
|---|---|
| 출처 | 사용자의 말하기 테스트 응답 |
| 자극 | 사용자가 현재 강도를 편함, 보통, 벅참 중 하나로 답한다. |
| 대상 | 개인화 모델의 Zone 2 상한 |
| 상황 | 초기 공식값에서 시작하고 이전 세션의 학습 결과를 이어 받는다. |
| 대응 | 응답을 관측값으로 사용해 Bayesian 방식으로 개인 경계를 갱신한다. 한 세션의 이동 폭은 10bpm을 넘지 않게 제한한다. |
| 합격 기준 | 참임계를 정해 둔 가상 러너 15개 사례에서 최종 오차 3bpm 이하, 5세션 안에 오차 3bpm 이하 도달, 마지막 4세션의 경계 폭 4bpm 이하, 세션당 이동 10bpm 이하 |

기온과 드리프트는 분석 정보지만 현재 개인화 값을 직접 갱신하지 않는다. 따라서 이 QAS의 자극에는 넣지 않는다. 가상 러너 시험은 수렴 구조를 확인할 뿐, 사람의 실제 유산소 역치를 맞혔다는 근거가 아니다.

### QA3. 제어가능성 — 어긋난 LLM 출력을 규칙이 막는다

| 요소 | 내용 |
|---|---|
| 출처 | 온디바이스 LLM 또는 모델 실행 환경 |
| 자극 | 판정과 반대인 문장, 행동 지시가 없는 문장, 또는 LLM 실패가 발생한다. |
| 대상 | 코칭 출력 가드와 기본 문구 경로 |
| 상황 | 실시간 코칭 중 |
| 대응 | 규칙이 문장을 검사해 기각한다. LLM을 사용할 수 없어도 정해 둔 기본 문구로 코칭을 이어 간다. |
| 합격 기준 | 선언한 검증 문장 집합에서 위반 문장 10/10 차단, 정상 문장 5/5 통과, LLM 실패·로딩·모델 없음에 대한 기본 문구 시험 통과 |

10/10은 선언한 시험 문장 집합의 결과다. 모든 가능한 한국어 문장을 완벽하게 거른다는 뜻은 아니다. 위험 심박에서는 정해 둔 규칙이 LLM보다 먼저 동작하지만, 이를 의료 안전 보장으로 표현하지 않는다.

### QA4. 강건성 — 노이즈는 줄이고 실제 변화는 놓치지 않는다

| 요소 | 내용 |
|---|---|
| 출처 | 워치 심박 센서에 해당하는 시험 입력 |
| 자극 | 40~220bpm 밖의 값 또는 경계 부근에서 반복해서 오르내리는 값이 들어온다. |
| 대상 | 심박 입력 가드와 Zone 판정기 |
| 상황 | 결정론적 시뮬레이션 입력을 1초 간격으로 넣는다. |
| 대응 | 범위를 벗어난 값은 버린다. 경계 부근의 짧은 흔들림은 히스테리시스로 줄이되, 실제로 크게 이동한 값은 빠르게 반영한다. |
| 합격 기준 | 이상치 50/50 차단, 정상 범위 500개 오차단 0개, 300초·시드 5종에서 판정 번복 60% 이상 감소, 실제 +10bpm 이동은 2틱 안에 전환 |

범위 시험은 구현한 가드가 유지되는지 확인하는 회귀시험이다. 실제 워치 센서의 정확도를 입증하는 시험은 아니다.

## 3. 우선순위와 ASR

모든 품질이 중요하더라도 설계를 크게 바꾼 요구와 이를 지원하는 요구는 구분한다.

| 순서 | 품질 | 우선순위 근거 | 연결 설계 |
|---|---|---|---|
| 1 | QA2 기능적응성 | 평균 공식값을 개인 값으로 바꾸는 핵심 기능이다. | 온라인 Bayesian 개인화, 말하기 테스트 |
| 2 | QA1 설명용이성 | 참값이 없는 상황에서 판단 근거를 확인할 수 있어야 한다. | 규칙이 사실 확정, 근거 기록, LLM은 표현만 담당 |
| 3 | QA3 제어가능성 | 생성 문장이 판정 권한을 가져서는 안 된다. | 출력 가드, 기본 문구, 규칙 우선 |
| 4 | QA4 강건성 | 입력이 흔들리면 위 세 설계의 결과도 흔들린다. | 입력 가드, 히스테리시스 |

QA1~QA3을 핵심 ASR로 선정한다. QA4는 핵심 ASR을 지지하는 지원 QA다.

## 4. 설계와 검증의 연결

| QA | 설계 결정 | 구현 근거 | 자동 검증 |
|---|---|---|---|
| QA1 설명용이성 | 투명 판정과 근거 기록 | 규칙 판정, NumberGuard, LlmCallLog | 미등록 숫자 차단, 기록 저장·복원 |
| QA2 기능적응성 | 제한된 온라인 개인화 | Personalization, talk-test 갱신, 10bpm 제한 | 15개 수렴 사례, 안정성과 이동 폭 |
| QA3 제어가능성 | LLM 권한 제한과 기본 문구 | DirectionGuard, 규칙 코치, 폴백 경로 | 위반·정상 문장 집합, 실패 경로 |
| QA4 강건성 | 입력 방어와 판정 히스테리시스 | OutlierGuard, DisplayZoneJudge | 이상치·정상값, 5개 노이즈 시드, 실제 이동 |

수치와 실행 방법의 정본은 eport/report-015-qa-verification.md와 QaMeasurementTest.kt다.

## 5. 검증 범위

이번 과제의 목표는 상용 제품 인증이 아니라 설계 역량을 보여 주는 것이다. 따라서 결과를 두 범위로 나눈다.

### 이번 제출에서 판정하는 것

- QA1~QA4의 규칙과 구조가 설계대로 동작하는지
- 같은 입력과 시드로 결과를 다시 만들 수 있는지
- QAS의 합격 기준을 자동시험으로 만족하는지

### 향후 확인으로 남기는 것

- 실제 사용자가 설명을 쉽게 이해하는지
- 개인화 값이 실제 사람의 유산소 역치와 얼마나 가까운지
- 실제 손목 움직임에서 센서 노이즈를 얼마나 줄이는지
- 워치 입력부터 음성 출력까지 실제 기기 지연

실제 달리기 없이 확인할 수 없는 항목은 현재 QA의 실패가 아니다. 이번 과제의 범위 밖이며, 보고서에서도 달성 결과와 섞지 않는다.

## 6. 지원 설계와 보조 제약

### 테스트가능성

RunSource 교체, 가상 러너, 고정 시드, JVM 단위시험은 네 QA를 자동 검증하게 해 주는 공통 설계 수단이다. 테스트 개수 자체를 AI 품질 성과로 사용하지 않는다.

### 수행효율성

1Hz 입력을 밀리지 않게 처리하고 LLM 코칭을 비동기로 실행하는 것은 보조 제약이다. 현재 JVM 시험에서는 로직 비용이 틱당 0.1ms 미만이었지만, 워치·화면·LLM을 포함한 실기기 성능으로 일반화하지 않는다.

## 7. 제외한 AI 품질

| AI 품질 | 이번 핵심 QA에서 뺀 이유 |
|---|---|
| 기능정확성 | 실제 개인 역치의 참값을 측정할 수 없어 사람에 대한 절대 정확도를 판정할 수 없다. |
| 프라이버시 | 심박·개인화·세션 분석은 자체 서버나 외부 AI API에 보내지 않지만, 날씨와 지도 기능은 외부 요청을 사용한다. 별도 핵심 설계문제보다 경계와 사실 표현의 문제로 다룬다. |
| 공정성 | 한 사용자 안에서 개인화하는 과제라 집단 간 성능 차이를 측정할 데이터와 대상이 없다. |
| 수행효율성 | AI 8대 품질이지만 현재 자동시험은 기기 전체가 아니라 JVM 로직만 측정한다. 보조 제약으로 관리한다. |
