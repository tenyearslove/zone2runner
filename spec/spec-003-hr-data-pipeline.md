# Spec-003: HR 데이터 파이프라인 & QA4 이상값 필터 (Watch→Phone, 소스 교체 가능)

- **상태**: In Progress (고정 범위 가드 구현됨, 세션 적응형 가드 설계 중)
- **날짜**: 2026-07-01 (업데이트: 2026-08-06)
- **관련 ADR**: `arch/adr-001-watch-phone-architecture.md`, `arch/archive/adr-003-zone2-classification-approach.md`(탈락 — 판정은 adr-013)
- **관련 품질**: QA4 강건성 (센서 이상값 차단)

## 목표

Galaxy Watch 8이 수집한 실시간 심박수를 Galaxy S26 Ultra의 Zone 2 판정 파이프라인까지 안정적으로 전달한다. 동시에 심박 소스를 추상화해 Watch 없이 시뮬 소스(가상러너/수동 러너 시뮬, spec-019/022)로 전체 파이프라인을 독립 검증할 수 있게 한다(QA5 테스트가능성).

## 범위

**포함**:
- 심박 소스 추상화 인터페이스 (as-built 명칭: `RunSource` + `HrProvider` — sensor/RunSource.kt)
- Watch→Phone 전송 (Wearable Data Layer)
- 샘플링/버퍼링 (1~2초 주기)
- 이상값 필터 (생리적 범위 40~220 bpm, QA3 강건성)

**제외**:
- Zone 2 판정 로직 (adr-013 / spec-004)
- Samsung Health Sensor SDK 실제 연동 코드 상세 (구현 시)
- LLM 코칭 (spec-005)

## 기능 명세

### 주요 흐름
1. Watch: Sensor SDK가 심박을 1~2초 주기로 수집
2. Watch: 샘플링 후 Wearable Data Layer로 Phone에 전송
3. Phone: 수신 → **Tier 1 고정 가드**(40~220 범위 체크) → **Tier 2 세션 적응형 가드**(시간창 일관성 검사) → 최근값 버퍼
4. Phone: `RunSource`/`HrProvider` 인터페이스가 판정 파이프라인에 심박 스트림 공급
5. 판정/개인화/코칭은 `RunSource` 추상만 의존 (소스 종류 불문)

### 시뮬 소스 교체
- 시뮬 소스(가상러너 재생/수동 러너 조종, spec-019/022)가 동일 소스 인터페이스로 합성 심박을 공급
  (구 `MockHrSource`/가짜 라이브는 커밋 7e6d172에서 제거 — 수동 가상러너 시뮬(spec-022)이 상위호환)
- Watch 없이 실행 시 시뮬 소스 주입 → 판정~코칭 전체 파이프라인 동작 (QA5 테스트가능성)

### QA4 이상값 필터 구조 (2단계 가드)

**Tier 1: 고정 범위 가드**
- 생리 범위 40~220 bpm 밖은 즉시 기각
- 센서 고장, 연결 끊김 등 명백한 오류를 막는 최소 안전장치
- 종류 C(설계 선택): 40/220은 정상 심박 최소/최대 범위 기준(참고: 나이 공식 오차는 ±10~15bpm, spec-001/§FR1)

**Tier 2: 세션 적응형 가드**
- Tier 1을 통과한 값 중에서 일시적 센서 튐(1~2초 점프 후 복원)과 지속적인 실제 변화(3초 이상 연속 변화)를 구분
- 구조: 최근 유효 심박 윈도우(10초, 종류 C)를 유지하면서 다음 판단 수행
  1. 중앙값(median) 계산: 10초 윈도우 내 유효 값들의 중앙값
  2. 변동폭(IQR): 윈도우 내 사분위수 범위로 정상 변화의 기대폭 산정(종류 A)
  3. 신규 샘플 검사: 새 HR이 (중앙값 ± 2·IQR)을 벗어나는 점프인가?
     - YES: 점프 기간이 1샘플(1초)만인가? → Tier 2 기각(이상값), 직전 중앙값으로 대체
     - NO: 지속 변화로 간주, 수용. 윈도우 갱신 후 3초 관찰 수행(중앙값이 안정되었는가?)
  4. 윈도우 관리: 신규 샘플 추가, 10초 이상 된 오래된 값 제거
- 종류 C 상수: 시간창 10초, 배수 2·IQR (문헌: 통계적 이상치 탐지 표준, Tukey 1977)

### 예외 처리
- Data Layer 연결 끊김: 마지막 유효값 유지 + 일정 시간 초과 시 코칭 보류
- 이상값 연속 유입: 기각 후 직전 유효 중앙값 유지, 윈도우 보존(지속성 판단 유지)

**수신 유통기한 `staleMs` = 15000ms(種類 C)**: `WatchHrProvider`는 마지막 수신 HR/SPM을 붙잡아 두되, 15초 넘게 미수신이면 `-1`(무효) 반환(`WatchHrProvider.kt:21`). 근거: 워치 HR은 BT/Wi-Fi로 간헐 끊김이 잦아 이보다 짧으면 파이프라인이 자주 멈춘다(실기기 관찰). 이는 워치 자체 표시용 8초 신선도(spec-010)와 별개인 폰측 수신 관용치로, 필드 데이터로 조정. 워치→폰 전송 범위 게이트(HR 30~240, SPM 60~260)는 spec-001/§FR1 참조.

## 수락 기준 (AC)

### 기존
- [x] AC-1: `RunSource` 인터페이스로 실센서/시뮬 소스를 코드 변경 없이 교체 가능

### Tier 1 (고정 범위 가드)
- [x] AC-T1-1: 40~220 bpm 밖 입력은 100% 기각되고 다운스트림에 전달되지 않음
- [x] AC-T1-2: 범위 내 값은 윈도우에 추가되어 다음 단계로 진행

### Tier 2 (세션 적응형 가드) — QA4 강건성 검증
- [ ] AC-T2-1: 10초 윈도우 유지, 신규 샘플 추가 시마다 중앙값/IQR 갱신
- [ ] AC-T2-2: 일시적 이상값 시나리오에서 기대 동작 일치율 100%
  - 시나리오: 안정 구간(120±5 bpm, 10초) → 점프 한 번(+30 bpm, 1초) → 복원(120±5 bpm, 5초)
  - 기대: 점프 1초는 기각, 나머지는 수용, 윈도우는 중앙값 120 유지
- [ ] AC-T2-3: 지속적 정상 변화 시나리오에서 기대 동작 일치율 100%
  - 시나리오: 안정 구간(120±3 bpm, 5초) → 선형 상승(120→140, 5초) → 안정(140±3 bpm, 3초)
  - 기대: 점프 없음, 모든 값 수용, 중앙값 120→130→140으로 평활(smoothing) 갱신
- [ ] AC-T2-4: 혼합 시나리오(점프+변화)에서 기대 동작 일치율 100%
  - 시나리오: 구간 A(120±2 bpm) → 한 번 튐(+35 bpm) → 구간 B(125±2 bpm, 지속) → 한 번 튐(−40 bpm) → 복원(125)
  - 기대: 첫 튐 기각, 구간 B 수용, 마지막 튐 기각, 최종 120 유지
