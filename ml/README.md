# ml/ — Zone 2 판정 PoC (오프라인 ML 검증 하네스)

Zone 2 판정 개인화의 핵심 AI를 오프라인에서 설계/학습/검증한다. 온디바이스 앱(app/) 이전에
"설계가 실제로 동작하고 목표 지표를 만족하는가"를 검증하는 단계다 (spec-004 §8, spec-006).

## 구성
- `simulator.py` — 물리 기반 러닝 세션 시뮬레이터. 참 Zone2 경계 θ*를 아는 가상 러너의
  세션을 생성하고, 다변량 특징 + 참 라벨을 산출. (라벨 확보 수단 → 지도학습 가능)
- `train_mlp.py` — Zone2 판정 MLP 학습/평가 + 설계 결정 정량 검증(3단 사다리).
- `artifacts/` — 학습 모델(.pt/.onnx), 지표(metrics.json), 플롯. (git 제외, 재현 가능)

## 실행
```bash
python3 -m venv .venv && ./.venv/bin/pip install -r ml/requirements.txt
./.venv/bin/python ml/simulator.py     # 데이터 통계 + 샘플 세션 플롯
./.venv/bin/python ml/train_mlp.py     # 학습/평가 → artifacts/
```

## 특징 (7) / 모델
입력: `hr_norm_u, hr_norm_l, dHR, pace, spm, decoupling, slope`
(HR을 개인 상/하한 경계로 정규화 → 개인화가 특징에 반영. spec-006 §1)
모델: MLP 7 → 32 → ReLU → 16 → ReLU → 3 (softmax). Adam + CE + early stopping + 노이즈 증강.

## 검증 결과 (seed=42, 러너 60명, 세션 360개, 러너 단위 분할)

### 설계 결정 기여도 (각 DP가 정확도를 얼마나 올리나)
| 단계 | Zone2 3분류 정확도(개발 지표) |
|------|:---:|
| 규칙 baseline (공식 임계값, DP1) | 0.485 |
| + 다변량 MLP (DP4) | 0.780 (+0.30) |
| + 개인화 정규화 (DP3) | 0.826 (+0.05) |

각 설계 결정이 정확도에 기여함을 정량 확인. NN이 규칙 대비 +30%p로 "왜 NN인가"를,
개인화가 +5%p로 "왜 개인화인가"를 실증.

### QA 목표 대비 (Zone2 판정은 실측 정답이 없어 QA는 코칭 방향으로 평가)
| 지표 | 결과 | 목표 | 달성 |
|------|:---:|:---:|:---:|
| **QA1 코칭 방향 정확성** (반대방향 오판 없음) | **0.996** | 0.95 | **O** |
| **QA2 이상치(40~220밖) 기각율** | **1.000** | 1.0 | **O** |
| 오르막 / 고드리프트 구간 정확도 | 0.811 / 0.787 | - | 유지 |

### 해석
- **두 QA 모두 목표 달성.** 코칭 앱의 핵심은 "느려야 하는데 빨리 뛰라"는 반대 오판을 안 내는 것
  (QA1 방향 정확성 99.6%)과 생리범위 밖 이상값을 거르는 것(QA2 100%).
- 3분류 exact 정확도(0.826)는 개발용 내부 지표. Zone2 판정은 실측 정답이 없어 그 자체를 QA로 쓰지 않는다.
- **센서 측정 노이즈는 프로젝트 범위 밖**(센서 하드웨어 소관). 강건성은 이상치 필터링으로 확보.
- 개인화(DP3)와 다변량(DP4)이 각각 정확도를 올림을 정량 확인 → 설계 정당성 입증.
