# 개인화 접근 A vs B — 실증 비교

두 개인화 접근을 같은 시뮬레이터/같은 test 러너로 비교한다 (adr-006).

- **A. 직접 Zone 분류** (MLP, `train_mlp.py`) — 다변량 특징 → 3분류. 개인 경계로 입력 정규화.
- **B. HR 회귀 + 잔차 개인화** (`hr_regressor.py`, 성시원 제안) — 맥락 → 예상 HR 회귀, 잔차로 개인화, 경계 도출 후 판정.

작성: 2026-07-02. 시뮬레이터 60명/360세션, 러너 단위 동일 분할.

---

## 결과

| 축 | A (분류) | B (HR 회귀) |
|------|:---:|:---:|
| 코칭 방향 정확성 (QA1) | **0.996** | 0.695 (decoupling 경계) / 0.899 (좋은 경계 가정) |
| Zone2 상한 추정 오차 (bpm) | (경계 내재) | 공식 4.1 / 오프셋 43.6 / decoupling 21.9 |
| HR 예측 오차 MAE (bpm) | - | 48.7 → **23.2** (개인화로 감소) |
| 실데이터 학습 가능 | 어려움 (참 Zone 라벨 없음 → 시뮬 의존) | **가능** (정답=실측 HR) |
| 해석가능성 | 낮음 (블랙박스) | **높음** (예상 HR/편차/경계) |
| 부가 산출 | 없음 | **피트니스(VO2max 상관), HR 예측** |

---

## 발견

1. **B의 개인화 메커니즘은 유효** — 잔차 보정이 HR 예측오차를 48.7→23.2 bpm로 낮춤. 정답(실측 HR)이 측정 가능해 실데이터로 학습·검증 가능(직접분류 A의 최대 약점 해소). (문헌 개인화 HR모델 중앙오차 ~6bpm; 본 시뮬레이터는 base_pace가 잠재변수라 오차가 큼)
2. **제안 원안(잔차 오프셋으로 Zone2 이동)은 실패** (43.6 bpm) — HR-페이스 오프셋은 "속도 체력"을 반영할 뿐 "유산소 임계 위치"가 아니다. 임계 도출엔 decoupling/편향점 신호가 별도로 필요(리서치와 일치).
3. **임계 추정은 어렵다** — decoupling 기반 추정(21.9bpm)이 현재 조악하여 공식(4.1bpm)보다도 나쁨. 임계 추정기 성숙이 B의 핵심 과제.
4. **A의 다변량 판정이 방향 오판을 더 잘 막는다** — 좋은 경계를 동일하게 줘도 A 0.996 vs B(단일 임계) 0.899. 다신호(dHR/decoupling/slope) 결합이 경계 근처 오판을 줄임.
5. **testbed 한계(중요)** — 본 시뮬레이터는 참 임계가 공식(0.70)에서 거의 안 벗어나(σ≈6bpm) 공식이 이미 4bpm으로 정확하다. 즉 **임계 개인화가 이길 여지가 작은 환경**이라, B(및 개인화 일반)에 불리하게 세팅돼 있다. 공정한 비교엔 개인 편차가 큰 시뮬레이터 또는 실데이터가 필요.

## 결론 (예비)

깨끗한 승자는 없다. 둘은 잘하는 지점이 다르다.

- **A (다변량 분류)** = 최종 **판정**이 강함 (방향 오판 최소, 0.996).
- **B (개인화 HR 모델)** = **개인화**가 강함 — 실측 HR로 학습·검증 가능, 해석가능, 피트니스 부산물. 단 임계 도출이 미성숙.

→ **하이브리드가 유력**: B의 개인화 HR 모델 + 임계 도출을 **개인화 코어(DP3, 실데이터로 적응)**, A의 다변량 분류기를 **판정(DP4)**. adr-006의 예상과 일치.

⚠️ 본 비교는 **예비**다. B의 낮은 판정 점수는 (a) 미성숙한 임계 추정기, (b) 임계 변동이 작은 시뮬레이터 탓이 크며, B 접근의 근본 한계로 단정하지 않는다.
