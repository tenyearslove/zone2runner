## 1. 목표

- Zone 2 판정 정확도 85% (과제계획서 지표)
- 코칭 방향 정확성 95% (QA1), 이상값 강건성 (QA2)
- 라벨(정답)이 없는 문제 → 물리 시뮬레이터로 라벨 생성 후 지도학습

## 2. 적용한 설계 (접근)

| 설계 | 내용 | 근거 |
|------|------|------|
| 물리 시뮬레이터 | 참 경계 θ*를 아는 가상 러너 세션 생성 → (특징, 참 라벨) | 라벨 확보(랩 검사 불가) |
| 러너 단위 분할 | train/val/test를 러너 단위로 분리 | 데이터 누수 방지 |
| 규칙 baseline | 공식(HRR) 임계값 판정 | 비교 기준 + 콜드스타트 폴백 |
| 다변량 MLP (DP4) | 7특징 → 32 → 16 → 3분류 | 단일 HR 임계값의 비선형 한계 극복 |
| 개인화 정규화 (DP3) | HR을 개인 상/하한 경계로 정규화해 입력 | 개인차 반영(QA3) |
| 이상치 필터 | 생리범위(40~220) 밖 값 기각 | 강건성(QA2) |

## 3. 튜닝 이터레이션 (진단 기반)

각 단계는 "문제 → 가설 → 조치 → 결과 → 진단"으로 진행했다. (수치는 test 정확도)

| # | 조치 | 3분류 정확도 | 진단/다음 가설 |
|:-:|------|:---:|------|
| 0 | 초기: 6특징(공식 정규화, 순간값) + MLP | MLP 0.70 / 규칙 0.53 | 85% 미달. HR 지연으로 순간 라벨이 모호할 것 |
| 1 | 라벨을 지속 강도(이동평균) 기준으로 | 0.69 | 변화 없음 → 천장은 라벨 스무딩이 아님 |
| 2 | HR을 개인 경계로 정규화(개인화) + 추정오차 민감도 | 0.69 (완벽 개인화도 0.69) | **개인화가 안 먹힘.** 경계 지식이 병목 아님 |
| 3 | HR/페이스를 지속(윈도우 평균) 특징으로 | 0.69 | 여전. 다른 원인 의심 → 시뮬레이터 점검 |
| 4 | **Cardiac Drift 현실화** (반감기 11분 → 시상수 2~3분 회복) | 규칙 0.49 → MLP 0.73 → 개인화 0.74 | **핵심 수정.** 드리프트 잔류가 HR을 현재 강도와 계속 어긋나게 했음. 이제 개인화가 +기여 |
| 5 | **하한도 개인화**(7번째 특징 hr_norm_l) | 0.74 | below↔in 혼동이 최대였음(상한만 개인화했던 탓). 하한 개인화로 완화 |
| 6 | 방향 정확성 지표 추가(튜닝 아님, 평가 관점) | — | 반대방향 오판 0.5% → 방향 정확성 0.996 |
| 7 | **센서 노이즈 제거**(프로젝트 범위 밖) + QA2를 이상치 필터로 재정의, 평가지표를 코칭 방향으로 확정 | **0.83** | 센서 측정노이즈는 센서 소관. 판정은 실측 정답 없음 → QA는 코칭 방향 정확성으로 측정. 노이즈 제거로 개인화 기여도 뚜렷(+5%p) |

### 결정적 진단 2가지
- **완벽 개인화 프로브**(추정오차=0)로도 정확도가 안 오름(#2) → 병목이 "개인 경계를 모르는 것"이
  아니라 "관측 HR이 강도와 어긋난 것"임을 특정 → 시뮬레이터 드리프트 모델 수정(#4)으로 해결.
- **혼동행렬**에서 below↔in이 지배적 → 상한만 개인화한 게 원인으로 특정 → 하한 개인화(#5).

| **QA1 코칭 방향 정확성** (반대방향 오판 없음) | **0.996** | 0.95 | **O** |

(초기 60러너/360세션에서도 0.485→0.780→0.826으로 사실상 동일 — 데이터 3배 확대로 견고성 확인.)

## 5. 결론 및 해석

- **두 QA가 모두 목표 만족**: QA1 코칭 방향 정확성 0.996(≥0.95), QA2 이상치 기각 1.000.
- **각 설계 결정이 정량 기여**: 규칙 0.544 → +MLP(DP4) 0.802 → +개인화(DP3) 0.828. NN 도입과 개인화의 정당성 실증.
- **평가 관점(중요)**: Zone2 판정은 실측 정답(ground truth)이 없어 판정 자체의 정확도로 QA를 평가할 수 없다.
  따라서 QA1은 "현재 심박 수치 대비 코칭 방향이 맞는가"로 측정한다. 3분류 정확도(0.828)는 개발용 내부 지표일 뿐.
- **센서 노이즈는 프로젝트 범위 밖**(센서 하드웨어 소관)이라 제외. QA2 강건성은 생리범위 밖 이상치 필터링으로 달성.

## 7. 콜드스타트 prior 정교화 실험 (2026-07-03, adr-012/spec-013)

`prior_experiment.py` — 프로필 factor(체형/러닝 수준/빈도) 기반 prior vs 고정 공식(HRR 70%).
factor 매핑은 참 편차의 일부(capture 0.6)만 설명 + 매핑 오차(σ 0.02) + 앱과 동일 clamp로 모델링
(문헌 기반 오프셋 표의 불완전성을 정직하게 반영). 러너 300명, Bayesian 갱신은 동일 조건.

| 지표 | 고정(0.70) | factor prior | 개선 |
|------|---:|---:|---|
| 세션 0 오차 평균 | 4.34 bpm | **2.51 bpm** | **-42%** |
| 세션 0 오차 p90 | 8.85 bpm | **5.15 bpm** | -42% |
| 3bpm 도달 세션 수(관측 저품질 σ12) | 2.0 | **1.0** | 절반 |

민감도(capture): 매핑이 무가치(0.0)여도 손해는 +0.08bpm에 그침(clamp 효과) — **downside 제한**,
매핑 품질에 비례해 이득(0.3→3.35, 0.9→1.99bpm). "입력만으로 의미 있는 초기값, 데이터로 적응"(DP2)의 정량 근거.

> ★ adr-016(2026-07-04)로 최종 정리: 아래 §8(심박 동역학 NN)은 현행 유지(NN=심박 예측), §10(역치 추정 NN)은 강등(개인화는 Bayesian 전담). 각 절 참조.

## 9. 드리프트(decoupling) 특징 ablation + 페이스 단조성 (2026-07-03, adr-013 옵션1)

사용자 질문("드리프트가 꼭 필요한가, 왜 38%/심박200이 나오나")에서 출발한 재검토.

**ablation** (`ablation_decoupling.py`, 동일 데이터/분할):

| 구성 | t+30 RMSE | t+60 RMSE | 페이스 단조성 위반 |
|------|---:|---:|---:|
| 8특징(decoupling 포함) | 8.30 | 14.65 | 1.3% (AC3 O) |
| 7특징(decoupling 제거, 페널티 없음) | **6.74** | 14.94 | **18%** (AC3 X) |
| 7특징 + 단조 페널티(W=6) | 9.04 | 15.62 | **0.0%** (AC3 O) |

- **발견**: decoupling은 예측 정확도엔 무익(빼면 오히려 개선)했지만, 페이스 응답의 **정칙자**였음 —
  빼니 "느리게 뛰면 심박 내려간다"가 18%에서 깨짐(역질의=페이스 제안이 불안정).
- **해결**: 그 역할을 학습 단계 **단조성 페널티**(느린 페이스가 예측 심박을 올리면 벌점)로 대체.
  decoupling 없이 단조성 0% + baseline(persistence 15.08/26.69) 확실히 하회. 최종 채택.
- **드리프트의 최종 위치**: 판정 경로엔 없음(규칙 판정), NN 입력에서도 제거. **표시/리포트 전용 지표**로만
  남기되 -10~+25% 클램프(실제 드리프트 0~15%, 시뮬 심박 포화/GPS 튐으로 인한 헛값 38% 방지).
- **왜 38%/심박200이었나**: 시뮬 강도 상한이 과해 심박이 최대심박 클램프에 붙고(=200), 표시 드리프트
  (속도 대비 심박 비용)가 동반 폭증(=38%)한 아티팩트. 강도 상한 0.85로 하향 + 표시 클램프로 해소.

## 10. 개인 젖산역치(Zone2 상단) 추정 MLP (2026-07-04, adr-014/spec-015 → adr-016로 강등)

> ★ **강등(adr-016, 2026-07-04)**: 아래 역치 추정 NN은 개인화 경로에서 제거됨. 개인 Zone2 학습은
> 소수/온라인 라벨(토크테스트)이라 Bayesian이 전담하는 게 옳다. 딥러닝 NN은 심박 예측(§8)에 둔다.
> Etxegarai/Zhu는 우리 방법 근거가 아니라 "NN 대신 Bayesian을 택한 대조군". 아래는 기록 보존.

프로젝트 본래 목적 복원 — "사람마다 다른 Zone2를 랩 없이 더 정확히". 문헌 근거로 NN 도입:
Etxegarai et al.(2018, RNN, R=0.89) / Zhu et al.(2025, 전이학습 RNN, MAE 4.37bpm)의 "다신호 →
신경망 → 무랩 역치 추정" 접근을 1인 과제 규모로 경량화(RNN → 소형 MLP, 집계 특징).

`train_threshold.py` — 세션 특징 8종(심박-속도 반응 삼분위/기울기/드리프트/케이던스/RHR/나이) → 참 uFrac 회귀.
시뮬레이터가 러너마다 다른 참 역치 생성(라벨). MLP 8→16→8→1.

| 지표(참 대비 MAE, bpm) | 결과 |
|---|---|
| 공식 고정(%HRR 0.70) baseline | 6.09 |
| **MLP 추정** | **4.73 (-22%)** |

- baseline이 "선형"이 아니라 **실제 통용 공식(0.70)** — "우리 NN이 공식보다 낫다"가 정직한 방어점.
- export: `threshold_mlp.json` (순수 Kotlin 순전파). 앱: 세션 종료 시 특징 집계 → uFrac 추정 →
  LearnedZone(EMA 누적) → 다음 세션 prior. NN=관측 산출기, 누적=적응(adr-014).
- 한계(명시): 랩 참값 부재로 절대 정확도 미검증 → 무랩 서로게이트(토크테스트/DFA-α1) 정합 + 수렴으로 대체.
  실데이터 fine-tune은 향후(필드 로그 spec-012, 공개 데이터 athlete_hr_predict 등 활용 가능).

## 11. Zone2 기준 재보정: %HRR → %HRmax (2026-07-04, 실기기 피드백)

**문제**: 실측 maxHr 사용자(max200/RHR60)에게 기존 %HRR 0.70이 %HRmax 79%(Zone3~4)로 과대평가.
Zone2가 155~169로 떠서 편한 유산소 러닝이 계속 "미달"로 나옴(실주행 피드백).

**원인**: 여유심박(HRR=140)이 큰 사용자는 %HRR에 안정심박을 더하는 방식이 유독 높게 나옴.
생리 문서가 %HRR을 택한 근거("나이기반 maxHr 과소평가 보정")는 **실측 maxHr엔 역효과**.

**수정**: 참/공식 Zone2 상단을 **%HRmax 0.70(유산소 임계 LT1 근사)** 기준으로 재정의.
- simulator: 참 상단 = %HRmax 0.70±(개인차) → HRR 비율로 환산(파이프라인 규약 유지)
- Zone2Prior: uFrac0 = (0.70×maxHr − RHR)/HRR, 클램프 0.30~0.75, BAND 0.10→0.12
- 클램프 완화(Personalization/ThresholdEstimator/LearnedZone): 0.55~0.80 → 0.30~0.75
  (실측 maxHr/저RHR은 HRR 비율이 낮으므로, 토크테스트로 더 내려갈 수 있게)
- 역치 NN 재학습: 새 라벨 기준 MAE 4.44bpm

**결과**: max200/RHR60 사용자 Zone2 155~169 → **123~140bpm(62~70% HRmax)**. 실사용 체감과 일치.
동역학 NN은 낮아진 임계로 드리프트가 잦아져 일시 악화(18.95/30.44) → 시뮬 강도를 Zone2 부근으로
낮춰 재튜닝, **현재 배포 모델 RMSE t+30 14.01 / t+60 20.45 bpm**(persistence 17.01/30.23 대비, 단조성 0%).

## 13. 상황조건 드리프트(퍼셉트론/ADALINE) 검증 → 기각 (2026-07-07)

질문: 예측 ODE의 드리프트 항을 '상수 스칼라' 대신 '상황조건 온라인 퍼셉트론(ADALINE, 사전학습 0)'으로
확장하면 나아지나? 리서치 2건(생리: 드리프트=임계초과×시간×더위, hinge 특징+on-kinetics 게이팅 필요 /
방법론: LMS보다 Kalman/RLS 권장, 특징표준화·leaky·clamp, 이득 modest·짧고시원한 러닝엔 스칼라로 충분)으로
설계를 최적화한 뒤 시뮬 폐루프로 정면 비교(`ml/experiment_context_drift.py`, τ 오라클로 드리프트만 격리).

결과(마지막 세션 60초 RMSE, bpm): **Ref0(드리프트 학습 안 함) 7.68 << A(상수) 10.01 ≈ B(퍼셉트론[1,rex]) 9.67
< C(+elapsed) 11.41 < D(+열적분) 14.08.** 퍼셉트론(B)이 상수(A)를 +3.4% 이기지만, **둘 다 "드리프트
안 배움"보다 크게 나쁨.** 특징 추가할수록 악화(식별성/과적합, 방법론 리서치 경고대로).

해석: 예측이 **현재 기울기로 정상상태를 역추정**(hSS=현재+τ·dHR)하므로, 완만한 드리프트는 이미 현재 심박/
기울기에 반영돼 궤적으로 캡처됨 → 별도 드리프트 항은 중복이고 variance만 더함(bias-variance 손실). 생리
리서치도 "드리프트는 덥고 긴 러닝에서 큼"이라 30분·무더위 없는 시뮬은 애초에 드리프트 이득이 없는 영역.

결정: **상황조건 드리프트 퍼셉트론 기각(미구현).** 부수 발견 = 드리프트 항 자체가 60초 예측엔 marginal.
예측을 Kalman(Bayesian)으로 올리는 것도 검토했으나 DP1/DP2가 유사해져 보류(사용자 판단). DP1 최종 =
순수 생리 ODE + LMS 점추정 유지. (더위×강도 항은 시뮬에 기온이 없어 검증 불가 → 실데이터/시뮬 확장 후 과제.)

## 14. DP1 다중 시간대 추이 예측 — 프로토타입 검증 (2026-07-09)

배경: DP1을 ODE에서 **다중 시간대 추이 + 페이스 기반 전이 가중 + 개인 반응 보정층**으로 재설계
(`arch/hr-prediction-multiscale-trend-design.md`, 쉬운판 `arch/hr-prediction-쉬운설명.md`). 이 알고리즘이
실제로 도는지, 각 조각(페이스 전이 가중 / 보정층 학습)이 값을 하는지 시뮬 폐루프로 검증.
코드: `ml/hr_multiscale_prototype.py` (numpy만, 산출물 `ml/artifacts/*.png|csv` — gitignore).

방법: 합성 러너(1차 지연 τ=25s + 카디악 드리프트 + 센서 노이즈 — 예측기는 이 식 모름)로 지상진실 생성.
시나리오 = 워밍업→**감속(심박 상승 중! = 중기/장기 stale 상승세, 단기만 꺾임)**→정속→재가속→장시간 정속+드리프트.
4개 비교: persistence / 균등평균 / 페이스가중 뼈대 / +보정(풀). 자기지도 라벨=30초 뒤 실측. 지평 30초, seed 7.

결과(30초 앞 MAE, bpm, 낮을수록 좋음):

| 구간 | persistence | 균등평균 | 페이스뼈대 | +보정(풀) |
|---|---|---|---|---|
| 전체 | 3.24 | 3.24 | 3.30 | **2.63** |
| 전이(감속/가속) | 7.61 | 8.10 | 8.82 | **7.01** |
| 정속 | 1.96 | 2.64 | 3.06 | 2.26 |
| 드리프트 | 1.54 | 1.70 | 1.74 | 1.54 |

반응 배율 g: 1.0 출발 → **0.3~0.7 수렴**("직선 추세의 30~70%만 실제로 움직인다" 자가 학습). 게이트 ON 76%.

해석/검증된 설계 주장 3개:
1. **전이구간에서 예측이 persistence를 이긴다**(풀 7.01 < persist 7.61), 전체도 2.63 < 3.24(~19%↓).
   리서치대로 가치는 전이에 몰림 — 정속은 근소 열세(예상), 드리프트는 무승부.
2. **보정층(학습)이 성능의 핵심**: 페이스뼈대 단독은 전이서 오히려 나쁨(8.82 > persist) — 직선 30초 외삽이
   지연 심박을 과하게 넘겨짚음. 보정층이 이를 배워 7.01로 끌어내림 = 학습이 안전장치가 아니라 성능을 만듦.
3. **페이스 가중이 stale 추세 문제를 짚음**: 균등평균은 상승 중 감속에서 오버슈트(8.10), 페이스 가중+보정이 개선.

정직한 한계/다음 숙제:
- **g_down이 바닥(0.3)에 붙음** = 하강 예측에서 직선 외삽이 특히 과함. 배율만으론 부족 → **직선 대신 감속(포화)
  곡선 외삽**이면 보정층 부담↓ (다음 튜닝 후보).
- 정속 열세(작음): 코칭이 정속에선 예측을 덜 신뢰하게(전이일 때만) 하면 됨.
- 시뮬 지상진실 기준 — 실주행 라벨 채점은 여전히 미착수(spec-012).

결정: **설계 방향 유효 확인, 계속 진행.** 승인 후 ADR/spec 승격 + Kotlin 앱 포팅. 코드/문서는 미승인(탐색) 상태 유지.

## 15. DP1 뼈대 외삽 = 감속 곡선 + 프로필 봉투 / 비대칭 τ 기각 (2026-07-10)

배경: §14의 뼈대는 **직선 외삽(fused_b·H)** — 하강/정속에서 과대예측(g_down이 배율 바닥 0.3에 붙음).
사용자 제안 = "프로필 안정/최대심박으로 직선 대신 **최대심박 쪽으로 수렴하는 곡선**을 쓰자". 정정: 수렴 목표는
최대심박이 아니라 **그 강도의 submaximal 정착점**(Zone2는 최대에서 한참 아래) → **궤적에서 역산한 목적지로
향하는 감속 곡선 + 프로필 [안정,최대] 봉투 clamp**로 구현. 이어서 상승/하강 비대칭 τ를 sweep 검증.

### 15-1. 프로필-봉투 + 감속곡선 (직선→곡선)
`dest = clamp(hr_now + τ·fused_b, resting, max); skel_change = (dest−hr_now)(1−e^(−H/τ))`, τ=30.
30초 앞 MAE(bpm), 직선(§14)→곡선:

| 구간 | persist | 뼈대 단독 직선→곡선 | 풀(보정) 직선→곡선 |
|---|---|---|---|
| 전체 | 3.24 | 3.30 → **2.49** | 2.63 → **2.31** |
| 전이 | 7.61 | **8.82 → 6.83** | 7.01 → **6.11** |
| 정속 | 1.96 | 3.06 → 2.41 | 2.26 → 2.18 |
| 드리프트 | 1.54 | 1.74 → 1.60 | 1.54 → 1.54 |

핵심: **뼈대가 자립.** 직선 뼈대는 전이서 8.82로 persistence(7.61)보다 나빴는데(과대예측), 곡선 뼈대는
6.83으로 persistence를 이긴다. 게이트 ON 76%→**56%**(구조가 더 하고 학습이 덜 함 = "값은 구조에서 도출" 강화).

### 15-2. 상승/하강 비대칭 τ sweep → **기각**
가설: "회복(off-kinetics)은 느리니 τ_down>τ_up". τ_up=30 고정, τ_down∈{60,30,15} sweep(전이 풀 MAE / g_down):

| τ_down | 전이 풀 | 전체 풀 | g_down |
|---|---|---|---|
| 60(느림) | 6.32 | 2.34 | 0.30 |
| 30(대칭) | 6.11 | 2.31 | 0.30 |
| 15(빠름) | 5.95 | 2.29 | 0.30 |

- **가설 반증**: τ_down 키우면(느린 회복) 오히려 **나빠짐**. 결합공식 `τ·(1−e^(−H/τ))`가 τ의 증가함수라,
  큰 τ_down = 큰 하강 예측 = 과대예측 심화(backfire). 문헌만 보고 진단한 방향이 우리 구조에선 뒤집힘 — 실험이 잡음.
- **g_down floor는 τ와 완전 무관(전부 0.30)** → 바닥 원인은 비대칭이 아니라 **급강하 직후 짧은 창 기울기가
  하강률을 과대 표현**하는 것(τ 어떤 값으로도 못 고침). 다만 게이트가 하강을 뼈대로 폴백해 **성능은 안 무너짐**(무해).
- **결정: 비대칭 τ knob 채용 안 함.** 정당한 방향(느림)은 손해, 이득 방향(빠름)은 근거 없어 시뮬 과적합.
  대칭 단일 τ=30 유지(상수 하나, 문헌 근거). 프로필-봉투+감속곡선은 **채택**(뼈대 자립 효과 명확).

### 15-3. ★ 정직 경고 — 이 MAE는 "정확도 증거"가 아니다 (사용자 지적)
지상진실을 **우리가 1차 지연(감속 곡선)으로 썼고** 예측기도 감속 곡선을 가정 → **"곡선이 직선을 이긴다"는
사실상 정의상 성립**(짜고치기). persistence를 이기는 것도 시뮬 추세가 깨끗해 **실제보다 쉽다**(리서치: 실 안정
상태선 랜덤워크가 이김). **따라서 15-1의 MAE는 알고리즘 건전성/상대 비교일 뿐, 실인간 정확도 아님.**
- **시뮬의 정당한 용도 = 디버거**(발산/수렴/명백한 실수 잡기). 15-2의 비대칭 τ 반증은 **시뮬 숫자가 아니라
  공식 구조에서 나온 것**이라 정당한 사용. 15-1을 "품질 증거"로 파는 건 선 넘음 → 강등해 표기.
- **짜고치기를 실제로 깨는 유일한 길**: (a) 실주행 몇 개로 채점(학습셋 아닌 **검증용** — 자기지도라 2~3회로도
  "실심박서 persistence 이기나?" 답 나옴, spec-012), (b) 시뮬 지상진실을 1차가 아닌 **2상(biphasic) 모델**로
  바꿔 "곡선이 시뮬 모양 덕에 이긴 것"이 아님을 보이기. 둘 다 미착수.

결정: **여기까지 저장하고 다른 길 탐색(사용자).** 코드 = 프로필-곡선 채택 + 대칭 τ(비대칭 env로 재현 가능).
