## 슬라이드 4 — 품질 속성 및 ASR 선정

**품질 속성 (출처: spec-002)**

| ID | 품질 속성 | 측정 |
|:---:|------|------|
| QA1 | 기능정확성(AI) | Zone 상태 대비 코칭 방향 일치율 95% 이상 |
| QA2 | 강건성(AI) | 이상치(40~220 밖) 기각율 100% |
| QA3 | 적응성(AI) | 누적 데이터로 개인 경계 실측 방향 이동 |
| QA4 | 효율성(AI) | 이탈 감지→음성 5초 이내 |
| QA5 | 테스트가능성 | HR 소스 교체로 Watch 없이 전체 검증 |

**Utility Tree → ASR 선정**: 중요도 7 이상을 ASR로 선정 (QA1~QA5 전부 해당). 우선순위 QA3 > QA1 = QA4 > QA2 > QA5.

**핵심 평가 관점**: Zone 2 판정은 실측 정답(ground truth)이 없으므로, 판정 정확도 자체가 아니라 **현재 심박 대비 코칭 방향의 정확성**(QA1)으로 평가한다.

## 슬라이드 5 — 설계: Architectural Decisions 개요

각 ASR을 해소하는 핵심 설계 결정(DP)을 대안 비교로 도출 (arch/adr-00X).

| DP | 결정 | 해소 QA |
|:---:|------|------|
| DP0 | Watch-Phone Hybrid (Watch=수집, Phone=AI) | C01 |
| DP1 | Zone2 판정 = 규칙 baseline + 개인화 하이브리드 | C02, QA2 |
| DP2 | LLM 코칭 = 규칙이 방향 + LLM 표현 + 출력 가드 | QA1, QA4 |
| DP3 | 개인 경계 추정 = 공식 prior + Bayesian 적응 | QA3 |
| DP4 | 실시간 판정기 = 다변량 MLP 분류기 | QA1, QA2 |

AI 역량 2개로 압축: (1) 개인화된 Zone 2 판정, (2) On-device LLM 코칭.

## 슬라이드 6 — 설계: 개인화 Zone 2 판정 (DP1/DP3/DP4)

**문제**: 단일 HR 임계값(선형)은 오르막/Cardiac Drift/이상치 상황에서 오판 → QA1 미달.

**결정**: 3층 협업 구조

- **규칙 baseline** (공식 HRR): 콜드스타트 prior + 안전 가드
- **개인화 (Bayesian)**: 누적 세션으로 개인 경계를 실측 방향 보정 (QA3, 주 목적)
- **다변량 MLP 판정기**: HR(개인 경계 정규화)/페이스/케이던스/디커플링/경사 → 미달/유지/초과

**근거**: 판정 정확성(QA1)을 규칙의 단변량 한계로는 못 채우므로 비선형 다변량 판정기(NN)가 필요. 개인화가 이 과제의 핵심.

## 슬라이드 7 — 설계: On-device LLM 코칭 (DP2)

**문제**: 정해진 문구 반복이 아닌 자연스러운 상황 코칭. 단 방향(가속/감속)은 틀리면 안 됨(QA1), 5초 이내(QA4), 오프라인.

**결정**: 규칙이 방향 결정 + LLM이 표현 + 출력 가드

```
규칙: Zone 상태 + 맥락 → 코칭 의도(가속/감속/유지/독려)   [방향 보장]
 → LLM: 의도 + 맥락 → 자연스러운 한 문장                  [자연스러움]
 → 가드: 방향 일치/길이/금지어 검증, 실패 시 템플릿 폴백   [QA1/QA4]
 → TTS 음성 출력
```

On-device LLM(Galaxy AICore 상정)으로 프라이버시/오프라인 확보.

## 슬라이드 8 — 최종 Architecture

```
[Galaxy Watch 8]                 [Galaxy S26 Ultra]
Sensor SDK                       HrSource(Real/Mock) → 이상치 가드(40~220)   [QA2]
HR 1~2초  ──Data Layer──▶        → Zone2 판정: 규칙 + 개인 경계(Bayesian) + MLP  [QA1/QA3]
                                 → 코칭 의도(규칙) + LLM 표현 + 가드 → TTS      [QA1/QA4]
                                 → 세션 기록/개인화 누적                        [FR5/FR6]
```

**모듈**: wear(수집) / app(hr, zone2, coaching, session) / shared(도메인). zone2·coaching은 HrSource에만 의존 → Watch 없이 Mock 검증(QA5).

## 슬라이드 9 — 구현 및 검증 (1): Zone 2 판정 MLP

**구현**: 물리 시뮬레이터로 라벨 생성(정답 부재 해소) → 다변량 MLP(7→32→16→3) PyTorch 학습 → TFLite 온디바이스.

**검증 결과** (러너 60명/360세션, 러너 단위 분할)

| 지표 | 결과 | 목표 |
|------|:---:|:---:|
| 설계 사다리: 규칙 → +MLP → +개인화 | 0.485 → 0.780 → 0.826 | - |
| QA1 코칭 방향 정확성 | **0.996** | 0.95 |
| QA2 이상치 기각율 | **1.000** | 1.0 |

각 설계 결정(MLP, 개인화)이 정확도에 기여함을 정량 확인. QA1/QA2 목표 달성.

## 슬라이드 10 — 구현 및 검증 (2): 개인화 (Bayesian)

**구현**: 공식(HRR)을 사전분포로, 세션 관측으로 켤레 가우시안 갱신 (경량 산술, 온디바이스).

**검증 결과** (QA3 수렴)

| 관측 조건 | 세션1→10 오차 | 판정 |
|------|:---:|:---:|
| 메커니즘(관측 양호) | 5.1 → 2.2 bpm, σ 8→1.9 | 수렴 O |
| 실제(decoupling 임계추출) | 11.4 → 15.3 bpm | 발산 |

**결론**: 적응 루프(Bayesian) 자체는 정상 수렴(QA3 실증). 병목은 "필드 데이터에서 개인 임계 추출"(Conconi 편향으로 알려진 난제) → 한계/향후과제로 명시.

## 슬라이드 11 — 설계 대안 검토 (판단 근거)

개인화 접근을 두 방식으로 실증 비교 (adr-006, ml/COMPARISON.md).

| 축 | A. 다변량 분류 | B. HR 회귀 + 잔차 개인화 |
|------|:---:|:---:|
| 코칭 방향 정확성 | 0.996~0.999 (견고) | 0.90 (좋은 경계 가정) |
| 실데이터 학습 | 어려움 | 가능(정답=실측HR) |
| 해석가능성 | 낮음 | 높음 |

**결정**: 주 판정기 = A. B(개인화 HR 모델)는 개인 경계 적응/피트니스 보조로 채택. "개인차가 클수록 개인화가 값지다"를 정량 확인. 무게중심 A의 하이브리드.

## 슬라이드 12 — 결론

**주요 성과**

- Galaxy Watch + On-device LLM 기반 개인화 Zone 2 코칭 아키텍처 설계 (DP0~DP4, 대안 비교 기반)
- 다변량 MLP 판정기 구현/학습, QA1 코칭 방향 0.996 / QA2 이상치 기각 1.0 달성
- 개인화 적응(Bayesian) 수렴 메커니즘 실증 (QA3)

**한계 및 향후 계획**

- 개인 임계의 필드 데이터 추출이 핵심 난제(현 단계 한계) → 실데이터 기반 개선
- On-device LLM/Watch 실연동, app 스캐폴딩은 후속 구현 단계

**기대효과**: 고가 장비 없이 개인 맞춤 Zone 2 코칭 가능성 검증, Samsung Health 기반 AI 코칭 확장 근거.
