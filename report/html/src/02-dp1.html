DP1. 설계 문제 정의

3

1.배경

  • 이 앱은 심박을 보며 달리기를 실시간으로 코칭한다 — "지금 존을 벗어났어요", "속도를 조금 낮춰볼까요".
  • 핵심 품질은 설명용이성이다. 모든 판정과 코칭의 근거를 남겨 리포트에서 확인할 수 있게 하고, 판정이 몸 상태와 다르다고 느끼면 말하기 테스트 답으로 판정 기준을 바로잡을 수 있게 한다.
  • 설명은 풍부할수록 좋다. 단, 앱이 실제로 판단한 근거를 그대로 보여줘야지, 그럴듯하게 지어낸 이유를 보여줘서는 안 된다. 이를 지키는 구조를 고르는 것이 이 설계 결정이다.

2.문제점

  • 정답지가 없다. 진짜 Zone 2인지는 실험실에서나 잴 수 있으니, 설명이 맞았는지 나중에 채점할 수 없다.
  • 그래서 틀린 설명이 처음부터 만들어질 수 없는 구조가 필요하다. 설명 기능이 아니라 판단 구조를 고르는 문제가 되는 이유다.
  • 판단 기준이 계속 바뀐다. 개인 경계는 러닝마다 갱신되고, 설명은 늘 그 최신 값을 보여줘야 한다.
  • 작은 LLM은 그럴듯한 말을 지어낼 수 있다. 설명을 통째로 맡기지 말고 역할을 제한해야 한다.

많은 사람의 데이터로 미리 학습한 모델이 판정과 코칭을 직접 내놓는다. 판단 과정은 수많은 내부 숫자에 흩어져 있어 사람이 읽을 수 없다. 그래서 설명은 결정이 난 뒤에 별도 분석 도구나 LLM이 추정해서 만들어 붙인다.

DP1. 설계결정 및 근거

3

1.최종 채택 구조

후보 1: 규칙/통계 기반 개인화 아키텍처 채택

2.채택 근거

  • 판단 근거가 그대로 설명이 된다. 판단에 쓴 숫자와 규칙을 그대로 보여주므로 지어낸 설명이 나갈 수 없다. 코칭 문장마다 근거 수치와 만들어진 과정이 기록되어 리포트에서 다시 확인할 수 있다.
  • 사용자의 정정이 바로 반영된다. "그건 내 느낌과 달라"라고 답하면(말하기 테스트) 그 자리에서 개인 경계가 움직이고, 얼마나 움직였는지 화면에 보인다. 2안은 정정을 모아 재학습해야 반영되고, 반영 여부를 확인하기도 어렵다.
  • 이 과제의 조건에 맞는다. 2안이 힘을 쓰려면 많은 데이터와 정답지가 필요하다. 이 과제에는 둘 다 없다. 입력도 심박, 페이스처럼 뜻이 분명한 몇 개의 신호여서, 투명한 모델을 써도 정확도 손해가 작다(Rudin 2019).
  • 폰에서 가볍다. 설명은 이미 계산한 값을 보여줄 뿐이라 추가 연산이 거의 없다.
  • 확장 여지도 있다. 정답 데이터가 생기면 2안 요소를 더해 고도화할 수 있다.

3.보완 계획

  • 단기: 시중 러닝 앱의 설명 기능을 조사한다. 사용자에게 설명이 이해되는지 평가한다. LLM 문장 기각 기록으로 표현 왜곡을 지켜본다.
  • 장기: 설명이 판단과 일치해도 판단 자체는 틀릴 수 있다. 이 부분은 말하기 테스트 정정을 강화해 메운다.

Appendix. DP1 상세 설계 내역

A

1.문제점이 걸리는 품질 속성

  • 사용자가 설명을 이해하지 못하면 코칭을 따르지 않는다 → 설명용이성
  • 설명이 지어낸 이유여서는 안 된다 → 설명용이성(심화)
  • 정답지가 없어 사후 채점이 불가능하다 → 구조 선택으로 대응
  • 개인 경계가 계속 갱신된다 → 기능적응성
  • 사용자가 정정할 수 있어야 한다 → 제어가능성
  • 폰 혼자, 추가 비용 없이 돌아야 한다 → 수행효율성
  • 소형 LLM이 말을 지어낼 수 있다 → 제어가능성, 강건성

2.채택안의 설명 생성 경로 5단계 (다른 DP의 구조 표와 같은 형식)

단계하는 일
1. 사실 확정규칙/통계가 판정과 근거 숫자를 확정한다 — 설명의 재료는 전부 여기서 나온다
2. 근거 기록각 수치의 출처(관측/학습/설계)와 코칭의 근거 관측이 그 자리에서 기록된다
3. 표현 한정LLM은 확정된 사실을 문장으로 바꾸는 일만 한다 — 이유를 지어내지 않는다
4. 표현 검사나가는 문장의 형식, 방향, 숫자를 규칙이 다시 검사한다
5. 추적 열람리포트에서 문장을 누르면 근거 관측과 생성 과정을 그대로 볼 수 있다

별점은 이 DP의 결정 범위가 해당 QA에 미치는 영향을 이 과제 조건에서 평가한 것이라, 같은 QA 명칭이라도 DP마다 평가 대상 행위가 다르다(예: DP1의 기능적응성=규칙 밖 패턴 학습 능력, DP3의 기능적응성=경계 적응 지연). 이 별점은 폰 단독, 정답지 없음, 소수의 분명한 신호라는 이 과제 조건에서의 평가다. 조건이 다르면(복잡한 신호, 정답 확보 가능) 2안이 나을 수 있다. 덧붙여 2안은 이 과제의 제약(C02 대량 데이터 확보 불가)과 정면 충돌한다 — 이 비교는 제약이 결정을 만든 사례를 보이는 비교이기도 하다.

4.예상 질문

  • "사후 설명 도구(SHAP, LIME)를 붙이면 2안도 설명되지 않나?" → 그 설명은 모델 밖에서 추정한 근사라서 실제 판단과 같다는 보장이 없고, 계산도 무겁다.
  • "LLM에게 설명을 다 시키면 되지 않나?" → 자기가 내리지 않은 판단의 이유를 지어낼 위험이 있다. 이 설계에서 LLM은 이미 정해진 내용을 문장으로 바꾸는 일만 한다.

5.용어와 문헌

  • 용어 대조(심사용): 1안의 설명 방식 = intrinsic interpretability(모델 자체가 해석 가능), 2안의 설명 방식 = post-hoc explanation(사후 설명), 설명과 실제 판단의 일치 = fidelity(충실도), 값의 출처 추적 = provenance, data lineage
  • 근거 문헌: Rudin(2019, Nature Machine Intelligence) — 신뢰가 필요한 결정에는 해석 가능한 모델을 쓰라 / XAI 충실도 문헌(2024, 상세 서지는 설계문서 부록 A) / 웨어러블 XAI 체계적 리뷰(JMIR 2024, 사후 설명이 88%) / DARPA XAI 프로그램
