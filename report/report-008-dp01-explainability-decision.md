## 슬라이드 1 — DP1. 설계 문제 정의

### 1. 배경

- **코칭 서비스의 지향**
  - 이 시스템은 심박을 보며 달리기를 실시간으로 코칭하는 앱이다("지금 존 초과", "당신의 Zone 2 상한", "속도를 조금 낮춰볼까요"). 코칭은 어디까지나 참고용
  - 정체성 품질 = 설명용이성(AI 특화 QA): 판정/경계/코칭마다 "왜"를 풍부하게 붙이고, 사용자가 이를 보고 관측과 어긋나면 정정할 수 있게 하는 것이 이 시스템의 지향
- **XAI의 핵심 함정 — 그럴듯함과 충실함은 다르다**
  - 설명을 많이 붙일수록 실제 판단과 어긋난 설명이 섞일 여지도 커짐 — 어긋난 설명은 잘못된 확신(false confidence)을 만듦
  - 참값이 없어 설명이 "옳다"는 보장은 불가 → 설계로 보장할 수 있는 것은 "설명이 실제 판단 근거와 일치한다"(fidelity, 충실도)

### 2. 문제점

- **설명의 정답이 없어 사후 채점 불가**: 설명이 "맞는지" 잴 외부 참값이 없음(운동 임계의 실험실 측정 부재) → 충실도를 사후 검증이 아니라 **구조로 보장**해야 함
- **plausible-but-wrong 위험**: 심박처럼 사용자 눈에 보이는 값에서 설명이 어긋나면 신뢰가 즉시 붕괴 → 설명과 실제 판단 근거의 일치가 필수
- **개인화로 판단 기준이 계속 변화**: 경계가 매 세션 갱신됨 → 설명이 그 변화를 따라가며 여전히 충실해야 함
- **약한 온디바이스 LLM의 개입 위험**: LLM이 설명 생성에 끼면 그럴듯한 거짓을 지어낼 수 있음 → LLM의 역할 한정 필요

## 슬라이드 3 — DP1. 설계결정 및 근거

### 1. 최종 채택 구조

**후보 1: 규칙/통계 기반 개인화 아키텍처 채택** (설계에 의한 설명 intrinsic + 수치 출처 추적 provenance + LLM=verbalizer)

### 2. 채택 근거

- **품질 속성(충실도)**: 판단이 투명해 설명이 실제 근거와 어긋날 여지가 작음 — 고위험/신뢰 결정에는 해석가능 모델을 쓰라는 문헌 처방(Rudin 2019, Nature MI)과 일치
- **제어가능성**: 판단의 기준(말하기 테스트 라벨)이 사용자 입력이라 "그건 내 답과 다르다"로 직접 정정 가능(HITL)
- **과제 조건 부합**: 2안의 강점(적응/정확 잠재)은 대량 데이터 + 참값을 전제하나 본 과제에는 둘 다 없음. 입력이 저차원 의미 특징(심박/페이스/케이던스/경사)이라 해석가능 모델의 정확도 손해도 작음(Rashomon)
- **운영 효율성**: 설명 = 이미 계산한 값의 표시라 추가 연산 거의 0, 온디바이스/비용 0 제약 충족(2안은 특징기여도 재평가/상시 LLM 부하)
- **확장성**: 참값 확보 또는 고차원 신호 확장 시 2안(사후 설명 병행) 통합으로 점진적 고급화 가능

### 3. 보완 계획

- Trade-off 분석 결과를 바탕으로,
- **단기**: 기존 러닝 앱 설명 기능 벤치마킹(대비 우위 주장은 검증 후에만) + 설명 사용자 평가(이해도/신뢰 측정)로 단계적 설명 개선 + LLM 표현 왜곡을 출력 가드레일 기각 기록으로 모니터링
- **장기**: 말하기 테스트 정정(HITL)을 정확성 교정 장치로 강화(intrinsic은 충실 보장이지 옳음 보장이 아님을 보완)

## Appendix 슬라이드 — DP1 상세 설계 내역

- **문제점-품질 매핑(P1~P7)**: 이해 실패(설명용이성) / false confidence(충실도) / 참값 없음(구조로 보장) / 지속 적응(기능적응성) / 정정 가능(제어가능성, HITL) / 온디바이스 매초 비용0(수행효율성) / LLM 환각(제어가능성, 강건성)
- **QA 별점 종합(관련 6축)**: 설명용이성 5:2, 제어가능성 5:2, 강건성 4:2, 수행효율성 5:2, 기능적응성 3:4, 기능정확성 4:3(잠재, 미검증) — 결정축 = 충실도
- **조건 의존성(공정한 평가)**: 본 별점은 이 과제 조건(온디바이스/참값 없음/저차원 의미 특징/정체성 QA=설명용이성)에 대한 평가. 조건이 다르면(고차원 원신호, 참값 확보 가능, 정확도 최우선) 2안이 우선될 수 있음
- **예상 질문**: SHAP/LIME 부착? — 원모델의 근사라 충실도 미보장 + 섭동 불안정 + 연산 부담 / LLM 전담 설명? — 사후 이유생성(rationalize)은 지어낼 위험, 본 설계는 LLM을 verbalizer(확정 사실의 표현)로만 한정
- **근거 문헌**: Rudin(2019) Nature MI / XAI 충실도 문헌(Faithfulness vs Plausibility, Assessing Fidelity) / 웨어러블 XAI 체계적 리뷰(JMIR 2024, post-hoc 88%) / DARPA XAI
