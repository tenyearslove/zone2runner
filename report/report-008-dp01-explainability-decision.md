## 슬라이드 1 — DP-01 개요: 설계 문제 한 문장

**"코칭 AI의 판정/경계/코칭을 — 참값도 대량 데이터도 없이, 폰 혼자, 사용자가 믿고 정정할 수 있게 — *그럴듯함이 아니라 충실함(진짜 이유대로)* 으로 설명하는 내부 구조를 무엇으로 할 것인가."**

- 이 시스템은 사용자가 **믿고 그대로 행동해야 하는** 결정을 낸다: "지금 존 초과", "당신의 Zone 2 상한은 여기", "속도를 낮춰요"
- 정체성 품질 = **설명용이성**(AI 8대 QA): 판단마다 "왜"가 붙어야 한다
- 함정: *그럴듯하지만 틀린 설명*은 없는 것보다 나쁘다(false confidence) → 진짜 요구는 "설명이 있냐"가 아니라 **"설명이 충실하냐(fidelity)"**

---

## 슬라이드 2 — 설계 문제 정의: 왜 어려운가

| 난점 | 내용 |
|---|---|
| **참값 없음** | 설명이 "맞는지" 잴 외부 정답이 없다(운동 임계의 실험실 참값 부재) → 충실도를 사후 채점할 수 없고 **구조로 보장**해야 |
| **그럴듯함과 충실함은 다르다** | 사람은 매끄러운 설명이면 믿는다 → plausible-but-wrong이 가장 위험. 심박처럼 눈에 보이는 값에서 어긋나면 신뢰 즉시 붕괴 |
| **계속 바뀜(적응)** | 경계가 개인화로 매 세션 갱신 → 설명이 그 변화를 따라가며 여전히 충실해야 |

**결론 구도**: 설명을 "결정과 분리된 사후 모듈"로 만들면 그 설명은 원 결정의 **근사**가 된다. 결정 과정 자체를 **투명한 규칙/통계**로 설계하면 판단 근거를 그대로 따라갈 수 있다(traceable).

## 슬라이드 3 — 문제점과 품질 요구의 연결 (P1~P7)

| # | 문제 | 걸리는 품질(AI 8대 QA)/제약 |
|---|---|---|
| P1 | 사용자가 이해 못 하면 코칭을 안 따른다 | 설명용이성(정체성 QA) |
| P2 | 그럴듯하지만 틀린 설명 = false confidence | 설명용이성 심화 = **충실도** |
| P3 | 설명의 정답이 없어 사후 채점 불가 | 제약: 참값 없음 → 구조로 보장 |
| P4 | 판정/경계가 개인화로 계속 바뀐다 | 기능적응성 |
| P5 | 사용자가 설명을 보고 정정할 수 있어야 | 제어가능성(HITL) |
| P6 | 폰 단독, 매초 동작, 운영 비용 0 | 제약: 온디바이스 + 수행효율성 |
| P7 | 약한 LLM이 설명에 끼면 그럴듯한 거짓 생성 위험 | 제어가능성/강건성 |

## 슬라이드 4 — 두 설계안을 공정하게 비교하는 틀

- **바깥 경계(입출력)를 동일하게 고정**하고 안쪽 구조만 비교
  - 입력: 관측 신호(1Hz 심박/페이스/케이던스/경사) + 시스템 결정(판정/경계/코칭)
  - 출력: (1) 결정의 설명 (2) 각 수치의 출처 (3) 사용자 정정 지점(HITL 라벨)
- 다이어그램 공통 표기: 블록 상단 «...» = AI System 아키텍처 컴포넌트 유형(가드레일/모델 서빙/설명 서비스/Retraining), 색 = 컴포넌트 성격, 실선 = 데이터, 점선 = 제어
- QA 평가는 그림이 아니라 **결정 표의 장점/단점 칸**에서(별점)

## 슬라이드 5 — (1안) 규칙/통계 기반 개인화 아키텍처 — 설계에 의한 설명(intrinsic)

(그림: `arch/diagrams/02b-component-cnc-simple.png`)

- **한 줄**: 결정을 투명한 규칙/통계로 내려 **판단 근거가 추적 가능** — 판정은 규칙, 경계는 베이지안(사전값+불확실도), 각 수치는 출처(관측/학습/설계) 구분
- **설명 방식**: 별도 추정 없이, **추론이 실제로 쓴 값과 규칙을 그대로 보여준다**
  - 예: "지속심박 128이 하한 132보다 낮아 미달 — 그런데 내리막+관절주의라 관절 보호를 우선했어요"
- **LLM의 자리**: 결정에 관여하지 않음. 규칙이 확정한 사실을 **말로만 옮김(verbalizer)** + 출력 가드레일/템플릿 폴백 → LLM 환각이 설명을 오염 못 함(P7)
- **근거 문헌**: Rudin(2019, Nature MI) "고위험 결정에는 블랙박스 사후 설명 대신 해석가능 모델" / 저차원 의미 특징에서는 정확도-해석가능성 트레이드오프가 대체로 성립하지 않음(Rashomon)
- **정직한 한계**: intrinsic = "설명이 모델과 일치" 보장이지 "모델이 옳음" 보장 아님 → 사용자 정정(HITL)으로 교정. 투명 구조라 복잡한 비선형 표현력엔 상한

---

## 슬라이드 6 — (2안) 사전학습 블랙박스 아키텍처 — 사후 설명(post-hoc)

(그림: `arch/dp/dp-01-explainability/images/dp-01-explainability-counter-simple.png`)

- **한 줄**: 오프라인 대량 학습한 모델이 결정을 직접 산출하고, 설명은 결정 후 별도 생성(특징기여도 SHAP/LIME 또는 LLM 이유생성)
- 산업계 주류 접근(웨어러블 데이터 XAI 연구의 88%가 post-hoc) — **동등하게 진지한 대안**
- 핵심 구성: 오프라인 학습 파이프라인(데이터셋 구축 - Data Lake - Model Construction - 테스팅 - Model Registry - 배포)
- **비용**: 설명이 원모델의 근사라 **충실도가 별도로 보장되지 않음**(모델 로직이 다수 파라미터에 분산). 결정 경로가 표면화되지 않아 사용자가 무엇을 정정할지 짚기 어려움. 특징기여도는 다중 재평가, LLM 이유생성은 상시 호출 부하
- **이 안이 우선되는 조건**: 고차원 원신호(이미지/음성 등), 검증할 참값 확보 가능, 정확도 최우선 문제

## 슬라이드 7 — 설계안 결정 표

| | **(1안) 규칙/통계 기반 개인화 (채택)** | (2안) 사전학습 블랙박스 |
|---|---|---|
| 설명 방식 | 설계에 의한 설명(intrinsic) — 근거 추적 가능 | 사후 설명(post-hoc) — 근거 추정 |
| 장점 | 설명용이성 ★★★★★<br/>제어가능성 ★★★★★ | 기능적응성 ★★★★ 잠재(복잡한 패턴 학습)<br/>기능정확성 ★★★ 잠재(고차원 신호에 강함) |
| 단점 | 기능적응성 ★★★(투명 구조 내 표현력 상한)<br/>기능정확성 ★★★★(절대 정확도 미검증 — 참값 없음, 양안 공통) | 설명용이성 ★★(사후 근사, 충실도 보장 어려움)<br/>제어가능성 ★★(결정 경로 비표면화) |
| Trade Off | 판단이 투명해 근거 추적 가능 — 설명이 실제와 어긋날 여지 작음<br/>수치 출처 구분(관측/학습/설계) + 사용자 정정(HITL)<br/>사후 계산 불필요 → 폰에서 가벼움 | 복잡한 비선형까지 배울 잠재력, 고차원 신호에 강함<br/>단 그 잠재는 참값/대상 대역 데이터가 없는 이 조건에선 확인 어려움<br/>설명이 근사라 안전/정정을 별도 보강 필요 |

## 슬라이드 8 — QA 별점 종합과 결정축

| QA(AI 8대) | (1안) intrinsic + provenance | (2안) 블랙박스 + post-hoc |
|---|:---:|:---:|
| 설명용이성 (정체성) | ★★★★★ | ★★ |
| 제어가능성 | ★★★★★ | ★★ |
| 강건성 | ★★★★ | ★★ |
| 수행효율성 | ★★★★★ | ★★ |
| 기능적응성 | ★★★ | ★★★★ |
| 기능정확성 | ★★★★ | ★★★ (잠재, 미검증) |

- **결정축 = 충실도(fidelity)**: 사용자가 *행동해야 하는* 코치에서는 설명이 실제 이유와 일치하는지가 핵심. 정체성 QA가 설명용이성인 이 시스템에서 이 축의 가중치가 크다
- **조건 의존성(공정성)**: 이 별점은 *이 시스템의 조건*(온디바이스/참값 없음/저차원 의미 특징)에 대한 평가 — 조건이 다르면(고차원 원신호, 참값 확보 가능) 2안이 앞설 수 있다

## 슬라이드 9 — 설계 결정 및 근거

**결정: (1안) 규칙/통계 기반 개인화 아키텍처 채택** — intrinsic + provenance + LLM=verbalizer

1. **충실도 우위**: 판단이 투명해 근거가 추적 가능 → 그럴듯하나 틀린 설명의 여지가 작음(Rudin 2019의 고위험 처방과 일치)
2. **제어가능성**: 라벨원이 사용자 입력(말하기 테스트)이라 "그건 내 답과 다르다"로 직접 정정(HITL)
3. **조건 부합**: 2안의 강점(적응/정확 잠재)은 "충분한 데이터 + 참값"을 전제하는데 이 시스템에는 둘 다 없음. 저차원 의미 특징이라 정확도 손해도 작음
4. **수행효율성**: 설명 = 이미 계산한 값의 표시라 추가 연산 거의 0 (2안은 사후 설명 상시 부하)

**예상 질문 대비**
- "SHAP/LIME 붙이면 되잖아?" → 원모델의 근사라 충실도 미보장 + 섭동 불안정 + 연산 무거움
- "LLM한테 다 설명시키면?" → 사후 이유생성(rationalize)은 지어낼 위험. 이 설계는 LLM을 verbalizer(확정 사실의 표현)로만 한정 — 이 구분이 DP의 핵심

## 슬라이드 10 — 보완 계획과 근거 문헌

**보완 계획**
- 설명 서비스 **사용자 평가**: 실사용자 이해도/신뢰 측정으로 단계적 설명(layered explanation) 개선
- **모델 정확성 교정**: intrinsic은 충실 보장이지 옳음 보장이 아님 → 말하기 테스트 정정(HITL)을 정확성 교정 장치로 강화
- **LLM 표현 왜곡 모니터링**: verbalizer의 왜곡을 출력 가드레일 기각 기록으로 추적(폴백 사유/기각 횟수가 세션마다 저장됨)

**근거 문헌(요지)**
- Rudin (2019) Nature Machine Intelligence — 고위험 결정엔 해석가능 모델
- Faithfulness vs Plausibility / Assessing Fidelity (XAI 충실도 문헌)
- 웨어러블 데이터 XAI 체계적 리뷰 (JMIR 2024) — post-hoc 88%, 충실도 검증 부족
- DARPA XAI "appropriately trust", provenance/lineage as trust
