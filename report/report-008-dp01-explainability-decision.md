## 슬라이드 1 — DP1. 설계 문제 정의

### 1. 배경

- 이 앱은 심박을 보며 달리기를 실시간으로 코칭한다 — "지금 존을 벗어났어요", "속도를 조금 낮춰볼까요".
- 핵심 품질은 **설명용이성**이다. 모든 판정과 코칭의 근거를 남겨 리포트에서 확인할 수 있게 하고, 판정이 몸 상태와 다르다고 느끼면 말하기 테스트 답으로 판정 기준을 바로잡을 수 있게 한다.
- 설명은 풍부할수록 좋다. 단, **앱이 실제로 판단한 근거를 그대로 보여줘야지, 그럴듯하게 지어낸 이유를 보여줘서는 안 된다.** 이를 지키는 구조를 고르는 것이 이 설계 결정이다.

### 2. 문제점

- **정답지가 없다.** 진짜 Zone 2인지는 실험실에서나 잴 수 있으니, 설명이 맞았는지 나중에 채점할 수 없다.
- **그래서 틀린 설명이 처음부터 만들어질 수 없는 구조가 필요하다.** 설명 기능이 아니라 판단 구조를 고르는 문제가 되는 이유다.
- **판단 기준이 계속 바뀐다.** 개인 경계는 러닝마다 갱신되고, 설명은 늘 그 최신 값을 보여줘야 한다.
- **작은 LLM은 그럴듯한 말을 지어낼 수 있다.** 설명을 통째로 맡기지 말고 역할을 제한해야 한다.

| **Trade Off** | 판단 근거를 언제든 따라가 볼 수 있고 정정이 바로 반영된다. 대신 규칙 밖의 복잡한 패턴은 배우지 못한다 | 데이터가 많으면 더 복잡한 것까지 배울 수 있다. 대신 왜 그렇게 판단했는지 보여주기 어렵고, 정답지가 없는 이 조건에서는 그 잠재력을 확인할 방법도 없다 |

## 슬라이드 3 — DP1. 설계결정 및 근거

### 1. 최종 채택 구조

**후보 1: 규칙/통계 기반 개인화 아키텍처 채택**

### 2. 채택 근거

- **설명이 곧 판단 근거다(설명용이성).** 이 앱은 설명을 따로 지어내지 않는다. "심박 145가 상한 132를 넘었다"처럼 판정에 실제로 쓴 숫자와 규칙을 그대로 보여주는 것이 설명이다. 그래서 설명과 실제 판단이 어긋날 수 없다. 코칭 문장마다 그 근거 숫자와 생성 과정이 기록되어, 리포트에서 문장을 눌러 다시 확인할 수 있다.
- **사용자의 정정이 바로 반영된다(제어가능성).** 러닝 중 "그건 내 느낌과 달라"라고 답하면(말하기 테스트) 그 자리에서 개인 경계가 움직이고, 얼마나 움직였는지 화면에 보인다. 2안은 이런 정정을 모아 모델을 다시 학습해야 반영되고, 제대로 반영됐는지 확인하기도 어렵다.
- **이 과제의 조건에 맞는다.** 2안의 장점은 학습 데이터와 정답이 충분할 때 나오는데, 이 과제에는 그 둘이 다 없다(제약 C02·C03). 게다가 입력이 심박·페이스처럼 뜻이 분명한 소수의 신호라, 투명한 모델을 써도 정확도 손해가 크지 않다(Rudin 2019).
- **추가 연산이 거의 없다.** 설명은 이미 계산해 둔 값을 그대로 보여주는 것이라 별도 연산이 들지 않아, 폰에서 실시간으로 무리 없이 돌아간다.

### 3. 보완 계획

- **단기**: 시중 러닝 앱(가민·스트라바 등)이 코칭 근거를 어디까지, 어떤 형태로 보여주는지 조사해, 우리 설명의 상세도와 표현 형식을 다듬는 기준으로 삼는다. 실사용자에게 설명이 실제로 이해되는지 평가해 어려운 용어를 고친다. LLM 문장이 검사에서 기각된 기록을 모아 어떤 표현이 자주 걸리는지 분석하고 프롬프트를 교정한다.
- **장기**: 설명이 판단과 일치해도 판단 자체는 틀릴 수 있다(참값이 없어 절대 정확도는 검증 불가). 이를 말하기 테스트로 메우되 — 질문을 심박이 안정된 구간에서만 던지고, 응답의 일관성에 따라 경계 갱신 폭을 가중해 — 사용자 라벨의 신뢰도를 끌어올린다.

## Appendix 슬라이드 — DP1 상세 설계 내역

**문제점이 걸리는 품질 속성**

- 사용자가 설명을 이해하지 못하면 코칭에 대한 신뢰가 떨어진다 → 설명용이성
- 설명이 지어낸 이유여서는 안 된다 → 설명용이성(심화)
- 정답지가 없어 사후 채점이 불가능하다 → 구조 선택으로 대응
- 개인 경계가 계속 갱신된다 → 기능적응성
- 사용자가 정정할 수 있어야 한다 → 제어가능성
- 폰 혼자, 추가 비용 없이 돌아야 한다 → 수행효율성
- 소형 LLM이 말을 지어낼 수 있다 → 제어가능성, 강건성

**채택안 상세 설계 — 추상 블록을 하위 모듈(실제 클래스)까지 전개**

![DP1 채택안 상세 — 하위 모듈 전개](../arch/dp/dp-01-explainability/images/dp-01-explainability-detail.png)

| 단계 | 하는 일 |
|---|---|
| 1. 사실 확정 | 규칙/통계가 판정과 근거 숫자를 확정한다 — 설명의 재료는 전부 여기서 나온다 |
| 2. 근거 기록 | 각 수치의 출처(관측/학습/설계)와 코칭의 근거 관측이 그 자리에서 기록된다 |
| 3. 표현 한정 | LLM은 확정된 사실을 문장으로 바꾸는 일만 한다 — 이유를 지어내지 않는다 |
| 4. 표현 검사 | 나가는 문장의 형식, 방향, 숫자를 규칙이 다시 검사한다 |
| 5. 추적 열람 | 리포트에서 문장을 누르면 근거 관측과 생성 과정을 그대로 볼 수 있다 |

**QA 별점 종합**

| 품질 속성 | (1안) 규칙/통계 기반 개인화 | (2안) 사전학습 블랙박스 |
|---|:---:|:---:|
| 설명용이성 | ★★★★★ | ★★ |
| 제어가능성 | ★★★★★ | ★★ |
| 강건성 | ★★★★ | ★★ |
| 수행효율성 | ★★★★★ | ★★ |
| 기능적응성 | ★★★ | ★★★★ |
| 기능정확성 | ★★★★ | ★★★ (잠재, 미검증) |

**평가의 조건**: 별점은 이 DP의 결정 범위가 해당 QA에 미치는 영향을 이 과제 조건에서 평가한 것이라, 같은 QA 명칭이라도 DP마다 평가 대상 행위가 다르다(예: DP1의 기능적응성=규칙 밖 패턴 학습 능력, DP3의 기능적응성=경계 적응 지연). 이 별점은 폰 단독, 정답지 없음, 소수의 분명한 신호라는 이 과제 조건에서의 평가다. 조건이 다르면(복잡한 신호, 정답 확보 가능) 2안이 나을 수 있다. 덧붙여 2안은 이 과제의 제약(C02 대량 데이터 확보 불가)과 정면 충돌한다 — 이 비교는 제약이 결정을 만든 사례를 보이는 비교이기도 하다.

**예상 질문**

- "사후 설명 도구(SHAP, LIME)를 붙이면 2안도 설명되지 않나?" → 그 설명은 모델 밖에서 추정한 근사라서 실제 판단과 같다는 보장이 없고, 계산도 무겁다.
- "LLM에게 설명을 다 시키면 되지 않나?" → 자기가 내리지 않은 판단의 이유를 지어낼 위험이 있다. 이 설계에서 LLM은 이미 정해진 내용을 문장으로 바꾸는 일만 한다.

**용어 대조(심사용)**: 1안의 설명 방식 = intrinsic interpretability(모델 자체가 해석 가능) / 2안의 설명 방식 = post-hoc explanation(사후 설명) / 설명과 실제 판단의 일치 = fidelity(충실도) / 값의 출처 추적 = provenance, data lineage

**근거 문헌**: Rudin(2019, Nature Machine Intelligence) — 신뢰가 필요한 결정에는 해석 가능한 모델을 쓰라 / XAI 충실도 문헌(2024, 상세 서지는 설계문서 부록 A) / 웨어러블 XAI 체계적 리뷰(JMIR 2024, 사후 설명이 88%) / DARPA XAI 프로그램
