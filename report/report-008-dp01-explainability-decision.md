## 슬라이드 1 — DP1. 설계 문제 정의

### 1. 배경

- **이 앱이 하는 일**: 심박을 보며 달리기를 실시간으로 코칭한다 — "지금 존을 벗어났어요", "속도를 조금 낮춰볼까요"
- **가장 중요하게 삼는 품질 = 설명용이성**: 판정/경계/코칭마다 "왜 그런지"를 함께 보여준다. 사용자는 설명을 보고, 자기 몸의 느낌과 다르면 바로잡을 수 있다
- **설계에서 어려운 점**: 설명은 실제 판단과 달라서는 안 된다. 설명을 많이 보여줄수록, 실제 판단과 다른 설명이 섞여 나갈 위험도 같이 커진다

### 2. 문제점

- **정답지가 없다**: 지금이 진짜 Zone 2인지는 실험실 장비로나 잴 수 있어서, 앱에는 정답이 없다. 그래서 "이 설명이 맞았나"를 나중에 채점할 방법이 없다
- **검사할 수 없으면, 애초에 틀리게 만들 수 없어야 한다**: 설명을 나중에 검사할 수 없으니, 실제 판단과 다른 설명이 아예 만들어질 수 없는 쪽으로 구조를 골라야 한다
- **판단 기준이 계속 바뀐다**: 개인 Zone 2 경계는 러닝할 때마다 조금씩 갱신된다. 설명도 항상 그 최신 기준을 따라와야 한다
- **작은 LLM이 지어낼 위험**: 폰에서 도는 소형 LLM에게 설명을 통째로 맡기면 그럴듯한 말을 지어낼 수 있다. LLM의 역할을 제한해야 한다

## 슬라이드 3 — DP1. 설계결정 및 근거

### 1. 최종 채택 구조

**후보 1: 규칙/통계 기반 개인화 아키텍처 채택**

### 2. 채택 근거

- **설명이 어긋날 틈이 없다**: 설명은 판단에 실제로 쓴 숫자와 규칙을 그대로 보여주는 것이다. 지어낸 설명이 나갈 수 없고, 코칭 문장마다 그 순간의 근거 수치와 생성 과정이 기록돼 나중에도 문장 단위로 확인할 수 있다
- **사용자 정정이 살아 있다**: "그건 내 느낌과 달라"(말하기 테스트)가 그 자리에서 개인 경계에 반영되고, 얼마나 바뀌었는지 화면에서 바로 확인된다. 2안은 정정을 모아 모델을 다시 학습해야 반영되고, 제대로 반영됐는지 확인하기도 어렵다
- **이 과제의 조건에 맞다**: 2안의 강점은 많은 데이터와 정답지를 전제로 하는데, 이 과제에는 둘 다 없다. 입력도 심박/페이스/케이던스/경사처럼 뜻이 분명한 소수의 신호라, 투명한 모델을 써도 정확도 손해가 작다는 연구 결과가 있다(Rudin 2019)
- **폰에서 가볍다**: 설명을 따로 계산하는 것이 아니라 이미 있는 값을 보여주는 것이라 연산 부담이 거의 없다
- **확장 여지**: 나중에 정답 데이터를 확보하면 2안 요소를 더해 고도화하는 길도 열려 있다

### 3. 보완 계획

- **단기**: 기존 러닝 앱의 설명 기능 벤치마킹(비교 우위 주장은 조사 후에만) + 사용자 이해도/신뢰 평가로 설명 개선 + LLM 문장 검사에서 기각된 기록으로 표현 왜곡 모니터링
- **장기**: 말하기 테스트 정정을 판단 정확성 보완 장치로 강화(설명이 판단과 일치해도 판단 자체가 틀릴 수 있는 부분을 사용자 정정으로 메움)

## Appendix 슬라이드 — DP1 상세 설계 내역

- **문제점-품질 매핑**: 이해 못 하면 안 따름(설명용이성) / 설명과 판단의 일치(설명용이성 심화) / 정답지 없음(구조 선택으로 대응) / 판단 기준의 지속 변화(기능적응성) / 사용자 정정(제어가능성) / 폰 단독, 비용 0(수행효율성) / 소형 LLM의 지어냄 위험(제어가능성, 강건성)
- **QA 별점 종합(관련 6축, 1안:2안)**: 설명용이성 5:2, 제어가능성 5:2, 강건성 4:2, 수행효율성 5:2, 기능적응성 3:4, 기능정확성 4:3(잠재, 미검증)
- **평가의 조건**: 이 별점은 이 과제의 조건(폰 단독/정답지 없음/뜻이 분명한 소수 신호) 기준이다. 조건이 다르면 — 예를 들어 이미지처럼 복잡한 신호를 다루거나 정답 데이터를 확보할 수 있으면 — 2안이 더 나을 수 있다
- **예상 질문**: "사후 설명 도구(SHAP/LIME)를 붙이면 2안도 설명되지 않나?" — 그 설명은 모델 밖에서 추정한 근사라 실제 판단과 같다는 보장이 없고, 계산도 무겁다 / "LLM에게 설명을 다 시키면?" — 자기가 내리지 않은 판단의 이유를 지어낼 위험이 있다. 이 설계는 LLM을 "정해진 내용의 문장화"로만 쓴다
- **용어 대조(심사용)**: 1안의 설명 방식 = intrinsic interpretability(모델 자체가 해석 가능) / 2안의 설명 방식 = post-hoc explanation(사후 설명) / 설명과 실제 판단의 일치 = fidelity(충실도) / 값의 출처 추적 = provenance, data lineage
- **근거 문헌**: Rudin(2019) Nature MI — 신뢰가 필요한 결정에는 해석 가능한 모델 / XAI 충실도 문헌 / 웨어러블 XAI 체계적 리뷰(JMIR 2024, 사후 설명 88%) / DARPA XAI
