## 1. 검증 범위

이번 과제는 실제 달리기 성능이나 의료적 정확도를 인증하는 프로젝트가 아니다. 설계한 AI 구조가 정해 둔 QAS대로 동작하는지를 자동시험으로 확인한다.

따라서 검증 결과를 다음처럼 읽어야 한다.

- 확인한 것: 규칙, 가드, 개인화, 시뮬레이션이 설계대로 동작하는지
- 확인하지 않은 것: 실제 사람의 유산소 역치 정확도, 실제 센서 성능, 사용자 이해도, 실기기 전체 지연
- 판정 용어: 아래의 달성은 자동화된 구조 검증 범위에서의 달성을 뜻한다.

## 3. 공통 검증 방법

자동시험은 워치 대신 정해 둔 입력을 같은 로직에 넣는다.

1. 입력 값과 난수 시드를 고정한다.
2. 실제 앱과 같은 판정·개인화·코칭 로직을 실행한다.
3. QAS에서 미리 정한 합격 기준과 결과를 비교한다.
4. 결과를 pp/app/build/qa-measurements/에 텍스트로 남긴다.

이 방식의 장점은 같은 조건을 여러 번 재현할 수 있다는 것이다. 단점은 실제 사람과 실제 워치의 특성을 대신할 수 없다는 것이다.

## 4. QA별 상세 결과

### QA1. 설명용이성

#### 확인하려는 질문

LLM이 그럴듯하지만 근거에 없는 숫자를 만든 경우, 사용자에게 나가기 전에 막을 수 있는가?

#### 시험 조건

- 허용 사실: Zone 2, 현재 심박 148bpm, 경계 132~152bpm
- 잘못된 문장: 근거에 없는 160, 145, 5, 30, Zone 3을 포함한 문장 5개
- 정상 문장: 허용된 숫자만 쓰거나 숫자를 쓰지 않은 문장 3개
- 추가 확인: 코칭 문장과 근거 기록 저장, JSON 저장·복원

#### 결과

- 미등록 숫자 문장: 5개 중 5개 차단
- 사실 문장: 3개 중 3개 통과
- 근거 기록: 관련 저장·복원 시험 통과

#### 해석

설명이 시스템이 가진 숫자 사실에서 벗어나지 않게 하는 구조가 동작했다. 이 결과는 선언한 문장 집합에 대한 것이다. 설명이 누구에게나 쉽고 유용하다는 사용자 평가 결과는 아니다.

### QA2. 기능적응성

#### 확인하려는 질문

평균 공식값에서 시작한 개인 경계가 말하기 테스트 응답을 받으며 가상 러너의 경계로 가까워지고, 지나치게 흔들리지 않는가?

#### 시험 조건

- 참임계 5종: 135~147bpm
- 난수 시드 3종
- 전체 15개 사례
- 각 사례는 8세션을 이어서 실행
- 학습기는 가상 러너의 참임계를 직접 보지 않고 말하기 테스트 응답만 사용

#### 합격 기준

- 8세션 뒤 오차 3bpm 이하
- 5세션 안에 오차 3bpm 이하 도달
- 마지막 4세션 경계의 최대값과 최소값 차이 4bpm 이하
- 한 세션의 경계 이동 10bpm 이하

#### 결과

- 15개 사례 모두 1~2세션에 안착
- 8세션 뒤 최종 오차 0.20~0.77bpm
- 기준 사례의 마지막 4세션 경계 폭 3.04bpm
- 기준 사례의 세션당 최대 이동 9.97bpm

#### 해석

사용자 응답을 받아 개인화 값을 제한된 폭으로 갱신하는 구조가 목표를 만족했다. 이 수치는 가상 러너 안에서의 결과다. 실제 사람의 유산소 역치를 0.20~0.77bpm 오차로 찾았다는 뜻이 아니다.

오답 응답 10% 시험은 한 시드에서만 실행했고 정상 입력보다 오차가 작게 나왔다. 해석하기 어려우므로 본문 합격 근거에서는 제외한다.

### QA3. 제어가능성

#### 확인하려는 질문

LLM이 판정과 반대인 말을 하거나 아무 행동도 알려 주지 못할 때, 규칙이 문장을 막고 코칭을 이어 갈 수 있는가?

#### 시험 조건

- 판정 방향과 반대이거나 행동 지시가 없는 문장 10개
- 판정과 맞는 정상 문장 5개
- LLM 로딩 중, 실행 실패, 모델 없음 상황의 기본 문구 경로

#### 결과

- 위반 문장: 10개 중 10개 차단
- 정상 문장: 5개 중 5개 통과
- LLM을 사용할 수 없는 상황: 관련 기본 문구 시험 통과

#### 해석

LLM이 최종 판정 권한을 갖지 않고 규칙의 통제를 받는 구조가 동작했다. 10/10은 선언한 시험 집합의 결과이며, 모든 가능한 한국어 표현을 완벽하게 거른다는 뜻은 아니다.

### QA4. 강건성

#### 확인하려는 질문

이상한 심박값과 경계 부근의 작은 흔들림은 줄이면서, 실제로 크게 변한 심박은 빠르게 반영하는가?

#### 시험 조건

- 40~220bpm 밖의 이상치 50개
- 정상 범위 값 500개
- 경계 부근 정현파 2bpm과 백색 노이즈 표준편차 1.5bpm을 섞은 300초 입력
- 난수 시드 5종
- 실제 이동에 해당하는 +10bpm 입력

#### 결과

- 이상치: 50개 중 50개 차단
- 정상값: 500개 중 잘못 차단한 값 0개
- 경계 부근 판정 번복: 순간값 판정보다 67.1~74.7% 감소
- 실제 +10bpm 이동: 1틱 만에 전환

#### 해석

노이즈 번복을 줄이면서 실제 변화는 늦추지 않는 두 조건을 함께 만족했다. 이상치 시험은 정해 둔 범위 규칙의 회귀시험이며, 실제 워치 센서의 정확도 시험은 아니다.

## 5. 검증을 가능하게 한 설계

테스트가능성은 별도 AI QA가 아니라 네 QAS를 반복 검증하게 한 공통 기반이다.

- RunSource를 교체해 워치 없이 같은 파이프라인에 입력을 넣는다.
- 고정 시드를 사용해 같은 가상 세션을 다시 만든다.
- 참임계를 가진 가상 러너로 개인화의 수렴 과정을 관찰한다.
- 각 측정 결과를 텍스트 파일로 남긴다.

최근 전체 JVM 단위시험은 153개가 통과했다. 이 숫자는 제품 정확도를 뜻하지 않고, 자동 회귀 범위를 설명하는 참고 정보다.

## 6. 보조 성능 확인

수행효율성은 핵심 QA가 아니라 보조 제약이다. 60분 분량인 3600틱을 JVM에서 처리했을 때 로직 비용은 틱당 0.1ms 미만이었다. 이 결과는 워치 통신, 화면, TTS, 온디바이스 LLM을 포함하지 않는다.

따라서 이번 보고서에서는 로직이 1Hz 주기의 병목이 아님을 확인했다고만 쓴다. 워치 입력부터 음성 출력까지 5초 이내인지와 화면 멈춤이 없는지는 실기기 확인 항목으로 남긴다.

## 7. 최종 판정

QA1~QA4는 자동화된 구조 검증 범위에서 모두 합격 기준을 만족했다. 이 결과로 확인한 것은 QAS와 설계와 구현과 시험이 서로 연결되어 있다는 점이다.

실제 사용자 효과와 실제 생리 정확도는 확인하지 않았다. 이를 숨기지 않고 과제 범위 밖의 향후 확인 항목으로 분리한다.
