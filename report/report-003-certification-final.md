## 슬라이드 2 — 과제 배경과 문제 정의

**Zone 2의 생리학적 정의**: 단순 "심박 2구간"이 아니라 **1차 젖산역치(LT1/유산소 임계) 바로 아래**
강도다. 이 지점에서 미토콘드리아 호흡/지방 산화/젖산 제거가 최대(San Millán). 목표 = 개인 LT1에 강도 정렬.

**배경**: Zone 2 훈련은 지구력/대사 건강의 핵심으로 대중화됐지만,
"내 Zone 2가 몇 bpm인가"에는 **합의된 정답이 없다.**

| 통용 기준 | 35세/RHR58 기준 Zone 2 상한 | 문제 |
|------|:---:|------|
| %HRmax 60~70 (Garmin 기본 등) | 128 bpm | 안정심박(개인차) 무시 |
| Karvonen %HRR 60~70 | 145 bpm | 위와 17bpm 차이 |
| MAF 180-나이 | 145 bpm | 나이 외 개인차는 ±5 범주 보정뿐 |
| LT1/VT1 (생리학 정의) | 개인 실측 필요 | 랩 젖산/가스 검사 없이는 측정 불가 |

**→ 같은 사람에게 기준마다 최대 17bpm이 다르고, 참값(LT1)은 소비자 환경에서 측정 불가.**
게다가 같은 심박도 오르막/피로 누적(Cardiac Drift)/컨디션에 따라 의미가 달라진다.

**과제 정의**: 워치+폰만으로, (1) 개인의 경계를 데이터로 추정하고 (2) 다신호로 상태를 판정하며
(3) 실시간 음성으로 코칭하는 온디바이스 AI 시스템을 설계한다.

> 생리학 배경/추정 방법 리서치 전문은 `arch/zone2-physiology-and-estimation.md`.

경계 추정이 다소 틀려도 물리적으로 검증 가능하며, 사용자가 실제로 소비하는 출력이다.

## 슬라이드 5 — 설계 개요: 3개의 Architectural Decision

| DP | 설계 문제 | 결정 |
|:---:|------|------|
| DP1 | 정답 없는 개인별 Zone 2를 **무엇으로 판정**하는가 | 하이브리드: 규칙 가드 + **다변량 MLP**(실제 NN) + 개인 경계 정규화 |
| DP2 | 개인 데이터가 없을 때/쌓일 때 **경계를 어떻게 추정**하는가 | **프로필 factor prior + 온라인 Bayesian 적응** (학습 없는 학습) |
| DP3 | 코칭 문장 생성을 **어디서, 무엇으로** 하는가 | **온디바이스 LLM(Gemini Nano)** + 규칙 방향 잠금 + 출력 가드 |

전제 구조(DP0, adr-001): Watch=수집/표시, Phone=AI 판단 — 연산·모델·배터리 제약을 폰으로 몰아
워치는 얇게 유지. 이하 각 DP를 [문제 → 후보 비교 → 결정 근거 → 보완계획]으로 전개.

## 슬라이드 6 — DP1 ① 설계 문제: "정답이 없는 판정"

**문제**: FR3의 미달/유지/초과 판정. 단일 HR 임계값 비교는 세 가지 상황에서 체계적으로 오판한다.
1. **오르막**: HR은 부하를 15~40초 지연 추종 → 임계 비교가 뒷북 (QA1 위협)
2. **Cardiac Drift**: 같은 페이스여도 시간이 지나면 HR 상승 → 후반부 과대 판정 (QA1 위협)
3. **센서 노이즈/장착 불량**: 손목 HR 튐 → 판정 채터링 (QA2 위협)

즉 판정 함수는 (HR, HR변화율, 페이스, 케이던스, 디커플링, 경사)의 **비선형 다변량 함수**여야 한다.
동시에: 참 라벨이 없고(정답 없음), 온디바이스여야 하며(C01), 1인 1달 안에 검증까지 끝나야 한다.

## 슬라이드 7 — DP1 ② 후보 비교

| 기준 | A. 규칙 기반(임계+휴리스틱) | B. 순수 ML(시계열 분류) | C. 하이브리드(규칙+소형 MLP) ★채택 |
|------|:---:|:---:|:---:|
| QA1 다신호 오판 방지 | ★☆☆ 임계 근처 취약 | ★★★ | ★★★ |
| QA2 강건성 | ★★☆ 가드는 쉬움 | ★☆☆ 이상치에 취약 | ★★★ 가드가 앞단 |
| 라벨 문제 | 해당 없음 | ★☆☆ 실라벨 없음 | ★★☆ 시뮬레이터 라벨 |
| 콜드스타트 | ★★★ | ★☆☆ | ★★★ 규칙 폴백 |
| 설명가능성 | ★★★ | ★☆☆ | ★★☆ 특징이 물리량 |
| 온디바이스/일정 | ★★★ | ★☆☆ | ★★☆ |
| 교육요건(NN 설계·학습) | ✗ | ○ | ○ |

**A 기각**: 오르막/드리프트 규칙을 손으로 쌓으면 규칙 폭발 + 상호작용 처리 불가 → QA1 목표(95%) 미달 (검증: 규칙 방향 정확도 0.544).
**B 기각**: 라벨 없음 + 이상치 취약 + 콜드스타트 전무. 검토한 변형(HR 회귀+잔차 개인화, COMPARISON.md의 B안)도
단일 경계 비교 구조라 방향 정확도 0.899에 그침(동일 조건 A안 0.996).

## 슬라이드 8 — DP1 ③ 결정: 판정 스택과 "정답 없음"의 해법

**판정 스택** (각 층이 서로 다른 QA를 담당):
```
OutlierGuard(규칙)  →  FeatureExtractor(7특징)  →  MLP 분류기(3분류)  →  코칭
   QA2: 생리범위 밖 기각      물리량 정규화               QA1: 비선형 다변량        (규칙 폴백 상시 대기)
```
- **특징 7종**: 개인 경계 대비 HR 위치 2종(hr_norm_u/l — DP2의 경계로 정규화), dHR, 페이스, 케이던스, 디커플링(드리프트), 경사.
  → 개인화(DP2)와 판정(DP1)이 특징 정규화 지점에서 결합하는 구조.
- **라벨 부재의 해법**: 물리 기반 러닝 시뮬레이터(HR 지연 1차계 + 드리프트 + 지형 + 노이즈)가
  (특징 → 참 존 상태) 라벨을 생성. 150러너/40만 샘플 학습, 노이즈 증강으로 강건성 확보.
- **온디바이스 단순화(2단계)**:
  ① 모델 자체를 소형화 — MLP 7→32→16→3 (수천 파라미터, 시계열 모델 불채택: 특징에 시간정보를 요약해 넣음)
  ② 런타임 제거 — TFLite 대신 **가중치 JSON + 순수 Kotlin 순전파 ~60줄**(adr-011).
    의존성 0, 초기화 즉시, 모델 이식 정확성을 단위 테스트로 직접 검증(export 모델 로드 → 학습 지표 재현).

**검증**: 방향 정확도 규칙 0.544 → +MLP **0.802** → +개인화 **0.828**(내부 지표),
**QA1 코칭 방향 0.996 / QA2 이상치 기각 1.000** (목표 달성). 온디바이스 재현 일치.

**보완계획**: 실주행 필드 로그로 판정 채터링(존 전환 최소 체류) 평가, 히스테리시스 도입 여부 결정.

## 슬라이드 9 — DP2 ① 설계 문제: "데이터가 없는 개인화"

**문제**: FR1/FR5. 판정(DP1)은 "개인 경계 대비 HR 위치"를 입력받는다 — 그 경계는 어디서 오는가?
- 신규 사용자: 데이터 0 (C02). 그런데 첫 세션부터 판정은 해야 한다.
- 데이터가 쌓여도: 경계의 참값 라벨이 없다. 지도학습 불가.
- 한 사람의 세션은 수 회~수십 회 — per-user 대규모 학습 불가.

**요구**: 입력만으로 의미 있는 초기값 → 세션이 쌓일수록 개인 실측 쪽으로 적응 → 전 과정 온디바이스.

## 슬라이드 10 — DP2 ② 후보 비교 (적응 축)

| 기준 | A. 공식 고정(비적응) | B. 공식 prior + 온라인 Bayesian ★채택 | C. per-user 시계열 학습(LSTM 등) |
|------|:---:|:---:|:---:|
| QA3 적응성 | ✗ | ★★★ 세션 1회부터 갱신 | ★★☆ 데이터 충분 시 |
| 라벨 요구 | - | **불필요** (물리 관측: 디커플링 상승점) | 필요 (없음) |
| 콜드스타트 | ★★★ | ★★★ prior=공식 | ✗ |
| 온디바이스 | ★★★ | ★★★ 순수 산술(켤레 가우시안) | ★☆☆ |
| 설명가능성 | ★★★ | ★★★ μ·σ가 곧 상태 | ★☆☆ |
| 강건성 | - | ★★☆ clamp/다운웨이트 필요 | ★☆☆ |

**B 채택**: "학습 없는 학습" — 경사하강도 라벨도 없이, 사전분포(공식)와 물리 관측(디커플링이 상승하는
지속 HR = 유산소 임계 부근 증거)의 베이즈 결합으로 개인 경계를 추정. 불확실성(σ)이 명시적이라
"얼마나 믿을 만한 추정인가"를 시스템이 스스로 알고, UI/가드에 그대로 쓴다.

## 슬라이드 11 — DP2 ③ 후보 비교 (콜드스타트 축, adr-012)

적응이 있어도 **첫 1~5세션의 품질은 순전히 prior가 결정**한다. prior를 무엇으로 잡는가?

| 기준 | A. 공식 고정(전원 HRR 70%) | B. 단계형 factor 오프셋 ★채택 | C. 모집단 회귀/ML |
|------|:---:|:---:|:---:|
| 콜드스타트 정확도 | ★☆☆ 개인차 무시 | ★★☆ 체계적 편차 흡수 | ★★☆ 데이터 의존 |
| 근거 데이터 | 불요 | 불요(문헌 오프셋) | 공개셋+파생 라벨 필요 |
| 온디바이스/일정 | ★★★ | ★★★ 덧셈 | ★☆☆ |
| 설명가능성 | ★★★ | ★★★ **오프셋 표가 곧 설명** | ★☆☆ |
| 오입력 강건성 | - | ★★☆ σ0 확대+Bayesian 회복 | ★☆☆ |

**관측 채널(리서치 반영)**: 디커플링(임계추출 편향 위험)에 더해 **토크 테스트 자가관측**을 도입.
"편하게 말할 수 있는 마지막 강도 ≈ VT1(1차 환기역치)"라는 검증 연구에 근거한 무비용 독립 채널로,
러닝 중 편함/애매/벅참 3단계 입력을 개인 경계 관측으로 반영한다. 참값에 더 가까운 **DFA-α1(HRV)**
(RR 0.75 교차 = 유산소 임계, Rogers 2021)은 온디바이스 향후 관측 채널로 명시. `arch/zone2-physiology-and-estimation.md`.

**B 채택 — 리서치 기반 차별화 지점**: 사용자가 나이/키/몸무게/안정심박에 더해
**체형 5단계, 러닝 수준 5단계, 주간 빈도 5단계**를 탭 3번으로 입력하면:
- 문헌 근거 오프셋(훈련자 LT1 상향 75~80%HRmax, MAF ±5 범주 보정 선례, 비만군 보수 경계)으로 uFrac0 조정
- **이중 계상 제어**: RHR이 이미 체력 반영 → 오프셋 총합 clamp(-8~+6%p)
- **정직한 불확실성**: 극단 선택/BMI-체형 불일치/RHR 미입력(자동 추정) → σ0 확대 → Bayesian이 더 빨리 교정
- 안정심박을 모르면 러닝 수준/빈도로 모집단 추정(RHR-체력 역상관) — %HRmax로 갈아타지 않고 HRR 파이프라인 유지

## 슬라이드 12 — DP2 ④ 결정 구조와 검증

```
프로필 factor ──(오프셋 표+clamp)──▶ prior(μ0, σ0) ──▶ Bayesian 갱신 ◀── 세션 관측(디커플링)
                                          │                 │  (켤레 가우시안, 산술)
                                          ▼                 ▼
                              첫 세션부터 개인 근사 경계   세션마다 개인 실측으로 이동
                                          └────── 안전 가드: 세션 내 ±10bpm, 상한 ≤ HRR 80% ──────┘
```

**검증** (시뮬 모집단 300러너, `ml/prior_experiment.py`):

| 지표 | 고정 공식 | factor prior |
|------|---:|---:|
| 세션 0(관측 전) 경계 오차 | 4.34 bpm | **2.51 bpm (-42%)** |
| 오차 p90 | 8.85 bpm | **5.15 bpm** |
| 3bpm 도달 세션 수(관측 저품질) | 2.0 | **1.0** |

민감도: 매핑이 무가치(capture=0)여도 손해는 +0.08bpm(clamp 효과) — **downside가 구조적으로 제한**.
적응 자체는 기존 검증(관측 양호 시 오차 5→2bpm, σ 단조 감소 = QA3 메커니즘 실증) 유지.

**한계/보완계획(정직하게)**: 실관측(디커플링 임계추출)은 Conconi류 편향 존재 — 상한 부풀림을
실기기에서 관찰해 안전 가드(±10bpm, ≤80%HRR)로 봉쇄했고, 임계추출 개선(또는 한계 확정)은 향후 과제.
factor 오프셋 값 자체의 정밀 검증은 정답 부재로 불가 — 필드 로그 축적 후 데이터 기반 갱신 경로(C안으로 진화)를 열어둠.

## 슬라이드 14 — DP3 ③ 결정: 방향은 규칙이, 표현만 LLM이

**역할 분리 원칙(adr-002)**: 안전이 걸린 **방향(더 빨리/유지/천천히)은 규칙이 결정**하고,
LLM은 그 방향을 자연어로 **표현만** 한다. 실패/미가용 시 규칙 템플릿으로 폴백 — 코칭은 항상 나온다.

```
판정(DP1) ─▶ 의도 결정(규칙) ─▶ LLM 표현(방향을 프롬프트에 잠금) ─▶ 출력 가드 ─▶ TTS
                   │                    실패/미가용/기각 ▼                │
                   └────────────── 규칙 템플릿 폴백 ◀───────────────────┘
```

**출력 가드의 진화(실측 주도)**: 실기기 로그에서 "초과" 상황에 "힘내세요!"(무방향) 문장이 가드를
통과하는 것을 발견 → **방향 잠금 가드(DirectionGuard)** 추가: 역방향 명령어 기각 + 방향 표현 필수
(2단계 어휘 — 좁은 명령어로 모순 판정, 넓은 단서로 방향 확인). 실제 LLM 출력을 테스트 케이스로 사용.
프롬프트에도 방향 표현 포함을 강제 → 개선 후 실기기 세션에서 8/8 문장 방향 명시, 기각 0건.

**실기기 검증(Galaxy S26, Exynos)**: Gemini Nano AVAILABLE, warm 생성 실측 1.1~2.7초(중앙값 1.3초),
TTS까지 end-to-end 동작. 비동기 분리로 생성 중 판정 루프/렌더 무정지. 제약(포그라운드 전용,
ErrorCode 30)은 화면 유지 모드로 대응, 화면off 코칭은 규칙 TTS 폴백 경로로 보완 계획.

## 슬라이드 18 — 결론

**성과**
1. "정답 없는" 개인 Zone 2 문제를 **평가 지표 재정의(방향 정확성) + 라벨 생성(물리 시뮬레이터) +
   개인화(prior→적응)**의 3단 구조로 풀 수 있음을 설계와 수치로 입증.
2. AI 3종의 역할 분리 — 판정은 소형 NN(MLP), 경계는 Bayesian(산술), 표현은 LLM(가드 하) —
   각 기술을 "그 QA에 필요한 최소 형태"로 온디바이스에 단순화.
3. 설계 문서 체계(요구 → QA/ASR → DP/ADR 12건 → spec 13건 → 추적표)와 구현·실기기 검증의 왕복.

**향후 계획**: 실주행 필드 데이터 축적 → 임계추출 편향 개선(또는 한계 확정), factor 오프셋의
데이터 기반 갱신(C안 진화), 워치-폰 존 기준 통일, 화면off 코칭 폴백.

  factor 매핑을 "참 편차의 60%만 설명 + 매핑 오차 σ0.02 + clamp"로 보수적으로 모델링.
