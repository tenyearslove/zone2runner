## 0. 공통 프레임 — 모든 QA는 "6요소 QA 시나리오"로 정의된다

강의는 각 QA를 **ATAM/QAW식 6요소 시나리오**로 명세한다. spec-002의 각 QA는 이 표 형식으로 써야 한다.

| 요소 | 뜻 |
|------|-----|
| **Source** | 자극의 출처(사용자/센서/외부시스템/공격자/타이머/운영자 등) |
| **Stimulus** | 시스템에 가해지는 자극(설명요청/비정상데이터/제어명령/도메인변화 등) |
| **Artifact** | 자극을 받는 대상(AI 시스템 / AI 추론 엔진 / 특정 모듈) |
| **Environment** | 자극이 발생하는 상황(정상/과부하/악의적/자원부족/비정상 등) |
| **Response** | 시스템이 수행하는 대응 |
| **Measure** | 대응의 성공을 재는 정량 지표 |

## 1. 앱 유형별 중요 QA (강의 표, 10-우선순위 p6) — 우리 선택의 근거

| AI 응용 유형 | 강건성 | 프라이버시 | 공정성 | 기능적응성 | 제어가능성 | 설명용이성 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| 개인화/추천 AI | | O | O | O | | |
| 인지/지각 AI | O | | | O | O | |
| 생성형/대화형 AI | | O | O | | O | O |
| **예측/진단 분석 AI** | **O** | | | **O** | | **O** |
| **의사결정 최적화/에이전트 AI** | **O** | | | **O** | **O** | **O** |

- **우리 앱 유형 판정**: 심박 예측(ODE) + 유산소 진단(드리프트/디커플링) = **예측/진단 분석 AI**,
  실시간 코칭 결정 = **의사결정/에이전트 AI**. (개인화는 "추천 시스템"이 아니라 생리모델 파라미터 적응이라
  개인화/추천 AI 범주와는 다르다 — 그래서 프라이버시/공정성이 헤드라인이 아니다.)
- **두 유형의 중요 QA 합집합 = 강건성 ∪ 기능적응성 ∪ 제어가능성 ∪ 설명용이성 = 우리가 고른 AI 4개와 정확히 일치.**
  → QA 선정의 강력한 외부 근거. (report-007 §3에 반영)
- 프라이버시/공정성은 개인화/추천/생성형 유형에서 중요 — 우리 주 유형이 아니고, 단일 사용자/비수집이라 제외 정당.

## 2. QA Trade-off 쌍 (강의, 10-우선순위 p13) — 우리 ATAM 근거

- **품질강화 vs 수행효율성** → 우리: 온디바이스(비용0/오프라인)로 품질 확보, 수행효율성은 기기 종속 대가로 수용.
- **설명용이성 vs 기능정확성** → 우리: **설명 가능한 투명 모델(ODE/규칙)** 을 위해 블랙박스의 절대정확도 헤드라인을 포기. (정체성)
- **프라이버시 vs 기능정확성**, **공정성 vs 기능정확성** → 우리 맥락 해당 약함(단일 사용자).

## 3. 선정 QA 상세 (AI 4)

### 3-1. 설명용이성 (Explainability) ★정체성
- **정의(ISO/IEC TS 6254:2025, ISO 22989:2022)**: AI가 도출한 결과의 **이유와 타당성**을 인간이 납득 가능한 형태로
  표현하는 능력. "결정에 영향을 준 주요 요인을 인간이 이해할 수 있게 표현."
- **설명 유형(Mode)**: ① **인과적 설명**(왜 이 결과가 나왔나, 주요 영향요인) ② **인식적 설명**(모델이 무엇을 알/모르나,
  불확실성) ③ **정당성 설명**(정책/기준/표준에 비춰 타당한가).
- **평가 2축**:
  - **기술적 신뢰성**("이 설명을 믿어도 되나?") = 정합성, **충실성(Fidelity, 설명이 실제 모델동작과 일치)**, 재현성, 강건성.
  - **사용자 경험**("나에게 유용한가?") = 가독성, **시뮬레이션가능성(입력→결과를 사용자가 예측)**, **실행가능성(actionability)**.
  - + 설명수행효율성.
- **Measure 예**: 정보일치도 ≥90%, **동일입력 일치율 100%**, 인간예측정확도 ≥80%, 실행가능 개선조치 제시.
- **▶ 우리 매핑**: 인과적=예측 ODE 항목분해("추세 +X, 드리프트 +Y bpm"), 정당성=규칙판정 경계비교("138<상한140→유지"),
  충실성=규칙이 사실 확정→**지어낸 수치 0 = 동일입력 일치율 100%**, 시뮬레이션가능성=결정론 규칙, 실행가능성=코칭 조치,
  설명서비스(spec-023)=사후 세션스토리/개인화설명. **인식적 설명(불확실성 σ) 노출은 강화 여지.**

### 3-2. 기능적응성 (Functional Adaptability) ★정체성 — ⚠ 이전 이해 대폭 수정
- **정의**: 시스템이 **운영 도메인(Operational Domain) 변화**에 대응해 스스로를 적응시키는 능력. 핵심은 단순 "개인화"가
  아니라 **① 적응이 필요한 변화를 감지(식별) → ② 적응 수행 → ③ 적응 후 품질 회복 → ④ 안정화**의 루프.
- **유형(2축)**:
  - 적응 **원인**: 요소확장(Expansion, 새 대상/환경 추가) vs 요소변경(Change, 기존 지식이 오답이 됨).
  - 적응 **방식**: **확정적(Deterministic**, 사전정의 프로필 전환) vs **진화적(Evolutionary**, 관측으로 모델을 학습/쇄신).
- **평가지표**: Adaptation Need **Recall/Precision**(적응 필요를 놓치지도 오판하지도 않음), Adaptation **Success Rate**,
  Adaptation **Latency**, Resource Overhead, **Post-adaptation Quality Attainment**, **Quality Recovery Rate**,
  **Time to Stabilization**, **Stability Index**.
- **하위 품질(각 적응마다)**: 적응기능정확성(식별 정확), 적응기능효율성(제약 내 완료), 적응효용성(품질 회복), 적응안정성(진동 없음).
- **▶ 우리 매핑 & 재검토**: 온라인 Bayesian 경계 + ODE τ/드리프트 추정 = **진화적 적응(Evolutionary)**. 콜드스타트
  factor prior→개인값 = 요소변경 대응. **환경 변화(기온↑/피로→드리프트)에 상한 재조정 = 운영도메인 변화 적응.**
  - ⚠ **정직한 약점**: 강의는 "적응 필요 상황 감지(Recall/Precision)"를 요구하는데, 우리는 명시적 "적응 트리거 감지기"가
    약하다(연속 스무딩에 가까움). → 논의 필요: (a) 드리프트/컨디션 변화를 **적응트리거로 명시**해 감지-적응-안정 루프로
    재서술, or (b) 진화적 적응(연속 갱신)으로 정직하게 프레이밍하고 Recall/Precision 대신 수렴/안정 지표로 측정.
  - 측정 후보: 세션수 대비 **수렴오차 곡선**(Quality Recovery), **Time to Stabilization**(경계가 참임계에 안착하는 세션수),
    **Stability Index**(세션 간 경계 진동폭) — 폐루프 VirtualRunner로 정량 가능.

### 3-3. 제어가능성 (Controllability)
- **정의**: 제어 주체(인간/외부에이전트/상위앱)가 시스템에 개입해 **목적완수/안전/기술신뢰를 회복**하는 통제권.
- **제어기능 유형**: **교정(Correction**, 파라미터/모드 변경) / **보완(Compensation**, 수동개입/리셋/재할당) /
  **안전전환(Fail-safe**, 기능 중단하고 안전상태로 전이).
- **제어수준 2단계**: **AI Application 제어**(전체 응용, 주체=최종사용자/원격관제, 목적=비즈니스+물리안전) vs
  **AI 시스템 제어**(지능서비스 엔진, 주체=운영자/상위앱, 목적=추론/학습의 기술적 신뢰성).
- **가드레일이 제어 수단**: 강의 시나리오가 **입력 가드레일 / 서빙로직 / 출력 가드레일** 조정을 제어행위로 명시.
- **Measure**: **제어정확성**(예: 안전상태 전이 100% 성공), **제어효율성**(예: 명령→구동 지연 ≤200/500ms).
- **▶ 우리 매핑**: 교정=**토크테스트(사용자 개입)** + 설정(spec-021 코칭빈도/모드), 안전전환=**Nano 미가용→규칙 폴백(fail-safe)**
  + 물리/세션 clamp(폭주 억제), **출력 가드레일=DirectionGuard(규칙이 LLM 출력을 검열/기각)**. 제어수준: AI시스템 제어
  =규칙이 LLM/개인화 엔진을 통제. **← DirectionGuard는 강의 정의상 "출력 가드레일=제어"이므로 설명용이성이 아니라 여기 귀속(겹침 해소).**
  - 측정 후보: DirectionGuard 방향위반 기각율, 폴백 전환 지연, 세션 경계이동 ≤10bpm 보장률.

### 3-4. 강건성 (Robustness) — ⚠ 이전 "얇다" 판단 철회, 최강 적합
- **정의(ISO/IEC 25059:2023, 신뢰성의 하위특성)**: 다양한 악조건에서도 **기능정확성을 유지**하는 능력.
- **4대 위협/유형**: ① **입력 데이터**(Unseen/OOD, Biased, Adversarial, **Invalid**) ② 외부 간섭(신호왜곡/기만)
  ③ 외부 환경(일반화/복원력/신뢰성 저해) ④ 추론 컴퓨팅(로직/플랫폼).
- **Invalid 데이터 세부**(우리와 직결): 형식 무결성(schema/type/**range**), 신호품질/정보충분성(fidelity),
  개별 내부 일관성(피처 모순), **선후/시계열 일관성(Spike/Jump/Drift, 물리적 타당성)**.
- **평가지표**: 정확성기반 **Robustness Score**(정상 대비 유지율), **RCD**(상대적 정확도 저하율), 적대적기반 ASR,
  **안정성기반 Stability Index / Flicker Rate(인접 프레임 판정 레이블 번복 빈도)**.
- **Response**: 편향→정답추론, 무효→정답추론 or 입력차단, 적대적/OOD→입력차단(필터링).
- **테스트 설계**: 유형2/3을 유형1(입력데이터) 형태로 투영해 테스트. Invalid 기법: Range violation, Signal degradation,
  **Spike/Jump/Drift Injection**, Frame drop 등.
- **▶ 우리 매핑(교과서적 일치)**: 손목 광학HR/GPS = Invalid 입력(신호품질 저하, motion artifact, Spike).
  **OutlierGuard(40~220 range violation 차단) = Invalid 입력차단**, **히스테리시스 = Flicker Rate 억제(판정 번복 억제)**,
  **SlopeEstimator 창회귀 = 고주파 노이즈 Smoothing**, 예측/개인화 물리 clamp = Physical/Semantic Constraint.
  = 강의 아키텍처의 **입력 가드레일** 컴포넌트.
  - **참값부재(C04) 우회**: 강건성은 "clean 입력의 결정론 판정"을 기준(참값 역할)으로 두고 **노이즈 주입 시 판정 유지율/
    Flicker Rate**를 측정 → 랩 참값 없이도 폐루프로 정량 가능(테스트가능성과 결합). RCD/Robustness Score/Flicker Rate 측정.

## 4. 제외 QA (정의 + 제외 근거)

### 4-1. 기능정확성 (Functional Correctness) — 제외(사용자 확정)
- **정의**: 정상 환경/정상 분포 데이터에 대해 정확한 추론을 내는 **기본 지능**(강건성의 "유지" 대상). Task별 지표(mAP/Recall/RMSE 등).
- **제외 근거**: 개인 Zone2/LT1의 **참값이 소비자 환경에 없음(C04)** → 절대정확도 헤드라인은 "어떻게 검증?"에서 무너짐.
  강의 Trade-off "설명용이성 vs 기능정확성"에서 **설명용이성 쪽을 택함**(정체성). 결정론적 판정 정확성(모순불가)은 제어/강건성에 흡수.

### 4-2. 프라이버시 (Privacy) — 제외
- **정의**: 개인정보의 수집/처리/노출을 통제하고 최소화. (개인화/추천/생성형 AI에서 중요.)
- **제외 근거**: 우리 주 유형(예측/진단/에이전트)에서 헤드라인 아님. 온디바이스/비업로드(C9)로 데이터가 기기를 안 떠남은
  DP0 부수효과로 기록. 단일 사용자/비수집이라 보호대상도 적음. (주 동기는 비용/오프라인.)

### 4-3. 공정성 (Fairness) — 제외
- **정의**: 집단/속성 간 차별 없는 출력(개인화/추천/생성형에서 중요).
- **제외 근거**: **단일 사용자 개인화**라 집단 간 차별 이슈가 구조적으로 없음. 우리 유형의 중요 QA도 아님.

### 4-4. 수행효율성 (Performance Efficiency) — 제외
- **정의**: 시간/자원 대비 성능(지연/처리량/자원사용).
- **제외 근거**: 온디바이스는 "효율적"이라서가 아니라 **비용(C1)/오프라인(C4)** 때문. 오히려 성능이 기기에 종속(C6, 저가폰 미지원).
  강의 Trade-off "품질강화 vs 수행효율성"에서 품질 쪽. → QA 아닌 **DP0/제약(C1)** 으로 다룸.

## 5. 재검토 결론 — 내 이해가 바뀐 지점

| QA | 이전 내 이해 | 강의 상세로 교정된 이해 |
|----|------|------|
| **강건성** | "값 필터링뿐, 제일 얇다" | **최강 적합.** Flicker Rate/Stability Index/Robustness Score가 히스테리시스/OutlierGuard/창회귀와 직결, 폐루프로 측정. 입력 가드레일 컴포넌트. |
