# report-006 DP1 설계 보고서 — 가까운 미래 심박 예측 아키텍처

> 인증 보고서 "03. 설계 / Architectural Decision"의 DP1 파트. 샘플(씬스틸러) DP 슬라이드 형식을 따른다:
> [설계 문제 정의] → [후보 아키텍처 2안: 구조 블록다이어그램 + QA 별점] → [설계 결정 및 근거].
> 이 분야 지식이 전혀 없는 사람도 읽고 이해할 수 있도록 쓴다. 이번 문서는 **DP1 하나에만** 집중한다.

---

## 0. 읽기 전에 — 30초 배경 (도메인 지식 0 전제)

- **Zone 2 러닝** = "편하게 오래 달릴 수 있는 낮은 강도"의 유산소 운동. 이 강도를 유지하는지는 **심박수(분당 심장 박동)** 로 판단한다.
- **문제의 핵심**: 심박은 운동 강도를 **곧바로 따라오지 않는다.** 페이스를 올려도 심박은 **20~40초쯤 늦게** 서서히 오른다.
- 그래서 **"지금 심박"만 보고 코칭하면 항상 늦는다.** 이미 강도를 넘긴 뒤에야 "초과!"라고 말하게 된다.
- 제때 코칭하려면 **"이 페이스를 유지하면 곧(30/60초 뒤) 심박이 어디까지 갈지"를 미리 예측**해야 한다.
- **DP1 = 그 "미래 심박 예측"을 어떤 구조(아키텍처)로 만들 것인가** 라는 설계 결정이다.

---

## 1. DP1. 설계 문제 정의

### 1-1. 배경
- 심박은 강도 변화에 **지연 반응**한다(운동생리학의 심박 on-kinetics). 오르막에 들어서면 힘은 이미 넘쳤는데 심박은 뒤늦게 반영된다.
- 오래 뛰면 같은 페이스라도 심박이 서서히 오르는 **드리프트** 현상도 있다.
- 사용자는 "넘고 나서 혼나는" 게 아니라 **넘기 전에 미리** 안내받길 원한다(선제 코칭).

### 1-2. 해결할 문제
- **P1. 예측 정확도**: 늦게 반응하는 심박을 30/60초 앞서 맞혀야 한다.
- **P2. 데이터 부족**: 우리에겐 대규모 실측 심박 데이터가 없다(사실상 개인 몇십 세션 수준). 데이터를 많이 먹는 방법은 못 쓴다.
- **P3. 설명 가능성(신뢰)**: "왜 그렇게 예측했는지"를 사용자에게 보여줄 수 있어야 앱을 믿는다. 속을 모르는 예측은 신뢰를 잃는다.
- **P4. 온디바이스 실시간**: 폰에서 매초 돌아가야 한다(무거운 런타임 금지).
- **P5. 안전(무결성)**: 예측이 생리적으로 말이 안 되는 값(예: 순간 250bpm)을 내면 위험하다. 물리 경계를 벗어나면 안 된다.

> 즉 DP1은 "예측을 **어떤 내부 구조**로 만들면 P1~P5를 가장 잘 만족하는가"의 선택이다.

---

## 2. 후보 아키텍처 비교

두 후보를 **도구 이름이 아니라 내부 구조**로 제시한다. 각 구조가 무엇으로 이뤄졌고 데이터가 어떻게 흐르는지 블록다이어그램으로 보인다.

### 2-1. (1안) 블랙박스 신경망 회귀 구조

**한 줄 개념**: 입력 숫자들을 여러 층에 통과시켜 미래 심박을 통째로 예측하는 신경망. 층 안의 수많은 가중치를 데이터로 학습한다.

```
   입력 특징 7개                은닉층(학습된 가중치)             출력
 ┌──────────────┐        ┌──────────┐    ┌──────────┐    ┌───────────────┐
 │ 현재 심박    │──┐     │          │    │          │    │               │
 │ 심박 추세    │  ├────▶│  32칸    │───▶│  16칸    │───▶│ 60초 뒤 심박  │
 │ 유지할 페이스│  │     │  (ReLU)  │    │  (ReLU)  │    │ (숫자 하나)   │
 │ 경사/케이던스│  │     │          │    │          │    │               │
 │ 경과 시간    │──┘     └──────────┘    └──────────┘    └───────────────┘
 └──────────────┘             ▲
                              └─ 층 속 수백~수천 개 가중치를 "데이터"로 학습.
                                 왜 그 값이 나왔는지는 사람이 들여다볼 수 없다(블랙박스).
```

**쉬운 설명**: 요리 재료(입력)를 기계에 넣으면 결과 요리(예측)가 나오는데, **기계 내부가 불투명**해서 "왜 이 맛이 났는지" 설명이 안 된다. 그리고 이 기계를 제대로 학습시키려면 **재료-결과 예시가 수천~수만 개** 필요하다.

| 관점(QA) | 평가 | 이유 |
|---|:---:|---|
| 기능정확성(QA1) | ⭐⭐⭐ | 데이터가 충분하면 정확. 단 우리처럼 **시뮬 데이터로 학습하면 "시뮬을 흉내"낼 뿐**(순환), 실사람 정확도 아님 |
| 강건성(QA2) | ⭐⭐ | 물리를 모르므로 **생리적으로 말 안 되는 값**을 낼 수 있다 |
| 적응성(QA3) | ⭐⭐ | "평균 사용자" 고정 모델 — 개인화는 별도로 얹어야 |
| 효율성(QA4) | ⭐⭐⭐⭐ | 순전파는 가벼움(곱셈/덧셈) |
| 검증가능성(QA5) | ⭐⭐ | 정답 라벨을 시뮬이 만들면 **라벨 순환 결함** 위험(과거 판정 NN에서 실제로 겪음) |
| 설명용이성(QA6) | ⭐ | **속을 못 보여줌** → "왜 이 예측?"에 답 불가. 신뢰 확보 최대 난점 |

### 2-2. (2안) 생리 ODE + 잔차 신경망 하이브리드 구조 (gray-box / PINN)

**한 줄 개념**: 심박이 어떻게 움직이는지 **생리 공식(ODE)** 으로 뼈대를 잡고, 그 공식이 못 담는 나머지(잔차)만 **작은 신경망**이 물리 경계 안에서 보정한다.

```
                          ┌──────────────────────────────┐
 [현재 상태]              │  생리 ODE (물리 공식, 뼈대)   │
  현재 심박 ─────────────▶│  "심박은 목표를 향해 서서히   │──▶ 뼈대 예측
  심박 추세               │   접근(지연) + 드리프트"      │    (예측의 대부분)
  유지할 페이스           └──────────────────────────────┘        │
                                                                    ▼
 [상태 특징]         ┌───────────────┐    물리 경계 clamp     ┌──────────────────┐
  심박/경사/경과 ───▶│ 잔차 신경망   │──▶ (±안전 범위로 자름)─▶│  최종 예측        │
                     │ (작은 MLP)    │    ODE가 못 담은        │  = ODE + 잔차     │
                     └───────────────┘    "나머지 버릇"만 보정 └──────────────────┘
                            ▲
                            └─ 오프라인 학습(폰은 추론만). 물리(ODE)가 사실을 확정,
                               신경망은 그 경계 안에서만 손댐(무결성 원칙).
```

**쉬운 설명**: 일기예보 공식이 이 동네를 "항상 2도 낮게" 빗나간다면, 공식을 버리지 말고 **"이 동네는 +2도" 버릇만 따로** 배우면 된다. 여기서 **공식 = 생리 ODE(뼈대)**, **버릇 학습 = 작은 신경망(잔차)**. 뼈대가 대부분을 설명하니 신경망은 자투리만 배우면 되고, 그래서 **적은 데이터로도** 된다. 또 공식이 뼈대라 예측을 **"추세 몇, 드리프트 몇, 보정 몇"으로 쪼개 설명**할 수 있다.

| 관점(QA) | 평가 | 이유 |
|---|:---:|---|
| 기능정확성(QA1) | ⭐⭐⭐⭐ | 심박은 물리가 지배 → 공식이 정확/안정, 잔차 신경망이 추가 보강(시뮬 +10%) |
| 강건성(QA2) | ⭐⭐⭐⭐⭐ | 출력을 **물리 경계로 clamp** → 비생리적 값 원천 차단 |
| 적응성(QA3) | ⭐⭐⭐⭐ | 그 사람의 반응속도(τ)/드리프트를 **실주행에서 온라인 개인화** |
| 효율성(QA4) | ⭐⭐⭐⭐⭐ | 식 몇 줄 + 아주 작은 순전파 → 폰에서 초경량 |
| 검증가능성(QA5) | ⭐⭐⭐⭐ | 폐루프 시뮬로 τ가 참값에 수렴 확인, "분해 합 = 예측" 불변식 테스트 |
| 설명용이성(QA6) | ⭐⭐⭐⭐⭐ | 예측 = 추세 + 드리프트 + 보정으로 **항목 분해 표시** 가능(블랙박스는 불가) |

### 2-3. QA 별점 종합 비교

| QA(품질속성) | (1안) 블랙박스 신경망 | (2안) 생리 ODE + 잔차 NN |
|---|:---:|:---:|
| QA1 기능정확성 | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| QA2 강건성 | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| QA3 적응성 | ⭐⭐ | ⭐⭐⭐⭐ |
| QA4 효율성 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| QA5 검증가능성 | ⭐⭐ | ⭐⭐⭐⭐ |
| QA6 설명용이성 | ⭐ | ⭐⭐⭐⭐⭐ |

### 2-4. Trade-off

- **(1안) 블랙박스 신경망**: 표현력이 크고 학습 파이프라인이 단순하다. 그러나 **(a) 데이터를 많이 먹고**, **(b) 속이 불투명해 설명이 안 되며**, **(c) 물리를 몰라 안전 경계가 없고**, **(d) 시뮬로 학습 시 "시뮬 흉내"라는 순환**에 빠진다. 우리의 P2(데이터 부족)/P3(설명)/P5(안전)와 정면충돌.
- **(2안) 생리 ODE + 잔차 NN**: 투명하고(설명 가능) 안전하며(물리 경계) 적은 데이터로 되고 초경량이다. 대신 **설계에 손이 더 가고**(공식 + 학습 + 개인화 결합), 잔차 신경망 부분은 여전히 반쯤 불투명하다(그 크기는 clamp로 제한).

## 3. DP1. 설계 결정 및 근거

### 3-1. 최종 채택 구조
**(2안) 생리 ODE + 잔차 신경망 하이브리드 구조**를 채택한다.
(초기엔 1안 블랙박스 신경망을 시도했으나, 시뮬 데이터로 학습하면 "우리가 이미 쓴 공식을 흉내내는 순환"임을 확인하고 폐기 → 2안으로 재설계. adr-020, report-005.)

### 3-2. 채택 근거 (QA 기준)
- **설명용이성(QA6) 결정적 우위**: 예측을 "추세 몇 bpm + 드리프트 몇 bpm + 개인보정 몇 bpm"으로 **분해해 화면에 표시**할 수 있다. 블랙박스는 이 화면 자체가 불가능하다. 사용자 신뢰(P3)에 직결.
- **강건성(QA2)**: 출력을 물리 경계로 잘라 **비생리적 예측을 원천 차단**(P5).
- **데이터 현실(P2) 부합**: 뼈대(공식)가 대부분을 설명하니 신경망은 잔차만 학습 → **적은 데이터로 성립**.
- **효율성(QA4)**: 식 몇 줄 + 작은 순전파 → 온디바이스 실시간(P4).
- **검증가능성(QA5)**: 폐루프 시뮬에서 개인 파라미터가 참값으로 수렴하는 것을 정량 확인, 라벨 순환 결함 없음.
- **무결성 원칙 정합**: 물리/규칙이 사실을 확정하고 학습 요소(잔차 NN)는 그 경계 안에서만 움직인다(프로젝트 관통 원칙).

### 3-3. 보완 계획
- **실데이터 재채점**: 현재 개선(+10%)은 깨끗한 시뮬 기준이라 낙관적. 실주행 필드 로그로 잔차 신경망을 재학습/재평가.
- **잔차 과활성 점검**: 잔차 보정이 물리(추세/드리프트) 항보다 커지면 clamp를 조이거나 학습을 재검토(설명 화면으로 상시 모니터).
- **개인화 상호작용 정리**: 온라인 파라미터 개인화와 잔차 보정의 중복 여지를 clamp로 상한, 향후 분리 정교화.

## 부록. 용어 한 줄 사전 (도메인 지식 0 독자용)

- **심박 예측**: "이 페이스를 유지하면 30/60초 뒤 심박이 몇일지" 미리 계산하는 것.
- **ODE(상미분방정식)**: 겁먹을 것 없이 "변화 규칙을 적은 식". 여기선 "심박이 목표를 향해 서서히 오르는 법칙".
- **잔차**: 공식이 맞히고 남은 나머지 오차. "항상 +2도 빗나가는 버릇" 같은 것.
- **신경망(MLP)**: 입력 숫자를 여러 층에 곱하고 더해 결과를 내는 학습 모델. 속이 불투명(블랙박스).
- **gray-box / PINN**: 물리 공식(뼈대) + 작은 신경망(잔차 보정)을 합친 구조. 적은 데이터에 강하고 설명 가능.
- **clamp**: 출력을 안전 범위로 "잘라내기". 생리적으로 말 안 되는 값 방지.
- **QA(품질속성)**: 시스템이 잘 만들어졌는지 보는 기준(정확성/강건성/적응성/효율성/검증가능성/설명용이성).

> 관련 문서: `arch/adr-020`(생리 ODE 결정), `report-005`(gray-box/PINN 학습 노트), `WHITEPAPER 5-1`(상세), `spec/spec-002`(QA 정의).
