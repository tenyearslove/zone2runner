# ADR-010: 폰 지도 렌더링 라이브러리 선택 — osmdroid(OSM)

- **날짜**: 2026-07-03
- **상태**: Accepted
- **결정자**: 성시원
- **보고서 매핑**: 설계 - Architectural Decision (구현 사후 문서화)

---

## 맥락

폰 앱은 러닝 앱의 필수 요소인 두 가지 지도 화면을 필요로 한다.

1. **실시간 지도**: 러닝 중 현재 위치를 추적해 이동 경로를 그려 보여준다 (MainActivity).
2. **결과 경로 지도**: 세션 종료 후 지나온 경로를 존(Zone) 색으로 구분한 폴리라인으로 표시한다 (ReportActivity, 미달/유지/초과 색 구분).

이 두 요건을 위해 지도 렌더링 라이브러리를 정해야 한다. 이때 zone2runner는 상용화가 아니라 **AI 설계 교육과정 수료 프로젝트**라는 성격이 선택을 좌우한다. 핵심 산출물은 설계와 얇은 PoC이므로, 지도는 "요건을 충족하되 도입 마찰이 가장 적은" 선택이어야 한다. API 키 발급, 결제 계정 연결, 사용량 과금 같은 절차는 이 프로젝트의 본질과 무관한 마찰이다.

---

## 결정

### 대안 비교

| 기준 | A. Google Maps SDK | B. osmdroid (OSM) | C. Mapbox |
|------|------|------|------|
| API 키 / 인증 | 필요(발급) | **불필요** | 토큰 필요 |
| 과금 | 결제 계정 + 사용량 과금 | **무료** | 무료 티어 제한 후 과금 |
| 실시간 위치 오버레이 | 우수 | 충분 | 우수 |
| 폴리라인 / 존 색 경로 | 우수 | 충분(Polyline API) | 우수 |
| 오프라인 타일 캐시 | 제한적 | 가능 | 가능 |
| 도입 마찰(교육 프로젝트) | 높음 | **낮음** | 중 |
| 준수 사항 | 약관 | 타일 서버 사용정책(User-Agent 설정) | 토큰 관리 |

### 대안 A: Google Maps SDK
- 장점: 완성도와 친숙도가 높고 문서/예제가 풍부하다.
- 단점: API 키 발급 + 결제 계정 연결 + 사용량 과금이 전제된다. 교육 프로젝트에서 지도 하나 띄우려고 결제 수단을 거는 것은 본질과 무관한 마찰이다.

### 대안 B: osmdroid (OSM) *(채택)*
- OpenStreetMap 타일을 렌더링하는 오픈소스 안드로이드 지도 라이브러리.
- 장점: **API 키/과금 불필요**, 무료. 오프라인 타일 캐시가 가능하고, 폴리라인/오버레이 API가 실시간 추적과 존 색 경로 표시에 충분하다. 의존성 한 줄로 도입된다.
- 단점: OSM 타일 서버의 사용정책을 준수해야 한다(요청 시 앱 식별용 User-Agent 설정 필요, 과도한 타일 요청 금지). 상용 지도 대비 타일 품질/커버리지 편차가 있을 수 있다.

### 대안 C: Mapbox
- 장점: 지도 품질과 커스터마이징이 좋다.
- 단점: 액세스 토큰이 필요하고 무료 티어를 넘으면 과금된다. A와 같은 계정/과금 마찰이 남는다.

### 채택: 대안 B

교육 프로젝트 성격상 **키/과금 없이 바로 도입되는 osmdroid가 마찰이 가장 적으면서** 두 요건(실시간 지도, 결과 존 색 경로)을 모두 충족한다. 실제 구현에 다음과 같이 반영되어 있다.

- `app/app/build.gradle.kts`: `org.osmdroid:osmdroid-android:6.1.18`
- `MainActivity`: 라이브 지도 위치 추적 및 경로 표시
- `ReportActivity`: 존 색 폴리라인으로 결과 경로 표시

---

## 결과 / 트레이드오프

- 지도 도입에 외부 계정/결제/키 관리가 필요 없어 개발과 시연이 단순해진다.
- 대가로 OSM 타일 서버 사용정책을 준수해야 한다(User-Agent 설정, 타일 요청량 절제). 타일 캐시로 반복 요청과 오프라인 열람을 완화한다.
- 이 결정은 교육 프로젝트 스코프에 한정된다. **상용화 단계에서는** 지도 품질, 타일 서버 부하 정책, 트래픽 규모에 따라 Google Maps나 Mapbox 등 상용 타일 서비스로의 전환을 재검토할 수 있다(라이브러리 교체 지점은 두 Activity의 지도 렌더링부로 국한된다).
