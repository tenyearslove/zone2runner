# DP-05 리서치 노트 — 소스 추상화 + 시뮬 검증(테스트가능성) 근거

> DP-05 본문(`dp-05-testability-decision.md`)의 근거 문헌 정리. 기존 설계 이력(spec-003/019/022, adr-024, EXPERIMENT_LOG)을 이 DP 관점으로 재정리 + 표준 문헌 대조.

## 1. 테스트가능성의 공식 정의

- **ISO/IEC 25010**: Testability = 시스템/컴포넌트에 대해 테스트 기준을 확립하고, 그 기준 충족 여부를 판정하는 테스트를 수행하기 쉬운 정도(유지보수성의 하위 특성). 실무 해석 = 테스트의 **제어 가능성**(원하는 자극을 넣을 수 있음)과 **관찰 가능성**(결과를 들여다볼 수 있음).
- **spec-002 QA5**: 참값 없는 문제(C03)를 폐루프 서로게이트로 검증. 측정 = Watch 없이 독립 실행 비율 100%, 단위 테스트 통과, 수렴 곡선. **핵심 단서 명시: "시뮬=구조 검증/디버거이지 실인간 정확도 아님".**

→ DP-05의 평가 기준: "재현 가능한 자극을 넣을 수 있는가, 자동으로 회귀를 잡는가, 시뮬 결론의 한계를 정직하게 긋는가".

## 2. 소스 추상화 — Ports and Adapters / DIP

- **Cockburn, Hexagonal Architecture(Ports and Adapters)**: 외부 장치(센서/DB/UI)를 포트(인터페이스) 뒤로 밀어내면, 운영에서는 실물 어댑터를, 테스트에서는 대역 어댑터를 꽂는다 — 애플리케이션이 "장치 없이" 구동/검증 가능해진다.
- **의존성 역전 원칙(DIP)**: 상위 로직이 구체(센서 API)가 아니라 추상(RunSource)에 의존. CLAUDE.md 모듈화 원칙에 명시된 이 시스템의 기존 규율 — RunSource(spec-003)가 구현체.
- 파생 효과: 검증과 운영이 **같은 코드 경로**를 지난다(테스트 전용 분기 없음) — 테스트가 검증하는 것이 곧 출시 코드.

## 3. 테스트 대역과 폐루프 서로게이트

- **Meszaros, xUnit Test Patterns**: Test Double(스텁/페이크/목) 분류 — 실물을 대신해 재현 가능한 검증을 만드는 표준 관행.
- 이 시스템의 가상 러너(spec-019)는 단순 재생 스텁이 아니라 **반응하는 페이크(폐루프)**: 코칭 → 러너 행동 변화 → 입력 변화의 상호작용을 검증. 참임계를 알고 있어 개인화 **수렴을 정량 채점**할 수 있다(압축 시간 — 수 주짜리 검증을 분 단위로).
- 수동 가상 러너(spec-022) = 사람이 조작하는 대역 — 엣지 시나리오 탐색용.

## 4. 테스트 배분 — 테스트 피라미드

- **Cohn(Succeeding with Agile) / Fowler(TestPyramid)**: 빠르고 저렴한 단위 테스트를 두텁게, 느리고 비싼 통합/실기기/수동 테스트를 얇게. 역피라미드(실기기 중심)는 피드백 지연과 검증 생략을 낳는다는 것이 일관된 관찰.
- 이 시스템의 배분: 결정 로직 전부가 JVM 순수 모듈(안드로이드 의존 없음) — 단위 테스트 153개가 수 초에 돌고, 실기기는 결합 확인(installDebug + 시뮬 확인)만.

## 5. 시뮬레이션 기반 검증과 그 한계(sim-to-real)

- 실환경 시험이 비싸거나 위험한 분야(자율주행, 로보틱스)에서 시뮬 기반 검증은 표준 관행 — 동시에 **시뮬-실환경 간극(sim-to-real gap)을 명시**하고 시뮬 결론의 범위를 긋는 것까지가 관행.
- **이 저장소의 자체 이력이 이 한계의 직접 증거**: 초기 예측 설계에서 "시뮬 MAE 우수"가 사실 자기 가정 채점(지상진실을 우리가 1차 지연 곡선으로 생성 → 곡선 예측기가 이기는 게 정의상 성립)임을 확인(`ml/EXPERIMENT_LOG.md` §15-3, 2026-07-10). 이후 결정: **시뮬 = 정확도 심판이 아니라 구조 검증/디버거**(adr-024, spec-002 QA5) — 구조적 실수(비대칭 τ backfire 등)를 잡는 용도는 정당, 정확도 주장은 실주행으로만.
- 시사점: 1안의 "정직한 한계" 절이 사후 변명이 아니라 설계 이력에 근거한 경계 긋기임.

## 6. 엣지/위험 시나리오 주입

- 위험 고심박(SafetyGuard 발동), 신호 두절(staleness 폴백), 경계 근처 진동(히스테리시스/Flicker) 같은 방어 로직은 실주행으로 만들기 어렵거나 위험 — 시뮬 주입이 유일하게 안전한 검증 경로. 강건성 DP(dp-04)의 일관성 지표 측정도 이 주입 위에서 수행(폐루프 Robustness Score).
- 실기기 검증과의 역할 분담: 시뮬 = 회귀/엣지/수렴, 실기기 = 결합 특성(센서 타이밍/전원 관리/블루투스) + 최종 실주행 검증(spec-012).

## 7. 2안(실기기 결합 검증)의 실제 위상

- 실환경 충실도는 시뮬이 완전히 대체할 수 없는 강점 — 센서 노이즈의 실제 분포, OS 백그라운드 제약, 기기 간 타이밍은 실기기에서만 드러난다(이 저장소도 워치 BG 액티비티 제한, Nano 다운로드 정책 등을 실기기에서 발견).
- 2안이 비중을 키울 조건: 테스트 러너 풀/장비를 갖춘 조직, 로직 안정기(변경 빈도 낮음), 규제상 실측 요구. 어느 설계든 최종 검증은 실주행 — 차이는 "실기기**만**으로 검증하느냐".

## 8. DP-01~04와의 관계

- 다섯 번째 QA 단면: 순수 모듈 분리(층별 검증)는 강건성 DP의 방어층 검증 단위와 같고, 폐루프 수렴 채점은 기능적응성 DP의 측정 지표를 실행 가능하게 만들며, 시뮬 계측(가드 동작 관찰, LLM 켬/끔 비교)은 제어가능성 DP의 감사와 설명용이성 DP의 추적을 개발 단계에서 재현한다 — 테스트가능성이 다른 QA들의 **측정을 실행 가능하게 만드는 기반 QA**.
