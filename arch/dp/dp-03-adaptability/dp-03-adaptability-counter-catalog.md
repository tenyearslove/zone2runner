# 오프라인 재학습 개인화 아키텍처 컴포넌트 카탈로그 (설계 B)

- **상태**: 검토용 v1 (2026-07-31). 기능적응성 DP의 **대안(설계 B)** 아키텍처를 우리 것과 **같은 방식**으로 식별/서술한다. 이는 우리가 구현한 게 아니라, 공정 비교를 위한 **가정 설계**(산업 개인화/추천의 주류 MLOps 재학습 루프)다.
- **도식**: `images/dp-03-adaptability-counter-detailed.png`(상세) + `images/dp-03-adaptability-counter-simple.png`(축약).
- **핵심 대비(우리 vs 카운터)**: 우리는 적응이 **폰 안에서 라벨이 들어온 그 자리**에 일어나고, 카운터는 **서버의 재학습 주기**에 일어난다. 우리 근거는 사용자 실라벨(검증 가능), 카운터 근거는 재학습 목적함수(참값 없는 조건에선 채점 기준 부재).

---

## A. 서빙 (폰 쪽)

### A1. 입력 가드레일
- **표준 매핑**: 입력 가드레일 / **책임**: 이상값 필터(우리와 동일하게 필요).

### A2. 개인화 모델 서빙 (배포본 vN)
- **표준 매핑**: 모델 서빙(블랙박스) / **책임**: 배포된 개인화 모델이 경계를 산출. **우리와 차이**: 배포본 사이에서 경계는 고정 — 세션 중 답/변화가 그 자리에서 경계를 움직이지 않는다.

### A3. 라벨/세션 수집기
- **표준 매핑**: 데이터셋 구축(수집 에이전트) / **책임**: 세션 관측과 말하기 테스트 답을 서버로 업로드. **우리와 차이**: 우리는 라벨이 그 자리에서 소비되고 기기를 떠나지 않는다 — 여기선 라벨이 "다음 학습의 재료"로 이동한다.

## B. 학습 (서버 쪽 — 적응의 본체)

### B1. Data Lake (코호트 데이터)
- **표준 매핑**: Data Lake / **책임**: 전체 사용자의 세션/라벨 축적. 코호트 학습의 원천(2안의 강점).

### B2. Model Construction (주기 재학습)
- **표준 매핑**: Model Construction / **책임**: 개인 + 코호트 데이터로 개인화 모델 재학습(일/주 주기). **우리와 차이**: 복잡한 특징(수면/요일/기온 상호작용)을 배울 잠재력이 있으나, 참값이 없어 무엇을 최적화했는지 채점하기 어렵다.

### B3. 모델 테스팅 / Model Registry / 배포
- **표준 매핑**: 모델 테스팅 + Registry / **책임**: 재학습본 검증(홀드아웃/오프라인 지표) 후 vN+1 배포. **우리와 차이**: 적응 반영 시점이 이 배포 주기에 묶인다 — 개인의 변화 감지→반영 지연이 일/주 단위.

## C. 운영/개입

- Operation UI + 개입 = 피드백 제출(다음 학습에 반영). **우리와 차이**: 우리 개입(말하기 테스트)은 그 자리에서 경계를 움직이고 결과가 화면에 보인다 — 여기선 개입 효과가 다음 배포에서야 나타나 확인이 늦다.

## 요약 — 무엇이 다른가

| 축 | 우리 (설계 A: 온라인 베이지안 개인 적응) | 카운터 (설계 B: 오프라인 재학습 개인화) |
|---|---|---|
| 적응 위치 | 폰 안(온디바이스) | 서버(재학습) |
| 적응 시점 | 라벨이 들어온 그 자리(분 단위) | 수집→재학습→배포 주기(일/주 단위) |
| 적응 근거 | 사용자 실라벨(검증 가능) | 재학습 목적함수(참값 없으면 채점 기준 부재) |
| 노이즈 대응 | 확신 폭 + 이동 한도 | 배치 평균화 — 이 축은 카운터 우위 |
| 표현력 | 단순(평균/확신 폭) | 복잡한 특징 학습 잠재 — 이 축은 카운터 우위 |
| 비용/제약 | 공식 몇 줄, 비용 0, 데이터 비이탈 | 서버/네트워크/운영 비용, 데이터 업로드 |
| 갱신 설명 | 평균/확신 폭 노출(그대로 설명) | 재학습 내부 — 왜 그 값인지 설명 어려움 |
