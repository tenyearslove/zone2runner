# LLM 판단 위임 아키텍처 컴포넌트 카탈로그 (설계 B)

- **상태**: 검토용 v1 (2026-07-23). 제어가능성 DP의 **대안(설계 B)** 아키텍처를 우리 것과 **같은 방식**으로 식별/서술한다. 이는 우리가 구현한 게 아니라, 공정 비교를 위한 **가정 설계**(LLM 에이전트 계열의 주류 방식)다.
- **도식**: `images/dp-02-controllability-counter-detailed.png`(상세) + `images/dp-02-controllability-counter-simple.png`(축약).
- **핵심 대비(우리 vs 카운터)**: 우리는 판단(방향/안전/타이밍)이 규칙에 있고 LLM은 표현만 맡지만, 카운터는 **판단과 표현이 모두 LLM 안**에 있다. 통제 수단이 우리는 구조(가드레일/폴백/우회)이고, 카운터는 **프롬프트 규정 + 사후 필터**다.

---

## A. 추론 서비스 (Inference Service)

### A1. 입력 가드레일
- **표준 매핑**: 입력 가드레일 / **책임**: 이상값 필터(우리와 동일하게 필요).

### A2. 컨텍스트 조립기
- **표준 매핑**: 데이터 준비 / **책임**: 관측(심박/페이스/케이던스/경사)과 세션 상태를 **프롬프트 텍스트로 직렬화**해 LLM 입력을 만든다. **우리와 차이**: 우리는 관측을 규칙/통계가 소비해 판정을 확정한 뒤 그 결과만 LLM에 준다 — 여기선 원맥락이 통째로 LLM에 간다.

### A3. 시스템 프롬프트 (규정 서술)
- **표준 매핑**: 모델 서빙 구성 / **책임**: 존 정의, 코칭 원칙, 안전 수칙, 금지 사항을 자연어 규정으로 서술. **통제의 주 수단이 이 문서다.** **우리와 차이**: 우리 규정은 코드(규칙/가드)라 강제되지만, 프롬프트 규정은 모델의 지시 이행에 의존한다.

### A4. LLM 판단+생성
- **표준 매핑**: 모델 서빙(판단 위임 — 블랙박스) / **책임**: 컨텍스트를 읽고 **코칭 여부/방향/내용을 직접 판단해 문장을 생성**한다. **우리와 차이**: 우리 LLM은 규칙이 확정한 내용의 표현만(verbalizer). 판단이 모델 안으로 들어가면 같은 입력에 다른 출력이 나올 수 있고(비결정), 판단 근거가 파라미터에 분산돼 읽기 어렵다.

### A5. 사후 안전 필터
- **표준 매핑**: 출력 가드레일 / **책임**: 금칙어/수치 범위/길이 등 **형식 수준**의 사후 차단. **우리와 차이**: 방향의 "정답"이 시스템에 없어(판단=LLM) **방향 일치 검증(DirectionGuard 상당)이 원리적으로 불가능**하다 — 필터가 확인할 기준값이 없다.

### A6. 재시도/캐시
- **표준 매핑**: 서빙 로직 / **책임**: LLM 타임아웃/오류 시 재시도, 최근 응답 캐시 재사용. **우리와 차이**: 우리는 실패 시 **규칙 판단으로 갈아탄다**(폴백 체인, 기능 무중단). 여기선 판단 주체가 LLM뿐이라 재시도 실패의 끝이 **침묵 또는 지연**이다.

## B. 설명
- LLM이 코칭과 함께 이유를 서술하게 할 수 있다(프롬프트로). 판단과 설명이 같은 모델에서 나와 자연스럽지만, 그 설명이 실제 내부 판단 근거인지 별도로 보장되지 않는다(DP-01의 사후 설명과 같은 한계).

## C. 분석/감사
- 입출력 로그(프롬프트/응답) 기록은 가능. **우리와 차이**: 우리는 "어느 규칙이 발화를 만들었고 가드가 왜 기각했는지"가 기록되지만, 여기선 판단 근거가 모델 내부라 감사가 **입출력 상관 수준**에 머문다.

## D. 운영 서비스 (Operation)
- Operation UI + 개입 수단 = **프롬프트 문구 수정**(규정 추가/강조) + 필터 목록 갱신. **우리와 차이**: 프롬프트 수정→행동 변화가 비결정적이라 개입 효과를 확인하려면 재현 실험이 필요하다. 우리 개입(설정 토글/가드 기준/폴백)은 결정적으로 작동한다.

## 요약 — 무엇이 다른가

| 축 | 우리 (설계 A: 규칙 확정 + LLM 표현 한정) | 카운터 (설계 B: LLM 판단 위임) |
|---|---|---|
| 판단 주체 | 규칙(코드로 강제) | LLM(프롬프트 규정에 의존) |
| 방향 검증 | 가능(정답=규칙 판정이 시스템에 있음) | 원리적으로 불가(정답이 모델 안) |
| 실패 시 | 규칙 판단으로 폴백(무중단) | 재시도 실패 = 침묵/지연 |
| 안전 권고 | LLM 미경유(규칙 즉시) | 프롬프트 수칙 의존 |
| 개입 수단 | 가드 기준/설정/폴백(결정적) | 프롬프트 수정(비결정적) |
| 감사 | 기각/폴백 사유가 세션 기록에 영속 | 입출력 상관 수준 |
| 표현/내용 자유도 | 상한 있음(규칙 문구 기반) | 높음(자유 문맥 생성) — 이 축은 카운터 우위 |
