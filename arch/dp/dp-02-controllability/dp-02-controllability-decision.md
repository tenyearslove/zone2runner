> **[설계 문제 정의] → [설계안 결정 표: 구조(다이어그램) / 장점(QA 별점) / 단점(QA 별점) / Trade Off] → [설계 결정 및 근거]**.
> 이 분야를 전혀 모르는 사람도 읽고 이해할 수 있게 쓴다. 이 문서는 **제어가능성 DP 하나에만** 집중한다.
>
> **상태**: v2 (2026-07-31) — 쉬운 문장 재작성(DP1 v3와 같은 톤, 전문 용어는 부록 B로) + as-built 정합(문장 세트 잔재 제거, 모델 준비 보류 반영). 리서치 노트(`dp-02-controllability-research.md`) 근거.
> v1.1: 표현 경로 현행화 — LLM 직생성 + 단어 수준 폴백 + 숫자 무결성 가드.
> DP-01(설명용이성)과 같은 아키텍처의 다른 QA 단면 — 관계는 §0/§6-2 참조.

## 0. 읽기 전에 — 30초 배경

- 이 앱은 코칭 문장을 만들 때 **폰 안에서 도는 작은 LLM**(Gemini Nano)을 쓴다. 서버 없이 도는 작은 모델이라 능력에 한계가 있다.
- 작은 LLM은 **시킨 대로 따르는 능력이 불안정하다**(문헌: 소형 모델의 지시 이행률 60% 미만 사례). "프롬프트에 규칙을 잘 써 두면 지키겠지"라는 기대가 보장되지 않는다는 뜻이다.
- 그런데 이 앱의 코칭은 **달리는 중에 실시간 음성**으로 나간다. 사람이 문장 하나하나를 검사해 줄 수 없다. 통제는 사람 손이 아니라 **자동으로 작동하는 구조**여야 한다.
- 제어가능성이라는 품질은 "문제가 생겼을 때 **제때, 알맞게 개입**할 수 있는 정도"를 말한다(ISO/IEC 25059). 강의 정본은 제어를 **교정 / 보완 / 안전전환** 세 유형으로 나누고, 입출력 가드레일을 조정하는 것 자체를 제어 행위로 본다.
- **이 DP = 믿고 맡기기 어려운 작은 LLM을 쓰면서도 통제권을 잃지 않는 내부 구조를 무엇으로 할 것인가** 라는 설계 결정이다.

## 1. 설계 문제 정의

### 1-1. 배경

**(1) LLM이 이 시스템에서 하는 일**
실시간 코칭 문장, 세션 스토리 요약, 개인화 설명 풀이 — 사용자와 만나는 자연어 출력을 만든다. 표현이 자연스러울수록 코칭 경험이 좋아지므로 LLM을 쓸 이유는 충분하다.

**(2) 무엇이 어려운가 — 이 문제의 진짜 난도**
- **모델이 약하다**: 작은 온디바이스 LLM은 시킨 형식과 금지 사항을 지키는 것이 불안정하다. 프롬프트에 규정을 아무리 잘 써도, 판정은 "초과 — 늦춰라"인데 문장은 "속도를 올려요"가 나오는 일을 프롬프트만으로는 막을 수 없다.
- **실시간이라 검수할 수 없다**: 달리는 중 음성으로 나가는 코칭이라 사람이 출력마다 확인하고 승인할 수 없다. 개입은 자동으로 작동하는 구조와 사후 기록 확인으로 설계해야 한다.
- **LLM이 없는 상황이 일상이다**: 모델을 아직 다운로드하지 않았거나, 준비 중이거나, 응답이 늦거나 실패하는 상황이 정상 운영 범위 안에 있다. 그때도 코칭 기능은 끊기면 안 된다.
- **안전이 걸린 순간이 있다**: 위험할 정도로 심박이 높을 때의 권고는 LLM이 늦거나 잘못 말할 여지를 허용할 수 없다.

**(3) 그래서 생기는 결론**
통제권을 "LLM이 규정을 따라 준다"에 의존하면, 그 기대가 깨질 때 개입할 곳이 없다. 반대로 **LLM이 맡는 일 자체를 좁히고(격리), 나온 출력을 규칙이 검사하고(가드레일), 실패하면 갈아탈 길을 두고(폴백), 작동 기록을 남기면(감사)** — LLM이 약해도 시스템 수준의 통제권이 성립한다.

### 1-2. 문제점 — 통제를 "프롬프트에 맡기면 안 되는" 이유

| # | 문제 | 걸리는 제약(spec-001)/품질(spec-002, framework 8대 QA) |
|---|---|---|
| P1 | 작은 LLM은 시킨 대로 따르는 것이 불안정 — 프롬프트 규정은 보장이 아니다 | **제어가능성**(정체성 축 중 하나) — 개입 지점이 구조에 있어야 |
| P2 | 실시간/음성이라 출력마다 사람이 검수할 수 없다 | **제어가능성** — 자동 가드레일 + 사후 감사(HOTL) |
| P3 | LLM 미가용/지연/오류가 정상 운영 범위다 | **강건성** — 실패해도 기능이 이어지는 폴백(안전전환) |
| P4 | 위험 심박 권고는 지연/오작동을 허용할 수 없다 | **제어가능성(안전전환)** — 안전 경로는 LLM 미경유 |
| P5 | 통제가 실제로 작동했는지 나중에 확인할 수 있어야 한다 | **제어가능성(감사)** — 기각/폴백 기록(HOTL) |
| P6 | 사용자도 개입할 수 있어야 한다(경계 정정, 빈도/말투/더위/관절 설정) | **제어가능성(교정/보완)** — HITL/HOTL 채널 |
| P7 | 통제가 과하면 표현이 굳는다 — 표현의 자유도와 통제는 상충한다 | **기능적응성** — 통제 비용의 정직한 인정 |

### 1-3. 설계 문제 (한 문장)

> **"시킨 대로 따르는 것이 불안정한 작은 온디바이스 LLM을 코칭 표현에 쓰면서 — 사람이 출력마다 검수할 수 없는 실시간 조건에서 — 어긋난 출력의 차단, 실패해도 기능 유지, 안전 상황의 즉시 권고, 사후 확인, 사용자 개입까지의 통제권(제어가능성)을 어떤 내부 구조로 확보할 것인가."**

## 2. 두 후보를 공정하게 비교하는 틀

- **바깥 경계(입출력)를 똑같이 고정하고, 안쪽 구조만 다르게 본다.**
  - 입력: 관측 신호(1Hz 심박/페이스/케이던스/경사)와 시스템 상태(존 판정/경계/맥락).
  - 출력: 코칭 문장(음성/TTS), 세션 후 설명 텍스트.
- **다이어그램 읽는 법**(두 안 공통 표기법): 각 블록 상단의 «...» = 강의 AI System 아키텍처의 컴포넌트 유형. 색 = 컴포넌트 성격(가드레일=주황, 모델 서빙=파랑(투명)/회색(블랙박스), 설명=초록, 운영=보라, 저장=회청, 외부=노랑). 실선=데이터 흐름, 점선=제어.
- 품질(QA) 평가는 그림이 아니라 **결정 표의 장점/단점 칸**에서 한다.

## 3. (1안) 규칙 확정 + LLM 표현 한정 아키텍처 — 판단은 규칙이 쥐고, LLM은 문장만 — ★채택

**한 줄 개념**: 코칭에서 **무엇을 권할지(방향)와 어떤 사실을 말할지(숫자)는 규칙이 확정**하고, LLM은 그 재료로 **문장을 만드는 일만** 맡는다. 나온 문장은 규칙이 다시 검사하고(출력 가드 3종), 걸리거나 실패하면 "속도 줄이기" 같은 단어 수준 문구로 바꿔 내보내며(폴백), 위험 심박 권고는 LLM을 거치지 않고, 모든 호출의 경로와 기각/폴백 사유가 세션에 기록된다(감사).

![1안 — 규칙 확정 + LLM 표현 한정](../../diagrams/02b-component-cnc-simple.png)

> 채택안(1안)은 이 시스템의 실제 아키텍처이므로 일반 도식을 참조한다. 상세 컴포넌트 뷰 = `arch/diagrams/02-component-cnc.png`, 컴포넌트 서술 = `arch/component-catalog.md`(A2/A7/A7-1/A8/D3).

**통제 장치 5층** (각 층은 독립적으로 작동한다 — 한 층이 뚫려도 다음 층이 막는다):

| 층 | 장치 | 제어 유형(강의 3유형) |
|---|---|---|
| 1. 구조적 격리 | 방향/사실은 규칙이 확정하고, LLM은 문장 표현만 맡는다. 프롬프트에는 말투 한 단어, 관측된 사실 숫자, "한 문장으로 권하라"는 임무만 담는다("숫자는 준 것만" 지시 포함) | 예방 — 맡기는 권한 자체를 좁힘 |
| 2. 출력 가드 3종 | 형식(길이/문장 수/이모지) + 방향(규칙이 정한 방향과 모순되거나 방향을 아예 안 전하면 기각 — DirectionGuard) + 숫자 무결성(문장의 모든 숫자가 입력 관측에 있어야 통과, 언어 무관 — NumberGuard) | 교정 |
| 3. 폴백 | 기각/실패/모델 없음이면 "속도 줄이기" 같은 단어 수준 문구로 바꿔 내보낸다. 모델 준비가 확정되기 전에는 코칭을 잠시 보류했다가 확정 후 재개한다. 어떤 경우에도 코칭 기능은 끊기지 않는다 | 안전전환(fail-safe) |
| 4. 안전 경로 분리 | 위험 고심박 권고는 LLM을 거치지 않고 규칙이 즉시 말한다(SafetyGuard) | 안전전환 |
| 5. HITL/HOTL + 감사 | 말하기 테스트로 경계 정정(HITL, 교정), 설정 토글(빈도/음성/말투/더위/관절 — 보완), 모든 LLM 호출의 경로/기각/폴백 사유가 세션마다 저장돼 리포트에서 확인 | 교정/보완 + 감사 |

### 3-1. 구조가 문제점(§1-2)을 푸는 방식

| 문제 | 푸는 구조 |
|---|---|
| P1 지시 이행 불안정 | 프롬프트 규정에 기대지 않는다 — 방향은 규칙이 확정(층1)하고, 나온 출력은 규칙이 재검사(층2) |
| P2 출력별 검수 불가 | 검사가 자동으로 작동(층2)하고, 결과는 사후 감사 기록으로 남는다(층5) |
| P3 미가용/지연/오류 | 가용성 확인 + 준비 전 보류 + 단어 폴백(층3) — 최악의 경우에도 단어 수준 코칭으로 이어진다 |
| P4 안전 상황 | 안전 권고는 LLM을 거치지 않는다(층4) — 지연/오작동 여지를 원천 배제 |
| P5 사후 확인 | 방향 기각 횟수/폴백 사유가 세션 기록에 남아 리포트에서 확인할 수 있다(층5) |
| P6 사용자 개입 | HITL(말하기 테스트, 경계 이동 ±10bpm 한도) + HOTL(설정 5종/일시정지)(층5) |
| P7 표현 굳음 | 표현은 LLM이 전담해 자유도가 있다 — 굳는 것은 기각/폴백이 일어난 그 순간뿐. 코칭 시점/내용의 상한은 인정한다(§단점) |

### 3-2. "이게 검증된 접근이냐?" — 근거

- **① 계층 가드레일 = 표준 관행**: LLM 안전 실무와 서베이는 입력 검증 / 출력 필터 / **구조적 격리(모델이 할 수 있는 일 자체를 제한)**의 계층 방어를 표준으로 제시하고, 그중 구조적 격리를 가장 강한 층으로 분류한다. 1안의 "LLM=표현만"이 이 격리에 해당한다.
- **② 판단을 LLM 혼자에게 맡기지 않기**: LLM을 판정자로 쓰는 실무 권고는 영향이 큰 판단에 LLM을 단독 결정자로 쓰지 말고 결정론적 규칙을 근간으로 두라고 명시한다. 1안은 판단(방향/안전)을 규칙에 두고 LLM은 표현만 맡는다.
- **③ 제어가능성 정의와의 정합**: "제때, 알맞게 개입"(ISO/IEC 25059)과 강의 3유형(교정/보완/안전전환)에 대해, 1안은 유형별 개입 지점이 구조에 존재한다(§3 표의 3열). 강의 정본은 입출력 가드레일 조정 자체를 제어 행위로 본다.
- **④ 실측할 수 있는 감사**: 통제 장치가 실제로 작동했는지(방향 기각률, 폴백 사유 분포, 지연)가 세션마다 기록돼, "통제가 되고 있는가"를 데이터로 답할 수 있다.

**정직한 한계(먼저 인정)**: (1) **코칭 시점/내용의 상한** — 언제 무엇을 코칭할지(트리거/임무)는 규칙 집합에 묶이므로, 규칙에 없는 새로운 상황의 코칭은 규칙을 추가해야 나온다(P7). 표현 자체는 LLM이 전담해 자유도가 있다. (2) **과차단 가능성** — 보수적으로 검사하므로 가드가 정상 문장을 기각할 수 있다. 기각률이 기록되므로 데이터로 튜닝할 대상이다. (3) **통제 ≠ 내용의 옳음** — 규칙 자체가 틀리면 통제는 성립해도 내용이 틀린다. 내용의 교정은 말하기 테스트(HITL)와 DP-01의 정정 채널이 맡는다.

**장점(QA 별점)**: 제어가능성 ★★★★★ (교정/보완/안전전환 개입 지점이 구조에 존재 + 감사 가능), 강건성 ★★★★★ (미가용/오류에도 단어 폴백으로 코칭이 이어짐)
**단점(QA 별점)**: 기능적응성 ★★★ (코칭 시점/내용은 규칙 집합에 묶임 — 새 상황은 규칙 확장 필요), 수행효율성 ★★★★ (가드 검사/폴백의 부담은 작지만 존재)

## 4. (2안) LLM 판단 위임 아키텍처 — 판단까지 LLM에 맡기고, 규정은 프롬프트로 — 카운터

**한 줄 개념**: 관측 컨텍스트를 프롬프트로 주고 **LLM이 코칭의 내용/방향까지 직접 판단해 생성**한다. 통제는 시스템 프롬프트에 규정(존 정의, 안전 수칙, 금지 사항)을 써 두고, 출력에 사후 안전 필터(금칙어/수치 범위)를 거는 방식이다. 이는 LLM 에이전트 계열의 주류 접근이며, 지어낸 비교 대상이 아니라 **동등하게 진지한 대안**이다 — 모델이 충분히 강하고 사람 검수 루프를 둘 수 있는 조건에서는 이쪽이 우선될 수 있다.

![2안 — LLM 판단 위임 아키텍처](images/dp-02-controllability-counter-simple.png)

> 카운터(2안)는 이 DP 전용 가정 설계다. 상세 컴포넌트 뷰 = `images/dp-02-controllability-counter-detailed.png`, 컴포넌트 서술 = `dp-02-controllability-counter-catalog.md`.

**요지**: 판단과 표현이 한 곳(LLM)에 있어 구조가 단순하고, 규칙 집합에 없는 상황에서도 문맥을 읽은 코칭을 만들어낼 잠재력이 있다. 대신 통제권의 성립이 "LLM이 프롬프트 규정을 따라 준다"는 기대에 의존한다.

**구조가 문제점을 대응하는 방식과 그 비용**:

| 문제 | 2안의 대응 | 남는 비용 |
|---|---|---|
| P1 지시 이행 불안정 | 시스템 프롬프트에 규정을 상세히 서술 | 작은 모델의 규정 준수가 불안정(문헌) — 대응 자체가 P1의 기대 위에 서 있다 |
| P2 검수 불가 | 사후 안전 필터(금칙어/범위) | 판단을 LLM이 하므로 "맞는 방향"이 시스템 안에 없다 — 방향을 검증하는 필터를 만들 수 없다 |
| P3 미가용/오류 | 재시도/캐시 | 판단 주체가 LLM뿐이라 실패하면 대신 판단할 것이 없다 — 폴백이 침묵이나 지연이 된다 |
| P4 안전 상황 | 프롬프트에 안전 수칙 명시 | 안전이 LLM의 지시 이행에 의존한다 — 지연/오작동 여지가 남는다 |
| P5 사후 확인 | 입출력 로그 | 판단 근거가 모델 내부에 있어 "왜 그 코칭이었나"를 감사하기 어렵다 |
| P6 사용자 개입 | 프롬프트 문구 수정 | 수정이 효과로 이어진다는 보장이 없고(같은 입력에 다른 출력이 나올 수 있음), 개입 결과를 확인하기 어렵다 |
| P7 표현 자유 | 강점 — 문맥을 읽은 자유로운 생성 | (이 축은 2안이 우위) |

**장점(QA 별점)**: 기능적응성 ★★★★ (규칙 집합 밖 상황에도 문맥 코칭 생성 잠재), 기능정확성 ★★★ 잠재 (풍부한 문맥 반영 — 단 이 조건에선 검증이 어려움)
**단점(QA 별점)**: 제어가능성 ★★ (개입 수단이 프롬프트 수정+사후 필터로 한정, 효과 비보장), 강건성 ★★ (LLM 실패 시 판단을 대신할 것이 없음)

## 5. 설계안 결정 표 (샘플 슬라이드 형식)

| | **(1안) 규칙 확정 + LLM 표현 한정 ★채택** | (2안) LLM 판단 위임 |
|---|---|---|
| 통제 방식 | 맡기는 일 자체를 좁히고(격리), 출력을 규칙이 검사하고(가드 3종), 실패하면 단어 폴백, 기록으로 감사 | 프롬프트에 규정을 써 두고, 출력에 사후 필터 |
| 구조 | §3 다이어그램(일반 아키텍처 참조) | §4 다이어그램 |
| 장점 | 제어가능성 ★★★★★<br/>강건성 ★★★★★ | 기능적응성 ★★★★ (자유 문맥 코칭 잠재)<br/>기능정확성 ★★★ 잠재(문맥 반영) |
| 단점 | 기능적응성 ★★★ (코칭 시점/내용 상한)<br/>수행효율성 ★★★★ (가드/폴백 부담 경미) | 제어가능성 ★★ (개입 수단이 프롬프트 수정에 한정)<br/>강건성 ★★ (실패 시 판단 대체 불가) |
| Trade Off | 어긋난 출력은 규칙이 기각하고, 실패해도 단어 폴백으로 코칭이 이어진다<br/>교정/보완/안전전환의 개입 지점이 구조에 있고 사후 감사가 된다<br/>대신 코칭 내용의 자유도에 상한 | 판단+표현이 한 곳이라 구조가 단순하고, 문맥 풍부한 코칭 잠재<br/>대신 통제가 "LLM이 규정을 따른다"는 기대에 의존<br/>실패/오작동 시 갈아탈 판단 주체가 없다 |

### 5-1. QA 별점 종합 (8대 QA 중 관련 축)

| QA(품질속성) | (1안) 구조적 격리 거버넌스 | (2안) LLM 판단 위임 |
|---|:---:|:---:|
| 제어가능성 (AI 특화, 이 DP의 축) | ★★★★★ | ★★ |
| 강건성 (AI 특화) | ★★★★★ | ★★ |
| 설명용이성 (AI 특화, DP-01과 정합) | ★★★★★ | ★★ |
| 수행효율성 | ★★★★ | ★★★ |
| 기능적응성 (AI 특화) | ★★★ | ★★★★ |
| 기능정확성 (AI 특화) | ★★★★ | ★★★ (잠재, 미검증) |

- **결정축 = 개입 가능성(intervenability)**: 제어가능성의 정의가 "제때, 알맞게 개입할 수 있는 정도"이므로, 개입 지점이 구조에 존재하는 1안과 프롬프트 문구에 의존하는 2안의 차이가 이 축에서 가장 크게 벌어진다. 강건성 차이도 같은 뿌리다 — 실패했을 때 갈아탈 판단 주체가 있느냐 없느냐.
- **2안 기능적응성이 높은데 종합에서 앞서지 못하는 이유**: 자유로운 문맥 코칭의 잠재는 실질적 강점이다. 다만 그 자유도만큼 통제해야 할 표면이 넓어진다 — 판단이 모델 안으로 들어가면 검증/폴백/감사가 설 자리가 사라진다.
- **조건 의존성(공정한 평가)**: 별점은 이 DP의 결정 범위가 해당 QA에 미치는 영향을 이 과제 조건에서 평가한 것이라, 같은 QA 명칭이라도 DP마다 평가 대상 행위가 다르다(예: DP1의 기능적응성=규칙 밖 패턴 학습 능력, DP3의 기능적응성=경계 적응 지연). 이 별점은 *이 시스템의 조건*(작은 온디바이스 모델/실시간 음성/미가용 일상/안전 권고 포함)에 대한 평가다. **조건이 다르면 — 충분히 강한 모델, 서버에서 실행, 출력별 사람 검수 가능, 저빈도 상호작용 — 2안이 우선될 수 있다.**

## 6. 설계 결정 및 근거

### 6-1. 최종 채택 구조
**(1안) 규칙 확정 + LLM 표현 한정 아키텍처 = 구조적 격리 + 출력 가드 3종(형식/방향/숫자) + 단어 수준 폴백 + 안전 경로 분리 + HITL/HOTL/감사** 를 채택한다. 코칭의 판단(방향/안전/타이밍)을 LLM에 위임하지 않는다.

### 6-2. 채택 근거 (2안 대비)
- **개입할 곳이 구조에 있다.** 교정(가드 기각/설정), 보완(설정 토글/폴백), 안전전환(LLM 우회/단어 폴백)의 개입 지점이 구조에 존재하고 각각 자동으로 작동한다. 2안의 개입은 프롬프트 수정뿐이고, 그 효과는 보장되지 않는다.
- **약한 모델이라는 전제와 맞는다.** 작은 모델의 지시 이행 불안정은 문헌으로 확인된 조건이다. 1안은 그 기대가 깨져도 통제가 성립하고(출력 재검사+폴백), 2안은 그 기대 자체가 통제의 근거다.
- **실패해도 코칭이 이어진다(강건성).** 미가용/타임아웃이 일상인 온디바이스 환경에서, 1안의 최악은 "단어 수준 코칭"(기능 유지)이고 2안의 최악은 "코칭 중단"이다.
- **통제 작동을 데이터로 확인한다(감사).** 방향 기각/폴백 사유가 세션마다 기록돼 리포트에서 확인한다(HOTL). 2안은 판단 근거가 모델 내부라 감사가 입출력 대조 수준에 머문다.
- **DP-01과 서로 떠받친다.** 판단을 규칙에 두는 같은 구조가 설명의 충실함(DP-01)과 통제권(DP-02)을 동시에 만든다 — 두 정체성 QA가 한 설계에서 나온다.

### 6-3. 예상 질문
- **"프롬프트 엔지니어링을 잘하면 2안도 통제되지 않나?"** — 프롬프트 규정은 권고이지 강제가 아니다. 물론 2안에도 규칙 판정기를 병렬 검증기로 붙일 수는 있다 — 그러나 그 검증기가 곧 규칙 판정이고, 불일치 때 규칙을 따라야 하는 순간 1안 구조로 수렴한다. 2안 고유의 것은 "규칙 없이 LLM만 믿는 구간"인데, 그 구간이 통제되지 않는다.
- **"가드레일이 정상 문장까지 기각해 코칭이 굳지 않나?"** — 가능하다(과차단). 그래서 기각/폴백이 전부 기록되고, 기각률이 높으면 가드 기준을 데이터로 튜닝한다. 기각의 비용은 "덜 자연스러운 단어 수준 문구"이지 코칭 중단이 아니다.
- **"판단까지 LLM에 주면 더 똑똑한 코칭이 나오지 않나?"** — 규칙 집합 밖 상황에서의 문맥 코칭 잠재는 2안의 실제 강점이다. 다만 이 조건(작은 모델/실시간/안전 권고)에서는 그 잠재를 검증하고 통제하는 비용이 크다. 조건이 바뀌면(강한 모델+검수 루프) 재평가할 수 있다(§5-1 조건 의존성).

### 6-4. 보완 계획
- **가드 기준 필드 튜닝**: 방향 기각률/폴백 사유 분포(세션 기록)를 실주행 데이터로 모아 방향/숫자 검사 기준과 폴백 타임아웃을 조정한다.
- **제어 측정 지표**: 시뮬/단위테스트 층위 실측은 완료했다 — 방향위반/무방향 기각율 100%, 이동 한도 최대 9.97bpm(report-015 QA3). 잔여 = 실주행에서의 기각률/폴백 사유 분포 수집. 방향 검사의 알려진 비대칭(유지 의도는 금지어 목록 검사만)도 같은 기록으로 감시한다.
- **코칭 상황 확장**: 통제 구조를 유지한 채, 프롬프트에 담는 임무(트리거) 종류를 늘려 새로운 상황의 코칭을 확장한다 — 판단을 위임하지 않고 기능적응성 단점을 완화하는 방향이다.

## 부록 B. 용어 한 줄 사전
- **제어가능성(controllability)**: 제어 주체(사용자/규칙/운영)가 시스템 동작에 제때, 알맞게 개입할 수 있는 정도(ISO/IEC 25059). 강의 3유형 = 교정/보완/안전전환.
- **구조적 격리(architectural containment)**: 모델이 할 수 있는 일 자체를 좁혀 위험 표면을 줄이는 통제 — 프롬프트 지시보다 강한 층.
- **출력 가드레일**: 모델 출력을 시스템 규칙이 사후 검증/차단하는 장치. 이 시스템 = 형식 가드 + DirectionGuard(방향 일치 검증) + NumberGuard(숫자 무결성 — 출력 숫자 ⊆ 입력 사실).
- **폴백(fail-safe)**: LLM 경로가 실패/기각되면 단어 수준 문구로 바꿔 내보내는 무손상 전환 — 코칭 무중단.
- **HITL / HOTL**: 사람이 루프 안에서 라벨로 교정(HITL, 말하기 테스트) / 루프 위에서 설정과 사후 감사로 감독(HOTL, 설정 토글 + LLM 사용 기록).
- **지시 이행(instruction following)**: 모델이 프롬프트의 규정(형식/금지/방향)을 지키는 능력 — 작은 모델에서 불안정.
- **감사(audit)**: 통제가 실제로 작동했는지 기록으로 사후 확인하는 것 — 이 시스템은 모든 LLM 호출의 경로/기각/폴백 사유를 세션에 저장한다.
