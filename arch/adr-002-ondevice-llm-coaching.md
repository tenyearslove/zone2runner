# ADR-002 (DP2): On-device LLM 상황 코칭 생성 구조

- **날짜**: 2026-07-01
- **상태**: Accepted
- **결정자**: 성시원
- **보고서 매핑**: 설계 - Architectural Decision **DP2**

---

## 맥락

FR4는 Zone 2 판정 결과와 실시간 맥락(오르막/내리막, 페이스 변화, SPM, 날씨)을 반영한 코칭 멘트를 생성해 TTS로 출력할 것을 요구한다. 정해진 문구 반복이 아니라 상황에 맞는 자연스러운 안내가 목표다. 이 코칭 생성기는 다음 제약을 동시에 만족해야 한다.

- **QA4 제어가능성(코칭 방향 무결성)** — Zone 상태와 코칭 방향(가속/감속/유지/독려) 일치율 95% 이상 (결정 당시 구 QA1 기능정확성 항목 — 현 체계에선 QA4 제어가능성 소관)
- **QA6 수행효율성** — 상황 변화 감지부터 음성 출력까지 5초 이내
- **프라이버시/오프라인** — 러닝 중 네트워크 불안정, 개인 운동데이터 외부 전송 최소화 → 온디바이스 선호

---

## 결정

### 대안 비교

| 기준 | 대안 A (템플릿/규칙 문구) | 대안 B (On-device LLM 단독) | 대안 C (규칙 의도 + LLM 표현 + 출력 가드) |
|------|------|------|------|
| 자연스러움 | 낮음 (고정 문구) | 높음 | 높음 |
| 코칭 방향 정확성 (QA4 제어가능성) | 보장 쉬움 | 보장 어려움 (환각/이탈) | 규칙이 방향 결정 → 보장 |
| 응답 지연 (QA6 수행효율성) | 즉시 | 느릴 수 있음 | 관리 가능 (프롬프트 최소화) |
| 프라이버시/오프라인 | 문제없음 | 온디바이스로 확보 | 온디바이스로 확보 |
| 구현 복잡도 | 낮음 | 중 | 높음 |

### 대안 A: 템플릿/규칙 기반 문구

Zone 상태 + 맥락 조합마다 미리 작성한 문구를 선택한다.

- 장점: 빠르고 결정론적이며 검증이 쉽다.
- 단점: 계획서가 명시적으로 피하려는 "정해진 문구 반복"이다. 맥락 조합이 늘면 문구 관리가 폭발하고 자연스러움이 떨어진다.

### 대안 B: On-device LLM 단독 생성

상황을 프롬프트로 넣어 소형 온디바이스 LLM이 멘트를 자유 생성한다.

- 장점: 자연스럽고 맥락 반영이 풍부하다. 온디바이스라 프라이버시/오프라인이 확보된다.
- 단점: 출력이 불안정해 **코칭 방향이 뒤집힐 위험**(예: 초과 상태인데 더 뛰라고)이 있어 QA4 제어가능성(코칭 방향) 보장이 어렵다. 지연/자원 부담과 검증 곤란.

### 대안 C: 규칙이 의도 결정 + LLM이 표현 + 출력 가드 *(채택)*

```
[규칙]  Zone 상태 + 맥락 → 코칭 의도 결정 (가속/감속/유지/독려)   ← 방향은 규칙이 확정 (QA4 제어가능성)
   │
[LLM]   의도 + 구조화된 맥락 → 자연스러운 한 문장 생성            ← 표현만 LLM (자연스러움)
   │
[가드]  방향 일치 검증 / 길이 / 금지표현 / 쿨다운                 ← 이탈 출력 차단 (QA4 제어가능성)
   │
[TTS]   음성 출력
```

- 장점: 코칭 **방향은 규칙이 결정**하므로 QA4 제어가능성을 보장하면서, 표현은 LLM이 담당해 자연스러움을 얻는다. 프롬프트를 의도/맥락으로 최소화해 지연(QA6 수행효율성)을 관리하고, 온디바이스로 프라이버시/오프라인을 확보한다.
- 단점: 규칙 계층 + LLM + 가드로 구현 복잡도가 올라간다.

### 채택: 대안 C

QA4 제어가능성(코칭 방향 정확성)은 LLM 단독(B)으로 보장하기 어렵고, 템플릿(A)은 자연스러움이라는 과제 핵심 가치를 포기한다. "방향은 규칙, 표현은 LLM, 출력은 가드"가 두 요구를 모두 만족하는 유일한 조합이다.

## 결과

- On-device LLM의 실체는 Galaxy S26 Ultra의 온디바이스 AI(예: Gemini Nano / AICore) 활용을 상정한다. **구체 모델/런타임 선정과 성능 튜닝은 구현 시 확정**한다(유보).
- 코칭 입력 컨텍스트, 프롬프트 구조, 출력 가드 규칙, TTS 연동의 상세는 `spec/spec-005-llm-coaching-generation.md`에서 다룬다.
- PoC 1단계에서는 LLM 호출을 stub(템플릿 또는 소형 로컬 호출)으로 두고 파이프라인 흐름부터 검증할 수 있다(QA5 테스트가능성).
