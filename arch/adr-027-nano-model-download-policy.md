# ADR-027: Gemini Nano 모델 다운로드 정책 전환 — 첫 실행 자동 다운로드 + 진행 표시 + 설정 상태

- **상태**: Accepted (2026-07-23) / Implemented
- **관련**: adr-007(온디바이스 LLM 런타임 검증 — "AVAILABLE일 때만 사용, 다운로드 트리거 안 함" 정책의 원 출처, **이 ADR로 그 정책만 부분 개정**), adr-026(Nano Rewriting/Summarization), spec-005(LLM 코칭 예외 처리), spec-021(앱 설정), spec-027(LLM 사용 감사 기록)

## 맥락

실기기(폰) 세션의 LLM 사용 감사 기록(spec-027)에서 코칭 전 호출이 `rule(LLM 미가용)`로 폴백됨을 확인했다. 기기에 AICore는 설치돼 있으나 ML Kit GenAI 기능 모델이 다운로드되지 않은 상태(DOWNLOADABLE)로 추정되며, 현행 정책(adr-007: AVAILABLE일 때만 사용, 다운로드 트리거 안 함)에서는 **사용자가 개입할 방법이 없어 영구히 규칙 폴백만 탄다.** 사용자 결정: 첫 실행 시 모델이 없으면 다운로드를 진행하고, 진행률을 보여주고, 설정에서 상태를 확인할 수 있어야 한다.

adr-007이 다운로드를 트리거하지 않았던 이유는 (a) 검증 단계라 기기 상태를 바꾸지 않으려는 보수성, (b) 예기치 않은 대용량 다운로드 방지였다. 기능이 실사용 단계로 온 지금은 (a)가 소멸했고 (b)는 진행 표시/폴백 유지로 관리 가능하다.

## 대안 비교

| | A. 현행 유지 (트리거 안 함) | **B. 첫 실행 자동 다운로드 + 진행 표시 + 설정 상태 (채택)** | C. 사용 시점 온디맨드 다운로드 |
|---|---|---|---|
| 동작 | AVAILABLE일 때만 사용. DOWNLOADABLE이면 영구 규칙 폴백 | 홈 진입 시 상태 확인, DOWNLOADABLE이면 자동 다운로드 시작(진행률 배너). 설정에 기능별 상태 + 수동 다운로드 | 코칭/요약 호출 시점에 DOWNLOADABLE이면 그때 다운로드 |
| 장점 | 구현 0, 기기 상태 불변 | 사용자가 개입 없이 LLM 표현이 활성화됨. 진행/상태가 보여 통제 가능(제어가능성). 다운로드 중에도 규칙 폴백 유지(무중단) | 필요할 때만 받음 |
| 단점 | LLM 기능이 사실상 죽은 채 유지될 수 있음(이번 실기기 사례) | 첫 실행 시 네트워크 사용(수백 MB 가능 — AICore가 관리) | 러닝 중 다운로드가 시작돼 대역폭/배터리 소모, 세션 중 상태 전이로 진단 어려움 |
| 판단 | 실사용 단계에 부적합 | **채택** — 다운로드는 세션 밖(홈/설정)에서만, 사용 시점 정책(AVAILABLE만 사용)은 불변 | 세션 중 부작용이 커서 기각 |

## 결정

**B 채택.**
- **다운로드 트리거는 세션 밖에서만**: 홈 화면 진입 시 기능(톤 재작성/요약/자유 생성) 상태를 확인하고, DOWNLOADABLE이면 다운로드를 시작해 배너로 진행률을 보여준다. 설정 화면에 기능별 상태(사용 가능/다운로드 필요/다운로드 중/미지원)와 수동 다운로드를 둔다.
- **사용 시점 정책은 불변**: LlmCoach/NanoRewriter/NanoSummarizer는 여전히 AVAILABLE일 때만 사용하고 아니면 무손상 폴백한다(adr-026). 다운로드 중에도 코칭은 규칙으로 무중단.
- **정직한 표시**: UNAVAILABLE(기기 미지원)이면 그렇게 표시하고 다운로드를 권하지 않는다. 실패도 상태로 남긴다.
- 구현 = `coaching/NanoModelManager.kt`(상태/다운로드 단일 책임) + HomeActivity 배너 + SettingsActivity "AI 모델" 카드. API = ML Kit GenAI `checkFeatureStatus`/`downloadFeature(DownloadCallback)`(Rewriting/Summarization), `checkStatus`/`download(): Flow<DownloadStatus>`(Prompt).

## 결과

- 모델 미다운로드 기기에서 사용자가 아무것도 몰라도 첫 홈 진입 시 준비가 시작되고, 준비 전/실패 시엔 기존과 동일하게 규칙 코칭이 나간다(강건성 불변).
- 제어가능성 관점: 모델 준비 상태가 보이고(설정), 다운로드가 언제 일어나는지 예측 가능(홈/설정에서만)하며, 감사 기록(spec-027)으로 LLM 채택 여부를 사후 확인한다.
