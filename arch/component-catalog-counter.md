# 카운터 아키텍처 컴포넌트 카탈로그 (블랙박스 + 사후 설명)

- **상태**: 검토용 v1 (2026-07-16). 설명용이성 DP의 **대안(설계 B)** 아키텍처를 우리 것과 **같은 방식**으로 식별/서술한다. 이는 우리가 구현한 게 아니라, 공정 비교를 위한 **가정 설계**(산업계 주류 방식)다.
- **도식**: `arch/diagrams/04-counter-component-cnc.png`(상세) + `04b-counter-component-cnc-simple.png`(축약).
- **핵심 대비(우리 vs 카운터)**: 우리는 학습이 운영 안 **온라인 개인화**로 축소됐지만, 카운터는 **오프라인 학습 파이프라인(AI Development 완전판)**을 갖고, 모델 서빙이 **불투명(블랙박스)**이며, 설명이 결정과 분리된 **사후 근사**다.

---

## A. 추론 서비스 (Inference Service)

### A1. 데이터 준비
- **표준 매핑**: 데이터 준비 / **책임**: 전처리/정규화 + 최근 N초 이력 윈도우를 만들어 시계열 모델 입력을 구성. **우리와 차이**: 우리는 파생 특징(지속심박/추세)이 곧 판정 재료지만, 여기선 원신호 이력을 모델에 통째로 넣는다.

### A2. 입력 가드레일
- **표준 매핑**: 입력 가드레일 / **책임**: 이상값 필터(우리와 동일하게 필요).

### A3. 블랙박스 결정 모델
- **표준 매핑**: 모델 서빙(블랙박스) / **책임**: 학습된 NN/부스팅이 신호를 먹고 **판정/코칭을 직접 출력**. 내부 로직이 다수 파라미터에 분산돼 결정 경로를 직접 읽기 어렵다. **우리와 차이**: 우리 모델 서빙은 규칙 판정 + 해석가능 베이지안 경계 + 분석 엔진으로 **투명**하다.

### A4. 개인 어댑터
- **표준 매핑**: 모델 서빙(개인화) / **책임**: 사전학습 모델 위에 얇은 층을 개인 데이터로 미세조정. **우리와 차이**: 우리는 사전학습 없이 온라인 베이지안으로 μ/σ를 직접 추정.

### A5. 출력 가드레일 (사후 클리핑)
- **표준 매핑**: 출력 가드레일 / **책임**: 모델이 생리를 모르므로, 출력값을 **사후에 범위로 자르는** 수준의 방어. **우리와 차이**: 우리는 방향 잠금(DirectionGuard) + 안전(SafetyGuard)이 구조 안에 있다.

## B. 설명 서비스 (사후 / post-hoc)

### B1. 사후 설명기
- **표준 매핑**: 설명 서비스(사후) / **책임**: 결정이 난 **뒤** SHAP/LIME 기여도나 LLM 이유생성으로 근거를 만든다. **원모델의 근사**라 충실도(진짜 이유대로인지)가 별도로 보장되지 않는다. **우리와 차이**: 우리 설명 서비스는 실제 계산의 **재생(replay)**이라 구조적으로 충실.

## C. 분석 서비스 (Analysis)
- 서빙 로그 → 모니터링 지표(우리와 유사). 모니터링이 Retraining 트리거로 연결.

## D. 운영 서비스 (Operation)
- Operation UI(attribution 숫자/LLM 서사) + HITL/HOTL 제어. **우리와 차이**: 결정이 불투명해 사용자가 **무엇을 정정할지 짚기 어렵다**(제어가능성 약화).

## E. AI Development Subsystem (완전판 — 오프라인 학습) ★ 최대 대비
표준의 개발 서브시스템이 **전부 실체화**된다(우리는 이 부분이 비어 있음):
- **데이터셋 구축 → Data Lake**: 공개데이터(FitRec 등) + 수집 세션.
- **Model Construction(오프라인 학습)**: 데이터 준비 → 입력 가드레일 → **모델 학습(대량, 오프라인)** → 출력 가드레일. Feature Store / Model Artifact / ML Metadata.
- **모델 테스팅**: 홀드아웃 테스트셋 검증 — **단 우리 도메인엔 참값이 없어** 이 검증이 우리 사용자 정확도를 보장하지 못한다.
- **모델 등록/승격 → Model Registry / Container Registry → 배포**.
- **Retraining**: 운영 모니터링 → 재학습 데이터셋 추출 → Data Lake(오프라인 재학습 루프).

## 요약 — 무엇이 다른가

| 축 | 우리(설계 A) | 카운터(설계 B) |
|---|---|---|
| 모델 서빙 | 투명(규칙+베이지안+분석) | 블랙박스(NN/부스팅) |
| 설명 | 실제 계산 재생(충실) | 사후 근사(충실 별도 보장) |
| 학습 | 운영 안 온라인 개인화 | 오프라인 대량 학습 파이프라인(완전판) |
| 개발 서브시스템 | 거의 비어 있음 | 전부 실체화 |
| 출력 가드레일 | 방향 잠금+안전(구조 내) | 사후 클리핑(생리 모름) |
| 제어가능성 | 반박/정정 쉬움 | 결정 불투명, 정정 지점 모호 |
