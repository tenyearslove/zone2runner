# ADR-020: 심박 예측을 시뮬-학습 MLP에서 생리 ODE + 온라인 개인화로 재설계

- 상태: 채택(2026-07-06 구현 완료 — HrOdeModel, 테스트 66건 통과, τ 온라인 추정 30→19.9 수렴 검증)
- 날짜: 2026-07-06
- 관련: adr-013(판정/예측 역할 분리), adr-016(AI 방법 선택), adr-019(예측 온라인 보정), spec-014(심박 예측 NN), spec-018(온라인 개인 보정)
- 대체 대상: spec-014의 "심박 예측 = 시뮬 데이터로 지도학습한 MLP" 부분

## 맥락 / 문제

현재 심박 예측(DP1)은 **물리 시뮬레이터가 생성한 데이터로 지도학습한 MLP**(7→32→16→2)다. 그런데
시뮬레이터의 심박 생성 자체가 **손으로 쓴 2상 상미분방정식(ODE)**이다(`ml/simulator.py`):

```
hr_lag = hr + (effort_hr - hr) * (dt / τ)          # 1차 지연(mono-exponential on-kinetics)
drift += (drift_scale*excess - drift) * (dt/τ_d)   # 카디악 드리프트
hr = hr_lag + drift + noise
```

즉 **MLP는 우리가 이미 쓴 방정식을 흉내 내도록 증류(distill)된 대리모델(surrogate)**이다. 결과적으로:

1. **순환적/공허함**: MLP는 ODE가 인코딩하지 않은 것을 배울 수 없다. "시뮬 데이터로 지도학습"은
   사실상 "우리가 쓴 식을 근사"다. 보고된 RMSE 14/20bpm은 **실사람 정확도가 아니라 시뮬 재현 충실도**
   (미학습 파라미터 추출에 대한)일 뿐이다.
2. **과잉주장**: 인증 관점에서 "지도학습 신경망"이라는 설명이 실체(대리모델)를 오도한다.
3. **손해**: 원 ODE보다 근사오차만 더해지고 물리적 투명성은 잃는다. 역질의(페이스 추천)도 ODE면
   해석적으로 되는 걸 NN 스윕으로 한다.

**진짜 학습은 이미 따로 있다** — 실주행에서 개인 잔차를 배우는 온라인 보정(adr-019, LMS). 이게 실데이터
기반의 정당한 ML이다. 문제는 그 아래 "기본 예측"이 가짜 학습이라는 점이다.

## 문헌 조사 (사용자 요청 — "논문을 따르자")

운동 중 심박 예측의 최신 접근은 **블랙박스 NN이 아니라 생리 ODE + NN 하이브리드**다.

- **Apple / npj Digital Medicine 2023 (Nazaret 외, Apple Heart & Movement Study)** — 운동 심박을 **ODE**로 기술:
  `dHR/dt`가 수요 D(t)를 향해 완화되고, `dD/dt = B·f(z,I)·g(W)·h(t) − D`. 여기서 f=강도→수요(속도/경사/케이던스),
  g=날씨(고온 시 HR +10%), h=피로/드리프트. **NN은 HR을 직접 예측하지 않고 개인 표현 z로 ODE 파라미터를
  개인화**한다. 실워크아웃 270,707건 학습, 워크아웃당 **중앙 오차 6.1bpm**.
- **MDPI Electronics 2024 "Hybrid Approach to Modeling HR Response"** — 생리 ODE + NN 성분,
  실착용 데이터에서 **MAE 5.2 / RMSE 8.1bpm**.
- **rikluost/athlete_hr_predict (Garmin fit, LSTM)** — 실데이터 LSTM. persistence 대비 15~25초 구간 오차 절반.
- 공통점: **(1) 물리 ODE를 골격으로 두고, (2) 학습은 실데이터로, (3) NN은 개인 파라미터화에만** 쓴다.
  우리가 "시뮬로 HR 자체를 지도학습"한 것과 정반대 구조다.

## 대안 비교

### 대안 A — 생리 ODE 기본 예측 + 온라인 개인 파라미터화 (★추천)
- 블랙박스 MLP를 **명시적 생리 ODE**로 교체: 페이스/경사 → 수요(정상상태 HR) → 1차 지연(τ) 완화 + 드리프트
  + 기온 변조. 30/60초 예측 = ODE 전방적분. **문헌(Apple/Nature, MDPI) 골격의 경량판.**
- 개인화 = 실주행에서 개인의 **τ / 정상상태 이득 / 드리프트**를 온라인 추정(기존 adr-019 학습기 재사용).
  이게 Apple의 "z가 ODE를 개인화"의 단일사용자·온디바이스 경량 대응(CNN 인코더 대신 재귀추정).
- 역질의(페이스 추천) = ODE 정상상태 해석적 역산.
- 장점: 투명/생리근거/문헌정합, 순환 제거, **실데이터 개인화가 학습의 중심**(정직), 온디바이스 초경량,
  "AI≠NN"(adr-016) 논지를 오히려 강화(가짜 NN 제거). 시뮬 ODE가 곧 제품 기본모델 → 이중관리 해소.
- 단점: 기본 ODE 파라미터는 학습이 아니라 생리 prior로 설정(정직하게 "모집단 prior"로 명시). 첫 세션엔
  개인화 전이라 모집단값.

### 대안 B — 실 공개데이터셋으로 MLP/LSTM 지도학습
- athlete_hr_predict(Garmin) 등 실데이터로 진짜 지도학습.
- 장점: 명실상부 실데이터 supervised. 단점: 단일선수/소수 도메인편향, 신규 사용자엔 결국 개인화 필요,
  온디바이스 LSTM 비용/복잡도, 라이선스, 인증 일정 대비 과투자. 여전히 개인화 계층은 별도 필요.

### 대안 C — 현행 유지 + 서술만 "대리모델"로 정정
- 코드 그대로, 백서에서 "시뮬 대리모델"이라 정직화.
- 장점: 무공수. 단점: 지적으로 약하고 문헌 미정합. 사용자가 이미 문제를 간파 — 부적절.

## 결정 (제안)

**대안 A 채택.** 심박 예측의 기본을 **생리 ODE**로 두고(모집단 생리 prior), 실주행에서 개인의 ODE
파라미터(τ/이득/드리프트)를 **온라인 추정**해 개인화한다. 시뮬-학습 MLP(`hr_dynamics.json` + `HrDynamics`)는
폐기하고, 시뮬레이터의 ODE를 제품의 기본 예측 모델로 승격(단일 소스화)한다. 온라인 개인 보정(adr-019)은
잔차 보정이 아니라 **ODE 파라미터 개인화**로 재정의해 계속 쓴다.

- adr-016 관점 재확인: "예측=NN"이라는 전제 자체를 문헌 근거로 교정한다 — **예측 = 생리 ODE(백본) +
  개인 파라미터 온라인 학습**. NN은 여기서 필수가 아니었다(가짜 부가가치). 이는 "문제에 맞는 도구" 원칙의
  더 강한 실증이다.
- 실데이터(대안 B)는 **후속 검증 경로**로 남긴다: 필드 로그(FIELD_TEST/spec-012)가 쌓이면 ODE 파라미터
  분포/정확도를 실데이터로 채점(대안 A를 반증/보정하는 용도), 필요 시 부분 도입.
