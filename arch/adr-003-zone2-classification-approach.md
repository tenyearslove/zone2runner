# ADR-003 (DP1): 개인화 Zone 2 실시간 판정 방식

- **날짜**: 2026-07-01
- **상태**: Accepted
- **결정자**: 성시원
- **보고서 매핑**: 설계 - Architectural Decision **DP1**

---

## 맥락

이 과제의 주 목적은 **개인별 신체능력에 맞는 Zone 2 판정**이다. 여기서 "판정"과 "개인화"의 관계를 먼저 정리한다.

- **판정(judgment)**: 지금 심박수가 내 Zone 2 경계 안이냐를 결정하는 행위. 임계값 비교 + 히스테리시스로, 그 자체는 단순 연산이다.
- **경계 산정 = 개인화(personalization)**: "내 Zone 2 경계가 실제로 몇 bpm이냐"를 내 데이터로 알아내는 것. **이것이 AI이고 이 과제의 핵심이다.**
- 공식(HRR)만 쓰면 나이/안정심박만 반영해 같은 나이면 같은 Zone을 준다(약한 개인화). 실제 심폐지구력 차이를 반영하려면 개인 데이터로 경계를 학습해야 한다.

즉 "AI로 Zone 2를 판정한다"는 것은 곧 개인화된 경계로 판정한다는 뜻이며, 판정과 개인화는 별개 기능이 아니다.

FR3은 수집된 심박수, 페이스, Cardiac Drift로 현재 Zone 2 상태(진입 / 유지 / 이탈)를 실시간 판정할 것을 요구한다. 이 판정 로직은 세 가지 품질 속성과 직접 충돌하거나 이를 달성해야 한다.

- **QA2 강건성** — 40~220 bpm를 벗어나는 이상값에도 Zone 1~5 범위 내 출력 유지율 100%
- **QA3 적응성** — 누적 데이터 기반으로 개인별 Zone 2 구간을 지속 보정
- **C02 콜드스타트** — 데이터가 충분히 누적되기 전에는 공식 기반 추정값을 사용

판정 방식을 규칙 기반으로 갈지, 학습 모델로 갈지, 둘을 결합할지 명확히 결정해야 한다.

## 결정

### 대안 비교

| 기준 | 대안 A (HRR 공식 규칙) | 대안 B (경량 ML 분류기) | 대안 C (규칙 + 개인화 하이브리드) |
|------|------|------|------|
| 콜드스타트 (C02) | 즉시 동작 | 학습 데이터 없이는 불가 | 즉시 동작 (공식 baseline) |
| 강건성 (QA2) | 범위 clamp/reject 용이, 100% 보장 쉬움 | 이상값에 비정상 출력 위험 | 규칙 가드가 방어, 100% 보장 |
| 적응성 (QA3) | 없음 | 재학습으로 가능 | 개인화 레이어로 자연 충족 |
| 설명가능성 | 높음 | 낮음 (블랙박스) | 높음 (규칙 경계 + 보정값) |
| 온디바이스 부담 | 없음 | 추론 비용 발생 | 낮음 (경량 통계 업데이트) |
| 테스트 용이성 (QA5) | 높음 | 낮음 (재현 어려움) | 높음 |

### 대안 A: HRR 공식 규칙 기반 임계값 판정

FR1에서 산정한 개인 Zone 2 구간 `[lower, upper]`에 현재 심박수가 들어오는지 임계값으로 비교한다. 이동평균과 히스테리시스로 경계 떨림을 방지한다.

- 장점: 결정론적이라 검증·설명이 쉽고, 이상값을 clamp/reject하기 용이해 QA2 달성이 명확하다. 학습 데이터가 필요 없어 콜드스타트가 없다.
- 단점: `maxHR = 220 - age` 등 공식은 개인차 오차가 크고(±10 bpm 수준), Cardiac Drift와 페이스 맥락을 반영하지 못한다. **QA3 적응성을 자체적으로 충족할 수 없다.**

### 대안 B: 경량 온디바이스 ML 분류기

HR, HR 변화율, 페이스, Cardiac Drift를 feature로 받아 Zone 상태를 분류하는 경량 모델을 온디바이스에서 실행한다.

- 장점: 다변량 맥락을 반영하고, 페이스-HR 관계와 Drift를 학습해 정밀한 판정 여지가 있다.
- 단점: 라벨링된 학습 데이터가 필요해 **콜드스타트(C02)와 정면 충돌**한다. 블랙박스 특성상 이상값 입력 시 출력을 보장할 수 없어 **QA2 강건성 보장이 어렵고**, 재현·검증이 힘들어 QA5와도 상충한다. 초기 정확도가 낮다.

### 대안 C: 규칙 baseline + 경량 개인화 하이브리드 *(채택)*

규칙(HRR 공식)이 안전한 경계 판정과 이상값 방어를 담당하고, 그 위에 개인화 레이어가 누적 데이터로 개인 Zone 2 경계를 Bayesian 업데이트하며, 페이스·Cardiac Drift는 보조 신호로 활용한다.

```
[이상값 가드]  40~220 bpm 밖 → reject, 범위 내 clamp        ← QA2
      │
[규칙 baseline]  공식 산정 [lower, upper] + 히스테리시스     ← C02 콜드스타트
      │
[개인화 레이어]  누적 데이터로 개인 경계 Bayesian 보정        ← QA3 적응성
      │            (페이스-HR, Cardiac Drift 보조 신호)
      ▼
  진입 / 유지 / 이탈 판정
```

- 장점: 데이터가 없으면 공식 baseline으로 즉시 동작하고(C02), 누적되면 실측 기반으로 경계가 이동한다(QA3 시나리오와 정확히 일치). 규칙 가드가 이상값을 방어해 QA2를 보장하고, 판정 근거가 설명 가능하며 테스트가 쉽다(QA5). 경량 통계 업데이트라 온디바이스 부담이 낮다.
- 단점: 두 레이어 조합으로 구현 복잡도가 올라가고, 규칙 경계와 개인화 보정 결과가 충돌할 때 우선순위 규칙이 필요하다.

### 채택: 대안 C

QA2(강건성)는 규칙 가드로, QA3(적응성)는 개인화 레이어로 각각 자연스럽게 달성되고, 콜드스타트(C02) 문제를 공식 baseline이 해결한다. 순수 ML(B)은 콜드스타트/강건성/검증성에서 과제 QA와 충돌하고, 순수 규칙(A)은 중요도 9인 QA3 적응성을 충족하지 못한다.

**레이어별 위상**: 개인화 레이어가 이 설계의 핵심(주 목적)이고, 규칙 baseline은 데이터가 없을 때의 콜드스타트 안전장치, 이상값 가드는 강건성 보호막이다. 즉 세 레이어는 대등한 병렬이 아니라 "개인화가 본체, 규칙/가드가 받침대" 구조다. 개인화 모델의 상세(사전분포, 업데이트 규칙, Cardiac Drift의 증거 활용)는 `spec/spec-004-zone2-personalization.md`에서 다룬다.

**판정기와 순수 ML 재검토**: 위에서 순수 ML(대안 B)을 뺀 이유는 콜드스타트/라벨/강건/검증 문제였다. 이후 이 하이브리드가 그 blocker들을 제거한다 — 라벨은 물리 시뮬레이터(spec-004 §8)로 생성, 콜드스타트는 규칙 폴백으로 처리, 강건성은 노이즈 증강 학습 + 규칙 가드로 확보. 따라서 다신호 비선형 정확성(QA1/85%)을 위해 판정기 자체는 다변량 MLP로 구현하며, 그 결정은 `arch/adr-005-zone2-classifier-nn.md`(DP4)에서 QA 근거와 함께 다룬다. 규칙/개인화는 여전히 prior/폴백/가드/정규화로 남는다.

### baseline 공식과 안정시심박(RHR) 확보

규칙 baseline은 FR1대로 **HRR(Karvonen)** 을 1순위로 사용한다. HRR은 안정시심박(RHR)이 필요하므로, RHR을 정확도/자동화 순으로 확보하는 사다리를 두고 실패 시 아래로 내려간다.

| 순위 | 소스 | 획득 방식 |
|:---:|------|------|
| 1 | Samsung Health 안정시심박 기록 | Phone에서 Samsung Health Data SDK(집계/이력)로 조회. 수면 기반 실측 |
| 2 | 온보딩 측정 | Watch Sensor SDK로 3~5분 안정 상태 HR 측정 후 안정값 채택 |
| 3 | 수동 입력 | 사용자가 아는 RHR 직접 입력 |
| 4 | %HRmax 폴백 | RHR 없이 `220-age` 기반 %HRmax 공식. 나이만 있으면 항상 동작 |

- **RHR은 실시간 스트림이 아니라 집계 데이터**이므로, ADR-001에서 실시간 스트림 불가로 배제된 Samsung Health Phone API가 여기서는 1순위 소스가 된다. Watch 없이 Phone만으로도 RHR 확보가 가능하다.
- **초기 RHR의 부정확함은 개인화 레이어가 흡수한다.** RHR/폴백값은 완벽한 초기값이 아니라 개인화 Bayesian 사전분포(prior)의 출발점일 뿐이며, 누적 데이터로 Zone 2 경계가 실측 기반으로 이동한다(QA3). RHR을 전혀 못 얻어도 인구통계 기본값을 prior로 두고 자가보정된다.

## 결과

- FR3의 "경량 온디바이스 AI 모델"은 무거운 신경망이 아니라 **규칙 가드 + Bayesian 개인화 레이어**로 구체화된다. 이 경량 학습 레이어가 QA3 시나리오의 "Bayesian 업데이트"와 직접 대응한다.
- 개인화 레이어의 구체적 통계 모델(사전분포, 업데이트 규칙, 5회 누적 기준)은 별도 Spec에서 상세화한다 → `spec/spec-004-zone2-personalization.md` 작성 필요.
- RHR 확보 사다리의 상세(Samsung Health Data SDK 레코드명/권한, 온보딩 측정 UX, 폴백 트리거 조건)는 FR1 프로필 입력 Spec에서 구체화한다. adr-003은 "HRR 우선 + %HRmax 폴백" 방향만 확정한다.
- 규칙과 개인화 결과 충돌 시 **규칙 가드가 항상 우선**(안전/강건성 우선)한다는 원칙을 구현 시 명시한다.
- Zone 2 판정 모듈은 HR 소스와 분리된 순수 함수 형태로 설계해 Mock HR로 독립 검증이 가능하도록 한다(QA5).
