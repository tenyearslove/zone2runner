# ADR-023: 워치 순수 뷰어화 - 폰이 표시 존까지 판정해 푸시, 표시 존은 순간심박+히스테리시스

- **상태**: Accepted (2026-07-07 사용자 승인)
- **날짜**: 2026-07-07
- **결정자**: 사용자 + Claude
- **대체 대상**: adr-022(워치가 폰이 보낸 지속심박+경계로 존을 "재계산"하는 미러 방식)
- **관련**: adr-013(판정/예측 역할 분리), spec-010(워치 대시보드)

## 맥락

adr-022 적용 후에도 실주행에서 폰(오렌지)/워치(레드) 존 색이 어긋났다. 원인은 데이터가 아니라 **판정 규칙이 두 곳에 존재**하는 것: 폰은 초과를 3단계 판정(미달/유지/초과, 초과는 항상 주황)으로, 워치는 폰이 보낸 값으로 5존(Z3 노랑/Z4 주황/Z5 빨강)을 "재계산"해 그린다. 같은 입력이라도 색 매핑이 다르면 모순으로 보인다. 또 존 색은 60초 평균 기준인데 화면의 큰 숫자는 순간심박이라, 숫자와 색이 따로 노는 2차 혼란도 있다.

사용자 확정 전제:
1. 폰/워치 모두 Z1~Z5 5구간, 구간별 동일 색.
2. 워치 게이지의 색 영역 길이는 고정(등폭), 폰 밴드는 심박 범위에 비례해 가변 - 색만 같으면 됨.
3. **표시 존 판정은 순간심박 기준**(화면 숫자와 색이 일치해야 함). 코칭/통계/개인화는 60초 평균 유지(사용자 확정).
4. **모든 판단은 폰, 워치는 디스플레이+입력 전달만**. 폰 신호 두절 시 워치는 존 미표시(순수 뷰어, 자체 폴백 판정 삭제 - 사용자 확정).
5. 토크테스트 설문 타이밍 판단도 폰으로 이관(사용자 확정).

## 결정

### 대안 비교

| 기준 | A: adr-022 유지 + 색 매핑만 통일 | B: 폰이 표시 존 확정 푸시, 워치 무로직 (채택) | C: 색 통일 + 판정은 60초 평균 유지 |
|------|------|------|------|
| 판정 로직 위치 | 폰+워치 2곳(재계산) | 폰 1곳 | 폰+워치 2곳 |
| 불일치 가능성 | 색 규칙이 어긋나면 재발 | 구조적으로 0(워치는 받은 존을 그대로 칠함) | 색은 일치, 숫자-색 괴리 지속 |
| 화면 숫자와 존 색 일치 | 불일치(색은 60초 평균) | 일치(순간심박+히스테리시스) | 불일치 |
| 워치 코드 | Zones 판정 유지 | Zones 판정/폴백/zones 동기화 삭제 | Zones 판정 유지 |
| 폰 두절 시 워치 | 자체 폴백 판정(불일치 원천) | 존 미표시 "폰 동기화 중" | 자체 폴백 판정 |

### 대안 A: adr-022 유지 + 색 매핑만 통일
워치가 계속 지속심박+경계로 존을 재계산하되, 폰의 색 체계를 5존으로 맞춘다.
- 장점: 변경 최소, 페이로드 그대로.
- 단점: 판정 규칙(구간 분할식, 히스테리시스)이 두 곳에 남아 미세 불일치가 영구히 재발 가능. "워치 무로직" 원칙 위배.

### 대안 B: 폰이 표시 존까지 확정해 푸시, 워치는 무로직 뷰어 (채택)
폰이 순간심박 기준(히스테리시스 포함)으로 표시 존을 확정하고 `/run/live`로 **존 인덱스(1~5) + 존 내 위치(0~1) + 순간심박**을 매초 푸시. 워치는 계산 없이 받은 존 색을 칠하고 등폭 게이지의 해당 세그먼트 안에 마커를 놓는다.
- 장점: 판정이 폰 한 곳 - 불일치가 구조적으로 불가능. 화면 숫자(순간심박)와 존 색이 항상 일치. 워치에서 Zones 판정/로컬 폴백/`/zones` 동기화 삭제로 코드 축소. adr-022가 대안 3(존 인덱스 푸시)을 기각한 사유였던 "게이지 연속 위치 재현 불가"는 등폭 세그먼트 확정 + 존 내 위치 전송으로 소멸.
- 단점: 폰 두절 시 워치는 존을 못 그림(전제상 허용). 표시 존과 코칭 판정(60초 평균)의 기준이 서로 다름 - 화면은 Z3인데 코치는 침묵할 수 있음(코칭은 간헐적이라 체감 모순 약함, 의도된 분리).

### 대안 C: 색 체계만 통일하고 판정 기준은 60초 평균 유지
- 장점: 코칭/표시가 한 기준, 색 안정적.
- 단점: 화면의 순간심박 숫자와 존 색이 계속 따로 놈 - 이번 혼란("139인데 레드?")의 절반이 미해결. 사용자가 명시적으로 기각.

### 채택: 대안 B
"두뇌는 폰, 워치는 뷰어" 원칙을 완성해 불일치를 원천 제거하고, 표시 존을 순간심박 기준으로 바꿔 화면 숫자와 색을 일치시킨다.

## 세부 설계

- **표시 존 판정(폰)**: 순간심박(OutlierGuard 정제값) 기준 5존. 경계 근처 깜빡임 방지 히스테리시스 - 존 변경은 새 존 경계를 2bpm 이상 넘거나 3초 연속 유지 시에만(정확 수치는 spec에서 확정).
- **역할 분리 유지(adr-013 연장)**: 음성 코칭 타이밍, zone2Pct 통계, Bayesian 개인화, 토크테스트 트리거는 기존대로 60초 지속심박 기준. 표시 존과 별개.
- **페이로드**: `/run/live` = "순간심박,존인덱스(1~5),존내위치(0~1000 정수),코칭존플래그" 형태로 교체(정확 스키마는 spec).
- **워치 삭제 대상**: `Zones.kt` 존 판정식, `WearRunActivity` 로컬 폴백 분기, `ZoneSyncService`/`/zones` 경로. 신선도(8초) 초과 시 존 미표시 "폰 동기화 중"(심박 숫자는 회색으로 계속 표시).
- **토크테스트**: 타이밍 판단(존 상승 20초 유지/10분 폴백)을 폰으로 이관, 폰이 워치에 "설문 표시" 명령 전송. 워치는 설문 UI 표시와 응답 전달만.
- **워치에 남는 것**: 심박 센서 수집과 폰 전달(HrForwarder), 대시보드/설문 렌더링, 버튼 입력 전달 - 뷰어+입력 장치 역할.

## 결과

- 긍정: 폰-워치 존 색이 어떤 심박에서도 동일(단일 판정). 화면 숫자와 존 색 일치로 "139인데 레드" 류 혼란 해소. 워치 코드 축소, 판정 규칙 변경 시 폰만 수정.
- 부정/트레이드오프: 폰 두절 시 워치 존 미표시(이전의 로컬 폴백 편의 포기 - 사용자 확정). 표시(순간)와 코칭(60초 평균) 기준이 다른 것은 의도된 분리로 문서화 필요. `/run/live` 스키마 변경으로 폰/워치 동시 재배포 필요.
