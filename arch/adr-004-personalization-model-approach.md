# ADR-004 (DP3): Zone 2 개인화 모델 접근 방식

- **날짜**: 2026-07-01
- **상태**: Accepted
- **결정자**: 성시원
- **보고서 매핑**: 설계 - Architectural Decision **DP3**

---

## 맥락

DP1(adr-003)에서 개인화 레이어가 이 과제의 핵심 AI라고 정했다. 그렇다면 "개인 Zone 2 경계를 데이터로 추정"하는 모델을 무엇으로 만들 것인가. 이 문제는 다음 제약을 동시에 안는다.

- **데이터 희소**: 개인화는 사용자별. 한 사람의 세션은 수 회~수십 회뿐. 유저당 대규모 학습 불가.
- **정답 라벨 없음**: "진짜 Zone 2 경계 몇 bpm"은 랩 젖산검사 없이는 라벨이 없다. 지도학습 대상이 아니다.
- **콜드스타트**: 신규 유저는 데이터 0.
- **온디바이스 경량 + 설명가능 + 강건** (QA2/QA3/QA4, 설명용이성).

이 제약이 모델 선택을 좌우한다.

---

## 결정

### 대안 비교

| 기준 | 대안 A (공식 prior + Bayesian 온라인 적응) | 대안 B (오프라인 모집단 ML + 개인화) | 대안 C (per-user LSTM) |
|------|------|------|------|
| 데이터 요구량 | 세션 1회부터 동작 | 공개 데이터셋 필요 | 유저당 수천 샘플 필요 |
| 정답 라벨 | 불필요 (물리 기반 관측) | 파생 라벨 필요 | 라벨 필요 |
| 콜드스타트 | 공식 prior로 즉시 | 모집단 모델이 완화 | 최악 (데이터 0) |
| 온디바이스 부담 | 없음 (순수 산술) | TFLite 추론 | 추론 부담 |
| 설명가능성 | 높음 | 중 | 낮음 (블랙박스) |
| 강건성(QA2) | 관측 다운웨이트/clamp로 확보 | 중 | 이상값에 취약 |
| 일정 리스크 (1인 1달) | 낮음 | 중~높음 | 매우 높음 |

### 대안 A: 공식 prior + Bayesian 온라인 적응 추정 *(채택)*

공식(HRR)으로 사전분포를 잡고, 세션마다 물리 기반으로 추출한 관측치로 개인 경계의 사후분포를 갱신한다(켤레 가우시안/칼만 유사). 전역 학습도, 신경망도, 모델 변환도 없다.

- 장점: 라벨 불필요(물리 관측), 세션 1회부터 동작, 콜드스타트=공식, 순수 산술이라 온디바이스 부담 0, 설명·강건 우수. QA3(적응성)/QA2(강건성)/설명용이성에 정확히 부합.
- 단점: "딥러닝"이 아니라 겉보기 화려함이 덜하다.

### 대안 B: 오프라인 모집단 ML 모델 + 개인화

공개 러닝/HR 데이터셋에 파생 라벨(예: HR-Pace 곡선의 Dmax로 유산소 임계 추정)을 붙여 소형 모델(GBM/소형 NN)을 오프라인 학습하고 TFLite로 온디바이스 탑재, 그 위에 Bayesian 개인화.

- 장점: ML 파이프라인 역량 어필, 모집단 사전지식으로 콜드스타트 일부 완화.
- 단점: 공개 데이터 확보 + 파생 라벨 정당화 + TFLite 변환/검증까지 1인 1달엔 리스크. 파생 라벨 자체가 결국 공식/휴리스틱 기반이라 A 대비 실익이 제한적.

### 대안 C: per-user LSTM 시계열 학습

사용자 시계열을 LSTM으로 학습해 상태를 예측.

- 장점: 다변량 시계열 표현력.
- 단점: 유저당 대규모 라벨 데이터가 필요해 **본질적으로 불가**. 콜드스타트 최악, 블랙박스라 설명·강건성 취약. **이 문제의 잘못된 도구.**

### 채택: 대안 A

데이터 희소성과 라벨 부재, 그리고 QA(적응성/강건성/설명용이성)가 A를 가리킨다. LSTM(C)은 실현 불가한 오답이고, 오프라인 ML(B)은 실익 대비 일정 리스크가 크다. B는 향후 고도화 경로로 남긴다.

---

## 결과

- **"AI"의 실체 = 확률적 온라인 적응 추정(Bayesian 학습)**. PyTorch/LSTM/모델 변환 불필요. (온디바이스 LLM은 별개 결정 DP2.)
- **학습 데이터**: 전역 지도학습 없음. 대신 검증용 **합성 세션 시뮬레이터**(+선택적 공개 데이터)로 수렴/강건성 검증. 상세는 `spec/spec-004-zone2-personalization.md`.
- **Python/PyTorch의 위치**: 온디바이스 모델을 만드는 데 쓰는 게 아니라, 오프라인 **검증 하네스**(시뮬레이터+추정기 수렴 그래프)를 돌리는 분석 도구로만 쓴다. 온디바이스 추정기는 Kotlin 산술로 구현.
- 향후(B): 데이터가 모이면 모집단 사전학습 모델을 얹는 경로 개방.
