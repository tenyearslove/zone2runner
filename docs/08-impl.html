구현 개요

4
플랫폼Android 폰 앱과 Wear OS 워치 앱, Kotlin
역할 분리폰은 판정·분석·개인화·코칭을 담당하고, 워치는 심박을 측정해 보내고 판정 결과를 표시한다.
AI 구성규칙 판정 + 온라인 Bayesian 개인화 + 관측 통계 분석 + 온디바이스 LLM 문장 표현
통제 장치입력 범위 검사, 판정 히스테리시스, LLM 방향·숫자 검사, 기본 문구, 규칙 우선 처리
외부 의존워치 센서, GPS, AICore, Open-Meteo, OSM 지도 타일을 사용한다. 자체 서버는 없다.
데이터 경계심박·개인화 값·세션 분석은 자체 서버나 외부 AI API로 보내지 않는다. 날씨와 지도는 외부 요청을 사용한다.
자동 검증최근 JVM 단위시험 153개가 통과했다. QAS 측정값은 별도 결과 파일로 다시 생성된다.

구현 — 러닝과 시뮬레이션

4
  • 실시간 판정: 심박, 현재 존, Zone 2 게이지, 페이스와 거리를 한 화면에 보여 준다.
  • 두 가지 시간 기준: 화면에는 현재 심박을 빠르게 반영하고, 코칭과 통계에는 일정 시간 유지된 값을 사용한다.
  • 코칭: 규칙이 올릴지, 유지할지, 낮출지를 정한다. LLM은 그 뜻을 자연스러운 문장으로 바꾼다.
  • 말하기 테스트: 사용자는 편함·보통·벅참 중 하나를 고른다. 이 응답이 개인 경계 갱신에 사용된다.
  • 시뮬레이션 모드: 자동 시나리오, 수동 페이스, 수동 러너를 선택하고 재생 속도를 높여 긴 세션을 짧게 확인할 수 있다.
  • 검증 도구: LLM을 켜고 끄거나 가상 러너를 바꿔 같은 화면과 파이프라인을 비교할 수 있다.

화면 자료 4: 말하기 테스트편함·보통·벅참 선택 화면

구현 — 리포트와 설명

4
  • 세션 요약: 존 분포, 심박과 페이스 변화, 경사, 케이던스, 구간 기록을 카드와 그래프로 보여 준다.
  • 관측 중심 분석: 미래를 예측하지 않고 실제 세션에서 계산한 드리프트, 회복 심박, 경사 보정 페이스를 설명한다.
  • 문장별 근거: 코칭 문장을 누르면 당시 심박과 경계, 사용한 프롬프트, 채택·차단·기본 문구 경로를 확인할 수 있다.
  • LLM 사용 기록: 호출 횟수, 채택과 기본 문구 횟수, 차단 이유를 남겨 생성 모델의 동작을 살펴볼 수 있다.
  • 저장 후 재사용: 세션 설명은 종료 시 저장한다. 같은 리포트를 다시 열 때 LLM을 다시 호출하지 않는다.

검증 결과를 해석하는 방법

4
항목확인한 내용이 결과로는 말할 수 없는 내용
설명용이성선언한 문장 집합에서 근거에 없는 숫자를 차단했다.모든 한국어 문장을 완벽하게 검사하거나 모든 사용자가 설명을 쉽게 이해한다는 뜻은 아니다.
기능적응성가상 러너에서 개인화 값이 정해 둔 목표 안으로 수렴하고 안정됐다.실제 사람의 유산소 역치를 0.20~0.77bpm 오차로 찾았다는 뜻은 아니다.
제어가능성선언한 위반 문장과 LLM 실패 경로를 규칙이 처리했다.세상에 존재하는 모든 잘못된 표현을 막는다는 뜻은 아니다.
강건성정해 둔 이상값과 노이즈 입력에서 판정 규칙이 목표대로 동작했다.실제 손목 센서의 정확도와 모든 실외 환경을 검증했다는 뜻은 아니다.
테스트가능성같은 seed의 난수 입력을 다시 만들고 네 AI QAS를 워치 없이 실행했다.시뮬레이션 결과가 실제 사람과 센서의 정확도를 대신한다는 뜻은 아니다.

■공통 검증 기반

RunSource 교체, 가상 러너, 고정 seed, JVM 단위시험은 네 AI QAS를 워치 없이 반복 확인하게 해 준다. 전체 단위시험 153/153 통과는 제품 정확도가 아니라 자동 회귀 범위를 보여 주는 참고 정보다.

■보조 성능 확인

60분 분량 3600틱의 JVM 로직 비용은 틱당 0.1ms 미만이었다. 워치 통신, 화면, TTS, LLM을 포함하지 않으므로 실기기 전체 성능으로 일반화하지 않는다.

결론

5

1.주요 성과

  • 문제와 제약에서 다섯 가지 품질을 선정했다. 네 가지 AI 품질과 테스트가능성이 프로젝트의 핵심 설계를 이끌었다.
  • 품질 요구를 실제 구조로 구현했다. 사용자 응답 기반 개인화, 규칙 중심의 판단, LLM 출력 가드, 입력 노이즈 방어, 반복 가능한 시뮬레이션이 각각 코드와 화면에 연결된다.
  • 같은 기준으로 구현을 검증했다. 각 QAS에 미리 정한 입력과 성공 기준을 적용했고, 다섯 항목 모두 자동화된 구조 검증 범위에서 목표를 만족했다.
  • 확인한 범위와 확인하지 않은 범위를 나눴다. 실제 사람의 생리 정확도나 사용자 효과를 자동시험 결과로 바꾸어 말하지 않았다.

2.과제 규정 충족

규정요구이 과제
기능 요구사항4개 이상6개, AI 관련 5개

3.향후 확인 항목

실제 제품으로 발전시킬 경우 사용자 설명 이해도, 실제 달리기에서의 개인화, 손목 움직임이 있는 센서 환경, 워치 입력부터 음성 출력까지의 지연을 추가로 확인한다. 이 항목들은 이번 과제 제출의 필수 검증 범위에는 포함하지 않는다.

이 과제의 핵심은 큰 모델이 아니라, 필요한 AI 품질을 정하고 설계와 구현과 검증을 한 흐름으로 연결한 것이다.
