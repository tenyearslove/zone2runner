DP5. 테스트가능성 — 같은 조건을 반복 검증하는 설계

실제 달리기를 반복하지 않고도 같은 조건을 시험하는 방법을 비교한다.

DP5. 설계 문제 정의

3

1.배경

  • 이 시스템은 검증하기 어려운 조건이 겹쳐 있다. 실제 사람의 Zone 2 경계를 측정한 정답이 없고, 같은 달리기를 정확히 반복할 수 없으며, 워치와 폰이 함께 동작한다.
  • 판정, 개인화, 코칭 로직은 개발 중에 계속 바뀐다. 매번 직접 달려야만 확인할 수 있다면 1인 과제에서 충분한 반복 검증이 어렵다.
  • 그래서 실제로 달리지 않아도 입력부터 판정·코칭·리포트까지 같은 코드 경로를 반복 확인하는 구조를 선택했다. 테스트가능성은 일반 소프트웨어 품질이지만, 실제 달리기를 반복하기 어려운 제약 때문에 이 시스템의 구조를 바꾼 핵심 요구사항이다.

2.문제점

  • 같은 입력 조건을 재현할 수 없다. 같은 심박 변화를 두 번 만들 수 없으니 수정 전후를 같은 조건에서 비교할 수 없다.
  • 위험한 상황을 직접 만들기 어렵다. 위험 심박, 신호 두절 같은 중요한 상황은 실제 달리기로 만들기 어렵거나 위험하다.
  • 변경할 때마다 직접 달려야 하면 검증을 반복하기 어렵다. 변경 하나를 확인할 때마다 한 번씩 달려야 한다면 자동화할 수 없다.
  • 시뮬레이션에는 한계가 있다. 데이터를 만든 규칙으로 같은 데이터를 채점하면 좋은 결과가 당연히 나오기 쉽다. 따라서 시뮬레이션으로 확인할 수 있는 범위를 분명히 해야 한다.

DP5. 설계 결정과 근거

3

1.최종 채택 구조

1안인 입력 교체와 반복 시뮬레이션 구조를 채택했다.

2.채택 근거

  • 같은 입력을 반복할 수 있어야 변경 전후를 비교할 수 있다. 1안은 시험 시나리오를 다시 실행해 변경으로 생긴 문제를 찾을 수 있다.
  • 위험하거나 드문 입력도 안전하게 넣을 수 있다. 범위 밖 심박이나 신호 두절처럼 실제 달리기로 만들기 어려운 조건을 시험 입력으로 재현할 수 있다.
  • 짧은 시간에 반복할 수 있다. 같은 입력으로 수정 전후를 비교하므로, 틈을 내어 진행하는 1인 과제에서도 변경할 때마다 다시 확인할 수 있다.
  • 여러 세션의 적응을 빠르게 확인한다. 경계를 정해 둔 가상 러너의 결과를 다음 입력에 다시 반영해, QA2의 여러 세션에 걸친 개인화 과정을 자동으로 실행한다.
  • 시뮬레이션의 한계를 분리했다. 자동시험은 규칙과 구조가 설계대로 움직이는지 확인한다. 실제 사람의 유산소 역치와 실제 센서 성능은 별도의 기기·사용자 평가가 필요한 항목이다.

3.보완 계획

  • 이번 과제에서 확인: QA1~QA4 자동 검증 경로 4개를 모두 워치 없이 실행했다(4/4). 같은 시드로 다시 만든 입력은 5개 시드 모두 일치했고(100%, 5/5), 서로 다른 시드에서는 서로 다른 심박값의 순서가 생성됐다. 전체 JVM 단위시험은 153/153 통과했다.
  • 향후 확인: 실제 기기 연결, 실제 센서 성능, 사람에 대한 정확도는 자동시험만으로 확인할 수 없다. 제품화를 검토할 때 별도의 기기·사용자 평가로 확인한다.

Appendix. DP5 상세 설계 내역

A

A1.이 설계 결정이 다루는 품질 문제

  • 같은 입력을 두 번 만들기 어렵다 → 테스트가능성(입력 재현)
  • 위험하거나 드문 상황을 실제 달리기로 만들기 어렵다 → 테스트가능성, 강건성
  • 변경할 때마다 직접 달려 검증하기 어렵다 → 테스트가능성(자동 회귀)
  • 측정 정답이 없어 실제 정확도를 평가하기 어렵다 → 시뮬 역할을 구조 검증으로 한정
  • 개인화 수렴에 여러 세션이 필요하다 → 결과를 다음 입력에 반영하는 반복 시뮬레이션
  • 워치와 폰이 함께 동작해 단독 실행이 어렵다 → 테스트가능성(기기 의존 분리)
  • 시뮬레이션 결과를 실제 사람의 정확도로 오해하지 않아야 한다 → 강건성 검증 범위의 한계

A2.채택안의 검증 구조 4요소

요소하는 일
1. 입력 분리실제 센서, 가상 러너, 수동 입력을 같은 인터페이스에서 교체할 수 있다. 운영과 시험이 같은 코드 경로를 사용한다.
2. 반복 가상 러너경계를 정해 둔 가상 러너의 결과를 다음 세션 입력에 반영해 개인화 과정을 자동으로 실행한다.
3. 순수 로직 분리판정 로직을 기기와 분리해 JVM 단위시험으로 변경 전후를 자동 확인한다.
4. 결과 측정QA별로 정한 입력을 넣고 결과를 같은 지표로 기록한다.

별점의 범위: 1인 개발, 짧은 제출 일정, 반복해서 확인해야 하는 네 AI QAS라는 조건에서 비교했다. 테스트가능성은 일반 품질이며, 실제 기기 확인과 자동시험은 서로 대체하지 않는다. 이번 과제에서는 자동화된 구조 검증 결과를 제시한다.

A4.용어 대조(심사용)와 근거 문헌

입력을 인터페이스로 분리하는 방식은 Ports and Adapters와 의존성 역전 원칙에 해당한다. 실제 센서를 대신하는 입력은 test double, 수정 뒤 같은 시험을 자동으로 다시 실행하는 것은 regression test라고 한다. 시뮬레이션과 실제 환경의 차이는 sim-to-real gap이라고 부른다.

근거 문헌: ISO/IEC 25010(테스트가능성 정의) / Cockburn(포트와 어댑터) / Meszaros(테스트 대역) / 테스트 피라미드(Cohn, Fowler) / 이 저장소의 자체 이력(시뮬 자기 채점 함정을 직접 확인하고 시뮬 역할을 한정 — 실험 기록 §15-3)

상세 설계와 참고 문헌은 별도의 DP5 설계 문서에 기록했다.
