DP3. 제어가능성 — LLM의 권한을 제한하는 구조

생성 문장이 정해진 형식이나 사실의 범위를 벗어나거나 LLM을 사용할 수 없는 상황에 대응하는 두 가지 설계안을 비교한다.

DP3. 설계 문제 정의

3

1.배경

  • 이 앱은 코칭 문장을 생성하는 데 기기에서 실행되는 LLM을 사용한다.
  • LLM은 자연스러운 문장을 만들 수 있지만 출력이 항상 같지는 않으며, 요청한 형식이나 제공된 숫자의 범위를 벗어날 수 있다.
  • 코칭은 달리는 중에 실시간으로 전달되므로 사람이 문장마다 확인할 수 없다. LLM이 맡는 범위와 실패했을 때의 대응을 시스템 구조로 정해야 한다.

2.문제점

  • 판단과 표현의 책임 범위를 정해야 한다. 코칭 방향과 숫자까지 LLM에 맡길지, 시스템이 사실을 먼저 확정하고 LLM에는 표현만 맡길지 결정해야 한다.
  • LLM을 사용할 수 없는 상황도 고려해야 한다. 지원되지 않는 기기, 모델 미설치, 응답 지연이나 실행 실패에도 규칙 기반 코칭을 제공할 수 있어야 한다. 다만 모델 상태를 확인하는 동안에는 생성 코칭을 보류한다.
  • 위험 심박 안내는 문장 생성을 기다리면 안 된다. 설정한 임계값을 넘으면 생성 결과와 관계없이 즉시 안내할 별도 경로가 필요하다.
  • 자동 대응의 근거를 사후에 확인할 수 있어야 한다. 생성 문장이 차단되거나 기본 문구로 전환된 이유를 기록으로 남겨야 한다.

DP3. 두 설계안의 비교

3
(1안) 규칙 판정과 LLM 표현 한정 구조 (2안) LLM 판단 위임 구조
한 줄
소개		 코칭 방향은 규칙이 정하고 LLM에는 문장 표현만 맡기는 구조 심박과 페이스 등 관측 정보를 LLM에 주고, 코칭 내용까지 직접 판단하게 하는 구조
구조
  • 판단 확정: 규칙이 심박과 세션 상태를 바탕으로 코칭 방향과 문장에 사용할 숫자를 먼저 정한다.
  • 표현 위임: LLM은 시스템이 확정한 사실과 방향 안에서 코칭 문장만 작성한다.
  • 검사와 실패 대응: 출력 가드레일이 형식·방향·숫자를 확인한다. 검사 탈락이나 생성 실패에는 기본 문구로 전환하고, 위험 심박 안내는 LLM을 거치지 않는다. 처리 경로와 전환 이유는 기록으로 남긴다.
  • 정보 전달: 심박·페이스·세션 상태와 자연어 지침을 LLM에 함께 전달한다.
  • 판단과 표현 위임: LLM이 속도를 올릴지·유지할지·낮출지 판단하고 코칭 문장까지 만든다.
  • 출력 통제: 프롬프트 규정과 형식·금칙어·숫자 검사를 적용할 수 있지만, LLM 밖에 결과를 대조할 독립된 코칭 방향은 없다.
장점

QA3 제어가능성 ★★★★★

QA1 설명용이성 ★★★★★

QA5 테스트가능성 ★★★★★
같은 입력으로 출력 검사가 같은 기준으로 동작하는지 반복 확인할 수 있다.

표현 범위
관측 정보를 함께 고려해 규칙에 미리 적지 않은 상황에도 다양한 코칭을 만들 가능성이 있다.

기능 확장
프롬프트와 입력 맥락을 넓혀 새로운 코칭 상황을 비교적 빠르게 실험할 수 있다.
단점

사전 정의 비용

표현 제약
허용한 사실과 방향 안에서만 문장을 만들기 때문에 생성 모델의 자유도가 줄어든다.

QA3 제어가능성 ★★

QA1 설명용이성 ★★
생성한 설명이 실제 판단 근거와 일치하는지 별도로 확인해야 한다.

QA5 테스트가능성 ★★★
같은 입력에도 생성 결과가 달라질 수 있어 판정과 표현을 함께 검증하기 어렵다.
Tradeoff 판정 방향과 실패 대응을 독립된 규칙으로 확인할 수 있는 대신, 통제할 상황과 코칭 방향을 미리 정의해야 한다. 문장 생성의 자유도는 높지만, QA1·QA3·QA5를 충족하려면 LLM 밖에 판정 기준과 실패 대응 경로를 추가해야 한다.

DP3. 설계 결정과 근거

3

1.최종 채택 구조

1안인 규칙 판정과 LLM 표현 한정 구조를 채택했다.

2.채택 근거

  • QA3 제어가능성: 시스템이 코칭의 방향·형식·숫자를 먼저 확정하고, 범위를 벗어난 문장은 차단한다. 모델 미지원·실행 오류에는 기본 문구를 사용하며, 위험 심박 안내는 LLM과 분리한다.
  • QA1 설명용이성: 판정에 사용한 사실과 생성 경로, 문장이 차단되거나 기본 문구로 전환된 이유를 함께 기록해 리포트에서 확인할 수 있게 한다.
  • QA5 테스트가능성: 방향과 숫자 검사를 독립된 규칙으로 두어 같은 시험 문장에 같은 차단 기준을 반복 적용할 수 있다.
  • Tradeoff: 판단과 실패 대응을 규칙으로 통제하는 대신 코칭의 상황과 방향을 미리 정의해야 한다. 2안은 표현의 자유도가 높지만 QA1·QA3·QA5를 위한 외부 기준과 대체 경로가 추가로 필요하다.

3.검증 결과

QA3: 판정 방향과 어긋나는 시험 문장 10개와 허용되지 않은 숫자가 있는 시험 문장 5개는 모두 출력 검사에서 차단됐다. 두 측정의 출력 검사 통과율은 각각 0%였다.

QA1·QA5: 출력 검사와 기본 문구 전환 경로를 기록하고, 같은 시험 문장에 동일한 검사 규칙을 반복 적용했다. 이는 미리 정의한 표현 범위에서 근거 추적과 반복 검사가 가능함을 확인한 것이며, 모든 한국어 문장의 의미를 이해한다는 뜻은 아니다.

4.보완 계획

  • 단기 개선안: 속도 조절을 나타내는 한국어 표현을 추가로 수집해 시험 문장과 차단 사유를 보강한다.
  • 장기 개선안: 실제 사용 기록이 쌓이면 사람이 문장 방향을 판정한 결과와 출력 검사 결과를 비교해 누락과 오차단을 줄인다.

평가 조건: 기기에서 LLM을 실행하고 실시간으로 코칭 문장을 제공하며, LLM을 사용할 수 없는 상황에도 코칭을 이어 가야 한다는 조건에서 두 안을 비교했다. 사람이 모든 출력을 미리 검토할 수 있는 서비스라면 2안의 평가가 달라질 수 있다.

A4.용어와 근거 문헌

ISO/IEC 25059에서 제어가능성의 핵심으로 다루는 개념은 개입 가능성(intervenability)이다. 모델에 맡기는 일의 범위를 구조적으로 좁히는 방식은 architectural containment(구조적 격리), 실패 시 기본 문구로 전환하는 방식은 fail-safe fallback에 해당한다. 사람의 개입은 HITL(루프 안 교정)과 HOTL(루프 위 감독), 사후 확인은 audit에 대응한다.

근거 문헌은 ISO/IEC 25059의 제어가능성 정의, LLM 가드레일의 계층 방어와 구조적 격리를 다룬 서베이, LLM 단독 판단 회피 권고, 생성 결과 검사와 실패 경로 분리에 관한 연구다.

상세 설계와 참고 문헌은 별도의 DP3 설계 문서에 기록했다.
