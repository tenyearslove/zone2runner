# 1차 평가자 예상 질문 목록

- 용도: 제출 HTML과 분리해 1차 평가자에게 제공할 질문 은행
- 원칙: 보고서 본문에는 넣지 않는다. 답변은 현재 확정된 QAS와 검증 범위에 맞췄으며, 1차 평가 전에 발표자의 말투로 한 번 더 다듬는다.

## DP1 설명용이성

- "사후 설명 도구(SHAP, LIME)를 붙이면 2안도 설명되지 않나?" → 그 설명은 모델 밖에서 추정한 근사라서 실제 판단과 같다는 보장이 없고, 계산도 무겁다.

- "LLM에게 설명을 다 시키면 되지 않나?" → LLM이 원래 판단에 사용한 값과 규칙을 직접 알지 못하면 설명이 실제 계산과 연결됐는지 확인하기 어렵다. 이 설계에서는 규칙이 근거를 먼저 확정하고 LLM은 그 내용을 자연스러운 문장으로 바꾼다.

## DP2 제어가능성

- "프롬프트를 잘 쓰면 2안도 통제되지 않나?" → 프롬프트는 원하는 문장을 만드는 데 중요하다. 다만 이 앱은 LLM이 아직 준비되지 않았거나 실행에 실패한 상황도 처리해야 한다. 그래서 판단은 규칙이 맡고, LLM 출력은 확인하며, 사용할 수 없을 때는 기본 문구로 전환하는 책임 분리가 필요하다.

- "검사가 정상 문장까지 기각해 코칭이 굳지 않나?" → 가능하다. 그래서 기각이 전부 기록되고, 기각률이 높으면 기준을 데이터로 조정한다. 기각의 비용은 덜 자연스러운 짧은 문구이지 코칭 중단이 아니다.

## DP3 기능적응성

- "데이터를 모아 학습하면 더 정확해지지 않나?" → 사용자가 많고 검증 체계가 있으면 그렇다. 이 조건에서는 코호트도 채점 기준도 없어 잠재를 확인할 수 없고, 개인의 변화 반영은 오히려 느려진다.

- "말하기 테스트 답이 틀리면?" → 답 하나의 영향은 확신 폭이 제한하고 세션당 이동 한도가 추가로 막는다. 갱신 이력이 화면에 노출되어 확인하고 재설정할 수 있다.

## DP4 강건성

- "코칭이 60초 늦으면 이미 늦은 것 아닌가?" → 이 설계는 순간 반응보다 안정적인 강도 유지를 우선한다. 화면 판정은 순간심박으로 빠르게 바뀌고, 코칭만 60초 평균을 사용한다. 위험 심박은 별도 규칙으로 처리하지만 이것이 의료 안전을 보장한다는 뜻은 아니다.

- "이동평균 창을 잘 고르면 2안도 충분하지 않나?" → 창 하나로는 스파이크 억제(긴 창)와 반응성(짧은 창)을 동시에 못 잡고, 경계 근처 번복은 창 길이와 무관하게 남는다. 번복 억제는 평활이 아니라 판정 규칙(들어갈 때와 나올 때의 경계를 다르게 두는 방식)과 판정 입력(순간값을 보느냐 60초 평균을 보느냐)의 문제다.

- "이동평균에 히스테리시스만 더한 중간안은?" → 그 순간 "층을 쌓는 설계"를 받아들인 것이다. 남는 질문은 몇 층이냐이고, 시간 필터와 개인 문턱과 폴백도 같은 논리로 필요해진다 — 각 층이 서로 다른 노이즈를 막기 때문이다.

## DP5 테스트가능성

- "시뮬로 통과한 게 무슨 의미가 있나?" → 시뮬이 답하는 것은 "로직이 설계대로 동작하는가"이지 "실제 사람에게 정확한가"가 아니다. 후자는 실주행 검증으로만 답해지며 그 계획이 별도로 있다. 이 한계를 설계 문서에 못 박았다.

- "입력 인터페이스가 과한 설계 아닌가?" → 이 경계 덕분에 워치 없이도 같은 판정 로직에 시험 입력을 넣을 수 있다. 153개 시험은 정확도 점수가 아니라 이 구조가 제공하는 자동 회귀 범위를 보여 준다.
