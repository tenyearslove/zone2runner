# 제출 HTML 한국어·논리 전수 검토

- 시작일: 2026-08-04
- 대상: docs/src의 원본 HTML과 docs의 빌드 산출물
- 원칙: Markdown은 논리를 정리하는 작업대이고, 최종 품질 판정은 제출되는 HTML을 기준으로 한다.

## 1. 교정 기준

모든 페이지를 아래 기준으로 처음부터 끝까지 읽는다.

1. 한 문장에는 한 가지 핵심만 담는다.
2. 번역투와 명사 나열을 피하고, 누가 무엇을 하는지 분명히 쓴다.
3. 전문용어는 꼭 필요할 때만 사용하고 첫 등장에 쉬운 뜻을 붙인다.
4. 문제, QAS, 설계, 구현, 측정, 한계가 같은 용어로 이어지게 한다.
5. 자동시험 결과를 실제 사용자 효과나 실제 생리 정확도로 넓혀 말하지 않는다.
6. 표 제목, 그림 설명, 각주도 본문과 같은 기준으로 고친다.
7. 원본 페이지와 합본을 함께 갱신한 뒤 실제 렌더를 확인한다.

## 2. 자주 고칠 표현

| 피할 표현 | 사용할 표현 |
|---|---|
| 실라벨 | 사용자의 말하기 테스트 응답 |
| 폐루프 시뮬레이션 | 결과를 다음 입력에 다시 반영하는 반복 시뮬레이션 |
| 라벨원 | 응답을 만드는 가상 러너 |
| 프로비넌스 | 판단에 사용한 값과 생성 과정 기록 |
| 정체성 논지 | 이 품질을 선택한 이유 |
| 담보한다 | 이 설계가 해당 품질을 지원한다 |
| 전 파이프라인 | 입력부터 판정·코칭·리포트까지의 전체 흐름 |
| 데이터 비이탈 | 어떤 데이터가 어디로 전송되지 않는지 구체적으로 씀 |

공식 품질명, QAS, ASR, Bayesian, LLM처럼 심사에 필요한 용어는 유지하되 바로 옆에서 쉬운 말로 설명한다.

## 4. 렌더 검토 기록

- 2026-08-04: 01과 08을 빌드해 Edge로 렌더하고 Poppler로 PDF 미리보기를 확인했다.
- 한글 글꼴과 표 내용은 정상적으로 표시됐다.
- 현재 인쇄 CSS는 슬라이드 중간에서 종이 페이지를 나눈다. 전체 문장 교정을 마친 뒤 한 슬라이드가 한 페이지에 들어가도록 인쇄 전용 CSS를 별도로 조정한다.
- 인앱 브라우저 연결은 실행 환경의 권한 정보 누락으로 사용할 수 없었다. 로컬 Edge 렌더로 대체했다.
