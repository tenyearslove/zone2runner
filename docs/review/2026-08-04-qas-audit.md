# AI QAS 타당성 감사

> 상태: 이 문서는 1차 감사 기록이다. 이후 사용자 피드백 검토에서 테스트가능성을 QA5로 복원했다. 현재 정본은 `spec/spec-002-quality-attributes.md`와 `docs/review/2026-08-04-user-feedback-p03-p14.md`다.

- 작성일: 2026-08-04
- 목적: 2주 안에 1인이 완수할 수 있는 인증 과제로 QA 선정, 설계, 구현, 검증의 논리를 맞춘다.
- 적용 범위: 문서와 보고서의 주장 교정. 앱과 워치 소스는 수정하지 않는다.

## 1. 먼저 내린 결론

현재 선정한 AI 품질의 방향은 맞다. 다만 6개 QA를 모두 같은 무게의 ASR로 둔 것과, 실제 구현보다 넓게 쓴 일부 시나리오와 지표는 고쳐야 한다.

제출 보고서에서는 다음 네 가지 AI QA에 집중한다.

| ID | AI QA | 이번 과제에서 확인할 좁고 분명한 목표 | 판정 |
|---|---|---|---|
| QA1 | 설명용이성 | 코칭 설명이 시스템이 가진 사실에서 벗어나지 않는다. | 유지하되 범위 축소 |
| QA2 | 기능적응성 | 말하기 테스트 응답을 받으면 개인 경계가 제한된 폭으로 갱신되고 안정된다. | 유지하되 자극 교정 |
| QA3 | 제어가능성 | LLM 출력이 판정과 어긋나면 차단하고 안전한 기본 문구로 바꾼다. | 유지하되 표본 범위 명시 |
| QA4 | 강건성 | 이상 심박과 경계 부근의 흔들림에도 판정이 불필요하게 번복되지 않는다. | 유지 |

테스트가능성과 수행효율성은 버리는 것이 아니다. 역할을 바로잡는다.

- 테스트가능성은 QA5가 아니라 QA1~QA4를 기기 없이 반복 검증하게 해 주는 설계 수단이다.
- 수행효율성은 보조 제약으로 둔다. JVM 로직 시간은 참고값으로 제시하되, 실기기 지연을 확인하지 않고 전체 성능을 달성했다고 쓰지 않는다.
- 실제 달리기, 사용자 평가, 의료적 정확도, 실기기 종단 지연은 이번 제출의 합격 조건에서 제외한다.

이 구성이 과제 규정인 품질속성 4개 이상과 AI 품질 2개 이상을 만족하면서도, 한 사람이 자동으로 다시 실행할 수 있는 검증에 집중하는 가장 작은 범위다.

## 2. 감사 기준

좋은 QAS는 다음 질문에 한 문장씩 답할 수 있어야 한다.

1. 누가 또는 무엇이 상황을 만드는가?
2. 어떤 일이 발생하는가?
3. 어느 부분이 대응해야 하는가?
4. 어떤 조건에서 발생하는가?
5. 시스템은 무엇을 해야 하는가?
6. 성공 여부를 어떤 숫자나 통과 조건으로 판단하는가?

추가로 아래 네 조건을 확인했다.

- 선택한 QA가 강의의 AI 8대 QA와 같은 뜻인가?
- 이 QA 때문에 실제 설계가 달라졌는가?
- 현재 코드와 자동시험으로 측정할 수 있는가?
- 측정 결과가 말해 주는 범위를 넘어서 주장하지 않는가?

## 3. 수정 QAS

### QA1. 설명용이성 — 사실과 다른 설명을 내보내지 않는다

| 요소 | 정의 |
|---|---|
| 출처 | 사용자 또는 코칭 기능 |
| 자극 | 판정 결과에 대한 설명을 요청하거나 LLM 코칭 문장을 생성한다. |
| 대상 | 규칙 판정, 설명 데이터, LLM 출력 가드 |
| 상황 | 정상 사용 중이며 LLM이 근거와 다른 숫자를 만들 수도 있는 상황 |
| 대응 | 규칙이 판단에 사용한 사실을 먼저 확정한다. LLM은 표현만 담당한다. 허용된 사실에 없는 숫자가 있으면 문장을 버리고 기본 문구로 바꾼다. 코칭과 근거 기록을 함께 저장한다. |
| 측정 | 자동 검증 문장 집합에서 미등록 숫자 문장 5/5 차단, 사실 문장 3/3 통과, 관련 기록 저장·복원 시험 통과 |

판정 근거:

- AI 설명용이성 중 이번 과제가 검증하는 부분은 이해도 전체가 아니라 설명의 충실성이다.
- 숫자 가드와 근거 기록 구조가 있으므로 설계와 구현에 직접 연결된다.
- 5개 문장 결과를 모든 한국어 문장에 대한 100% 성능으로 일반화하면 안 된다.
- 사용자 이해도와 설명의 친절함은 실제 사용자 평가가 필요하므로 향후 항목으로 둔다.

### QA2. 기능적응성 — 사용자 응답으로 개인 경계를 갱신한다

| 요소 | 정의 |
|---|---|
| 출처 | 사용자의 말하기 테스트 응답 |
| 자극 | 사용자가 현재 강도를 편함, 보통, 벅참 중 하나로 답한다. |
| 대상 | 개인화 모델의 Zone 2 상한 |
| 상황 | 초기 공식값에서 시작하고 이전 세션의 학습 결과를 이어 받는 상황 |
| 대응 | 응답을 관측값으로 사용해 Bayesian 방식으로 개인 경계를 갱신한다. 한 세션의 이동 폭은 10bpm을 넘지 않게 제한한다. |
| 측정 | 참임계를 정해 둔 가상 러너 15개 사례에서 최종 오차 3bpm 이하, 5세션 안에 오차 3bpm 이하 도달, 마지막 4세션의 경계 폭 4bpm 이하, 세션당 이동 10bpm 이하 |

판정 근거:

- 실제 코드는 말하기 테스트 응답으로 개인화 값을 갱신한다. 기온과 드리프트는 현재 이 갱신의 직접 자극이 아니므로 QAS에서 뺀다.
- 가상 러너는 학습기가 참임계를 모르는 상태에서 수렴 구조가 동작하는지를 본다.
- 현재 15개 사례는 모두 1~2세션에 안착했고 최종 오차는 0.20~0.77bpm이었다. 기준 사례의 마지막 4세션 경계 폭은 3.04bpm, 최대 이동은 9.97bpm이었다.
- 오답 응답 10% 결과는 한 시드만 측정했고 오히려 오차가 더 작게 나왔다. 일반적인 내오류성 근거로 쓰지 않고 부가 관찰로만 남긴다.
- 이 결과는 사람의 실제 유산소 역치를 맞혔다는 뜻이 아니다.

### QA3. 제어가능성 — 어긋난 LLM 출력을 규칙이 막는다

| 요소 | 정의 |
|---|---|
| 출처 | 온디바이스 LLM 또는 모델 실행 환경 |
| 자극 | 판정 방향과 반대인 문장, 행동 지시가 없는 문장, 또는 LLM 실패가 발생한다. |
| 대상 | 코칭 출력 가드와 기본 문구 경로 |
| 상황 | 실시간 코칭 중 |
| 대응 | 규칙이 문장을 검사해 기각하고, LLM이 없어도 정해 둔 기본 문구로 코칭을 이어 간다. |
| 측정 | 선언한 검증 문장 집합에서 위반 문장 10/10 차단, 정상 문장 5/5 통과, LLM 실패·로딩·모델 없음에 대한 기본 문구 시험 통과 |

판정 근거:

- 생성 모델이 최종 판단 권한을 갖지 않도록 만든 설계이므로 AI 제어가능성과 직접 연결된다.
- 10/10은 선언한 시험 문장 집합의 결과다. 모든 가능한 한국어 표현을 막는다는 뜻이 아니다.
- 개인 경계의 세션당 10bpm 제한은 QA2의 안정성과 QA3의 폭주 방지를 함께 지원하지만, 같은 측정값을 두 번 성과로 세지 않는다.
- 위험 심박 대응은 의료 안전 보장이 아니라, 정해 둔 임계 규칙이 LLM보다 우선한다는 구조만 설명한다.

### QA4. 강건성 — 노이즈는 줄이고 실제 변화는 놓치지 않는다

| 요소 | 정의 |
|---|---|
| 출처 | 워치 심박 센서에 해당하는 시험 입력 |
| 자극 | 40~220bpm 밖의 값 또는 경계 부근에서 반복해서 오르내리는 값이 들어온다. |
| 대상 | 심박 입력 가드와 Zone 판정기 |
| 상황 | 결정론적 시뮬레이션 입력을 1초 간격으로 넣는 상황 |
| 대응 | 범위를 벗어난 값은 버린다. 경계 부근의 짧은 흔들림은 히스테리시스로 줄이되, 실제로 크게 이동한 값은 빠르게 반영한다. |
| 측정 | 이상치 50/50 차단, 정상 범위 500개 오차단 0개, 300초·시드 5종에서 판정 번복 60% 이상 감소, 실제 +10bpm 이동은 2틱 안에 전환 |

판정 근거:

- 강의의 무효 입력 차단과 Flicker Rate 측정에 정확히 대응한다.
- 현재 번복 감소는 67.1~74.7%, 실제 이동은 1틱이었다.
- 40~220 범위 시험은 구현한 규칙이 바뀌지 않았는지 확인하는 회귀시험이다. 센서 정확도를 입증하는 시험이 아니다.
- 실제 손목 센서의 움직임 잡음과 신호 두절은 실기기 검증이 필요하므로 이번 합격 판정에 포함하지 않는다.

## 4. 기존 지표에서 고칠 점

| 기존 표현 | 문제 | 수정 원칙 |
|---|---|---|
| 모든 QA가 ASR | 우선순위를 정하지 않은 것처럼 보인다. | QA1~QA3을 핵심 ASR, QA4를 지원 QA로 구분한다. |
| 기온·드리프트가 개인화 갱신을 유발 | 현재 구현과 맞지 않는다. | 말하기 테스트 응답만 직접 자극으로 쓴다. |
| 수렴 후 진동 0.49~1.73bpm | 각 세션의 참임계 오차를 진동폭으로 잘못 설명했다. | 마지막 4세션 경계의 최대-최소인 3.04bpm으로 쓴다. |
| 오답 라벨 10%에도 0.09bpm | 한 사례이며 정상 입력보다 좋아 일반화하기 어렵다. | 본문 합격 근거에서 제외하고 부가 관찰로 표시한다. |
| 방향 위반 기각률 100% | 표본 수를 빼면 전체 언어에 대한 보장처럼 보인다. | 검증 집합 10/10이라고 항상 함께 쓴다. |
| 이상치 기각률 100% | 정해 둔 범위 규칙의 결과이지 센서 품질 성능이 아니다. | 구조 회귀시험임을 함께 쓴다. |
| 테스트 153개 통과 | 테스트 개수는 AI 품질 달성 지표가 아니다. | 검증 환경의 재현성 근거로만 쓴다. |
| 틱당 약 0.07ms | 실행 환경에 따라 변하고 LLM·워치·화면을 포함하지 않는다. | JVM 로직이 틱당 0.1ms 미만이었다고 참고만 한다. |
| 실기기 TTS 5초를 QA6 목표에 포함 | 이번 일정에 측정할 수 없고 사용자가 실제 달릴 시간도 없다. | 제출 합격 기준에서 제외하고 향후 실기기 확인 항목으로 둔다. |

## 5. 우선순위와 설계 연결

| 우선순위 | QA | 이 과제에서 중요한 이유 | 연결할 설계 |
|---|---|---|---|
| 핵심 ASR 1 | QA2 기능적응성 | 평균 공식값을 개인 값으로 바꾸는 프로젝트의 핵심 기능이다. | 온라인 Bayesian 개인화 |
| 핵심 ASR 2 | QA1 설명용이성 | 참값이 없는 상황에서 결과를 믿을 근거가 필요하다. | 규칙이 사실 확정, 근거 기록, LLM은 표현만 담당 |
| 핵심 ASR 3 | QA3 제어가능성 | 생성 문장이 판정 권한을 가져서는 안 된다. | 출력 가드, 기본 문구, 규칙 우선 |
| 지원 QA | QA4 강건성 | 입력이 흔들리면 위 세 설계가 모두 의미를 잃는다. | 입력 가드, 히스테리시스 |

테스트 소스 교체와 가상 러너는 위 네 QA를 자동으로 검증하기 위한 공통 기반이다. 별도 핵심 QA로 경쟁시키지 않는다.

## 6. 제출용 검증 판정 방법

검증 결과는 세 등급만 사용한다.

- 달성: 현재 자동시험으로 목표와 결과를 같은 조건에서 재현했다.
- 부분 달성: 일부만 자동시험했고 나머지는 실기기가 필요하다.
- 향후 확인: 실제 사용자나 실외 주행이 필요해 이번 과제에서는 판정하지 않는다.

QA1~QA4의 위 수정 지표는 모두 자동시험으로 재현할 수 있으므로 구조 검증 수준에서 달성으로 판정한다. 단, 표의 제목이나 각주에 반드시 구조 검증이라고 표시한다. 사용자 이해도, 실제 생리 정확도, 실제 센서 환경, 워치-폰-음성 종단 지연은 향후 확인으로 분리한다.
