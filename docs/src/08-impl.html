  • 문제와 제약으로부터 다섯 가지 품질을 선정했다. 네 가지 AI 품질과 테스트가능성을 기준으로 핵심 설계를 구체화했다.
  • 품질 요구를 실제 구조로 구현했다. 사용자 응답 기반 개인화, 규칙 중심의 판단, LLM 출력 검사, 센서 잡음 대응과 반복 가능한 시뮬레이션을 구현 코드와 실행 흐름에 연결했다.
  • 요구사항에서 정한 기준으로 구현을 검증했다. 각 QAS의 측정 항목과 성공 기준을 미리 정한 사례와 가상 조건에 적용하고 결과를 확인했다.
  • 검증한 범위와 검증하지 못한 범위를 구분했다. 자동시험 결과를 실제 사용자의 생리학적 정확도나 사용 효과로 확대해 해석하지 않았다.

2.개선 계획

  • 단기 개선안: 방향·숫자 검사 문장과 LLM 미지원·실행 오류 조건을 늘려 차단과 기본 문구 전환을 자동으로 확인한다.
  • 중기 개선안: 심박 수신 중단과 급격한 변화가 지속되는 상황을 다루는 조건을 보강한다. 또한 결과 폴더가 비어 있어도 QA1~QA4의 측정 결과가 모두 생성되는지 자동으로 확인한다.
  • 장기 개선안: 실제 러닝 데이터와 사용자 평가를 확보하면 설명 이해도, 개인화 동작, 손목 센서 환경과 워치 입력부터 음성 출력까지의 전체 지연을 확인한다.

Zone2Runner는 필요한 AI 품질을 먼저 정의하고, 설계·구현·검증을 하나의 추적 가능한 흐름으로 연결했다.
