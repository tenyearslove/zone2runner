아래 결과는 실제 사람이나 워치에서 측정한 성능이 아니다. 미리 정한 사례와 가상 조건에 측정 항목을 적용한 결과다.

QAS와 같은 순서로 시나리오와 대표 지표를 반복하고, 오른쪽에 실제 결과를 적었다.

QA2●기능적응성응답 기반 개인 경계 조정
사용자가 초기값 또는 이전 러닝에서 조정된 Zone 2 범위로 달리다가, 현재 강도에서 말하기가 얼마나 편한지를 편함·보통·벅참 중 하나로 답한다.
[응답] 시스템은 사용자 응답에 따라 개인 경계를 조정하고, 변경된 값을 다음 세션의 시작값으로 저장한다. 한 세션의 경계 변경 폭은 제한한다.
[측정] 말하기 테스트 응답 기준과 앱이 조정한 Zone 2 상한의 차이 3bpm 이하
세션당 경계 변경 폭 10bpm 이하
말하기 테스트 응답 기준 5개와 시드 3개를 조합한 결과, 앱이 조정한 Zone 2 상한의 차이는 모두 3bpm 이하였다. 세션당 최대 변경 폭은 9.97bpm이었다.

[응답] 시스템은 규칙이 정한 방향·형식·숫자와 문장을 대조한다. 기준을 벗어난 문장은 차단하고, LLM을 사용할 수 없으면 기본 문구를 제공한다.
[측정] 방향 위반 문장의 출력 검사 통과율 0%
판정 방향과 어긋나는 시험 문장 10개가 모두 차단돼 출력 검사 통과율은 0%였다.
QA4●강건성2단계 심박 입력 보정
달리는 중 심박이 측정 범위를 벗어나거나 앞선 값들과 크게 다른 값이 잠깐 들어온다. 운동 강도가 실제로 바뀌어 달라진 심박이 계속 들어올 수도 있다.
[응답] 시스템은 신뢰하기 어려운 입력이 판정에 반영되지 않게 하고, 변화가 계속되면 새 심박 흐름에 맞춰 판정을 이어 간다.
[측정] 범위 밖 입력·일시적 이상값·지속 변화 처리 기대값 일치율 100%
범위 밖 4개 입력은 모두 정제됐다. 120bpm 구간의 1초 160bpm 점프는 기각됐다. 122→130bpm의 5초 변화 중 3개가 수용됐고, 130bpm이 이어진 뒤 최근 중앙값은 130bpm까지 올라갔다.
QA5—테스트가능성같은 조건의 반복 시험
실제 달리기와 워치를 반복해서 준비하기 어려운 개발 환경에서, 같은 조건으로 핵심 기능을 다시 확인한다.
[응답] 자동시험은 같은 가상 러너·설정·시드로 입력을 만들고, QA1~QA4의 측정 코드를 실행해 QA별 결과 파일을 저장한다.
[측정] 동일 시드로 만든 입력의 대표 항목 일치
QA1~QA4 자동 측정 결과 생성 성공
동일 시드로 생성한 5분 세션에서 표본 수, 첫 심박, 마지막 페이스가 일치했다. QA1~QA4의 측정 코드는 자동시험에서 실행돼 결과 파일을 생성한다.

검증 결과를 해석하는 방법

4
항목확인한 내용이 결과로는 말할 수 없는 내용
설명용이성대표 판정의 심박·개인 경계를 기록했고, 미리 정한 시험 문장에서 근거에 없는 숫자를 차단했다.모든 한국어 문장을 완벽하게 검사하거나 모든 사용자가 설명을 쉽게 이해한다는 뜻은 아니다.
기능적응성말하기 테스트 응답 기준과 앱이 조정한 Zone 2 상한의 차이가 3bpm 이하였고, 세션당 변경 한도를 지켰다.실제 사람의 유산소 역치를 오차 3bpm 이내로 찾았다는 뜻은 아니다.
제어가능성미리 정한 위반 문장이 출력 검사를 통과하지 못하도록 규칙이 차단했다.세상에 존재하는 모든 잘못된 표현을 막는다는 뜻은 아니다.
강건성범위 밖 심박과 최근 흐름과 맞지 않는 입력은 정제했고, 지속된 변화는 최근 세션 기준값에 반영했다.실제 손목 센서의 정확도와 모든 실외 환경을 검증했다는 뜻은 아니다.
테스트가능성같은 조건의 입력을 다시 만들고, 개발용 자동시험으로 QA1~QA4의 측정 코드와 결과 파일 생성을 확인했다.시뮬레이션 결과가 실제 사람과 센서의 정확도를 대신한다는 뜻은 아니다.

■공통 검증 기반

RunSource 교체, 가상 러너, 고정 시드, 코드 시험은 다섯 QAS를 워치 없이 반복 확인하게 해 준다. 전체 단위시험 167개 통과는 제품 정확도가 아니라 변경 후 자동으로 다시 확인할 수 있는 범위를 보여 주는 참고 정보다.

결론

5

1.주요 성과

  • 문제와 제약에서 다섯 가지 품질을 선정했다. 네 가지 AI 품질과 테스트가능성이 과제의 핵심 설계를 이끌었다.
  • 품질 요구를 실제 구조로 구현했다. 사용자 응답 기반 개인화, 규칙 중심의 판단, LLM 출력 검사, 센서 잡음 대응, 반복 가능한 시뮬레이션이 구현 코드와 실행 흐름에 연결된다.
  • 같은 기준으로 구현을 검증했다. 각 QAS에 측정 항목과 성공 기준을 두고, 사례와 가상 조건에서 구조가 의도대로 동작하는지 확인했다.
  • 확인한 범위와 확인하지 않은 범위를 나눴다. 실제 사람에 대한 생리학적 정확도나 사용자 효과를 자동시험 결과로 바꾸어 말하지 않았다.

3.개선 계획

  • 단기 개선안: 방향·숫자 검사 문장과 LLM 미가용·오류 조건을 늘려, 차단과 기본 문구 전환을 자동으로 확인한다.
  • 중기 개선안: 심박 수신 중단과 급격하지만 지속되는 변화를 다루는 조건을 보강하고, 빈 결과 폴더에서도 QA1~QA4 결과가 모두 생성되는지 자동으로 확인한다.
  • 장기 개선안: 실제 달리기와 사용자 평가가 가능해지면 설명 이해도, 개인화 동작, 손목 센서 환경, 워치 입력부터 음성 출력까지의 전체 지연을 확인한다.

이 과제의 핵심은 새로운 AI 모델을 만드는 것이 아니라, 필요한 AI 품질을 정하고 설계·구현·검증을 하나의 흐름으로 연결한 것이다.
