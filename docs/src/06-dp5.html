DP5. 설계 문제 정의

3

1.배경

  • 이 시스템은 검증하기 어려운 조건이 겹쳐 있다. 실제 사람의 Zone 2 경계 정답지가 없고, 같은 달리기를 정확히 반복할 수 없으며, 워치와 폰이 함께 동작한다.
  • 판정, 개인화, 코칭 로직은 개발 중에 계속 바뀐다. 매번 직접 달려야만 확인할 수 있다면 1인 과제에서 충분한 반복 검증이 어렵다.
  • 그래서 실제로 달리지 않아도 입력부터 판정·코칭·리포트까지 같은 코드 경로를 반복 확인하는 구조를 선택했다. 테스트가능성은 별도 AI QA가 아니라 네 QAS를 검증하게 하는 공통 기반이다.

2.문제점

  • 자극을 재현할 수 없다. 같은 심박 곡선을 두 번 만들 수 없으니 수정 전후를 같은 조건에서 비교할 수 없다.
  • 위험한 시나리오를 만들 수 없다. 위험 심박, 신호 두절 같은 중요한 상황은 실주행으로 만들기 어렵거나 위험하다.
  • 변경마다 실주행이면 검증이 생략된다. 변경 하나의 검증 비용이 러닝 한 번이면 자동화가 불가능하다.
  • 시뮬에는 함정이 있다. 시뮬을 만든 가정으로 시뮬을 채점하면 "정확하다"는 결론이 정의상 나온다. 시뮬의 역할 한계를 정직하게 그어야 한다.

DP5. 설계결정 및 근거

3

1.최종 채택 구조

후보 1: 입력 교체 + 반복 시뮬레이션 구조 채택

2.채택 근거

  • 재현이 검증의 전제다. 수정 전후를 같은 자극으로 비교할 수 없으면 회귀를 잡을 수 없다. 1안은 시나리오 재생으로 이것을 얻는다.
  • 위험하거나 드문 입력도 안전하게 넣을 수 있다. 범위 밖 심박이나 신호 두절처럼 실제 달리기로 만들기 어려운 조건을 시험 입력으로 재현할 수 있다.
  • 짧은 시간에 반복할 수 있다. 같은 입력으로 수정 전후를 비교하므로, 틈을 내어 진행하는 1인 과제에서도 변경할 때마다 다시 확인할 수 있다.
  • 여러 세션의 적응을 빠르게 확인한다. 경계를 정해 둔 가상 러너의 결과를 다음 입력에 다시 반영해, QA2의 8세션 과정을 자동으로 실행한다.
  • 시뮬레이션의 한계를 분리했다. 자동시험은 규칙과 구조가 설계대로 움직이는지 확인한다. 실제 사람의 유산소 역치 정확도와 실제 센서 성능은 이번 제출의 합격 판단에 포함하지 않는다.

3.보완 계획

  • 이번 과제에서 확인: 같은 입력과 고정 시드로 QA1~QA4의 합격 기준을 다시 만들 수 있고, 최근 JVM 단위시험 153개가 통과했다.
  • 향후 확인: 실제 기기 연결, 실제 센서 성능, 사람에 대한 정확도는 자동시험이 답하지 못한다. 제품화를 검토할 때 별도의 기기·사용자 평가로 확인한다.

Appendix. DP5 상세 설계 내역

A

A1.문제점이 걸리는 품질 속성

  • 같은 자극을 두 번 줄 수 없다 → 테스트가능성(재현 주입)
  • 위험/엣지 시나리오를 실주행으로 못 만든다 → 테스트가능성, 강건성
  • 변경마다 실주행 검증은 비용이 감당 불가 → 테스트가능성(자동 회귀)
  • 정답지가 없어 "정확하다" 채점 불가 → 시뮬 역할을 구조 검증으로 한정
  • 개인화 수렴에 여러 세션이 필요하다 → 결과를 다음 입력에 반영하는 반복 시뮬레이션
  • 워치-폰 결합이라 단독 실행이 어렵다 → 테스트가능성(기기 의존 분리)
  • 시뮬 자산도 만들고 유지해야 한다 → 수행효율성(비용의 정직한 인정)

A2.채택안의 검증 구조 4요소

요소하는 일
1. 소스 추상화실센서/가상 러너/수동 시뮬이 같은 인터페이스로 꽂힌다 — 검증과 운영이 같은 코드 경로
2. 반복 가상 러너경계를 정해 둔 가상 러너의 결과를 다음 세션 입력에 반영해 수렴 과정을 자동 실행
3. 순수 로직 분리판정 로직을 기기와 분리해 JVM 단위시험 153개로 자동 회귀 확인
4. 시뮬레이션 계측QA별로 정한 입력을 넣고 결과를 같은 지표로 기록

A3.품질 영향 비교

품질 속성(1안) 소스 추상화 + 시뮬 계측(2안) 실기기 결합 검증
테스트가능성★★★★★★★
강건성★★★★★★

별점의 범위: 1인 개발, 짧은 제출 일정, 반복해서 확인해야 하는 네 QAS라는 조건에서 비교했다. 테스트가능성은 이번에 선정한 AI QA가 아니라 검증을 돕는 지원 품질이다. 실제 기기 확인과 자동시험은 서로 대체하지 않으며, 이번 제출에서는 자동화된 구조 검증을 합격 판단에 사용한다.

A4.예상 질문

  • "시뮬로 통과한 게 무슨 의미가 있나?" → 시뮬이 답하는 것은 "로직이 설계대로 동작하는가"이지 "실제 사람에게 정확한가"가 아니다. 후자는 실주행 검증으로만 답해지며 그 계획이 별도로 있다. 이 한계를 설계 문서에 못 박았다.
  • "입력 인터페이스가 과한 설계 아닌가?" → 이 경계 덕분에 워치 없이도 같은 판정 로직에 시험 입력을 넣을 수 있다. 153개 시험은 정확도 점수가 아니라 이 구조가 제공하는 자동 회귀 범위를 보여 준다.

A5.용어 대조(심사용)와 근거 문헌

입력 자리를 인터페이스로 = Ports and Adapters(헥사고날), 의존성 역전(DIP) / 실물을 대신하는 가짜 = test double / 출력이 입력에 되먹임 = closed loop / 수정 후 자동 재확인 = regression test / 시뮬과 실환경의 간극 = sim-to-real gap

근거 문헌: ISO/IEC 25010(테스트가능성 정의) / Cockburn(포트와 어댑터) / Meszaros(테스트 대역) / 테스트 피라미드(Cohn, Fowler) / 이 저장소의 자체 이력(시뮬 자기 채점 함정을 직접 확인하고 시뮬 역할을 한정 — 실험 기록 §15-3)
