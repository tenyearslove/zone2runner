DP3. 제어가능성 — LLM의 권한을 제한하는 구조

생성 문장이 정해 둔 형식이나 사실의 범위를 벗어나거나 LLM을 사용할 수 없을 때, 코칭 출력을 제어하는 두 가지 설계안을 비교한다.

DP3. 설계 문제 정의

3

1.배경

  • 이 앱은 코칭 문장을 만들 때 폰 안에서 실행되는 LLM을 사용한다.
  • LLM은 자연스러운 표현을 만들 수 있지만 출력이 매번 같지는 않으며, 요청한 형식이나 제공된 숫자를 벗어날 수 있다.
  • 코칭은 달리는 중에 실시간으로 전달되므로 사람이 문장마다 확인할 수 없다. LLM이 맡는 범위와 실패했을 때의 대응을 시스템 구조로 정해야 한다.

2.문제점

  • 판단과 표현의 책임 범위를 정해야 한다. 코칭 방향과 숫자까지 LLM에 맡길지, 시스템이 사실을 먼저 확정하고 LLM에는 표현만 맡길지 결정해야 한다.
  • LLM을 사용할 수 없는 상황도 있다. 지원하지 않는 기종, 모델 미설치, 응답 지연이나 실행 실패에도 규칙 기반 코칭을 제공할 수 있어야 한다. 다만 모델 상태를 확인하는 동안에는 생성 코칭을 잠시 보류한다.
  • 고심박 대응은 문장 생성을 기다리면 안 된다. 설정된 임계값을 넘으면 생성 결과와 관계없이 즉시 안내할 별도 경로가 필요하다.
  • 자동 대응을 나중에 확인할 수 있어야 한다. 문장이 왜 차단되거나 기본 문구로 바뀌었는지 기록으로 남겨야 한다.

구조

규칙이 코칭 방향과 사용할 숫자를 확정하면 LLM은 그 내용을 문장으로 표현한다. 생성된 문장은 형식, 방향, 숫자 검사를 거치며, 검사를 통과하지 못하거나 LLM을 사용할 수 없으면 "속도 줄이기" 같은 짧은 문구로 바꿔 내보낸다. 고심박 경고는 LLM을 거치지 않으며, 모든 LLM 호출 경로와 차단 사유를 기록한다.

심박과 페이스를 프롬프트로 주고 LLM이 코칭 방향과 문장을 함께 정한다. 프롬프트 지시와 간단한 출력 필터로 잘못된 문장을 줄인다.

실패 대응 ★★★★★

DP3. 설계 결정과 근거

3

1.최종 채택 구조

1안인 규칙 판정과 LLM 표현 한정 구조를 채택했다.

2.채택 근거

  • LLM을 사용할 수 없거나 출력을 채택할 수 없을 때 자동으로 대응한다. 기준을 벗어난 문장은 차단하고, 모델 미지원·미설치·실행 오류가 확인되면 짧은 기본 문구로 바꾼다. 고심박 경고는 LLM을 거치지 않는다.
  • 통제 기준은 LLM 밖에 있다. 규칙이 방향·형식·숫자를 확인하고 기준에 맞지 않으면 기본 문구로 바꾼다. 2안은 판단과 표현을 모두 LLM에 맡기므로 결과가 맞는지 대조할 별도 기준이 필요하다.
  • 실패해도 코칭이 이어진다. LLM이 없거나 실패했을 때 1안은 짧은 기본 문구로 코칭을 이어 간다. 2안은 별도 대체 경로를 두지 않으면 코칭이 중단될 수 있다.
  • 통제 과정이 기록으로 남는다. 어떤 문장이 왜 차단됐고 언제 기본 문구로 바뀌었는지가 세션마다 기록되어 리포트에서 확인할 수 있다.
  • 이 결정은 DP2와 같은 구조를 사용한다. 판단을 규칙에 두었기 때문에 설명이 실제 판단과 연결되고(DP2), 생성된 문장을 대조할 기준도 시스템 안에 생긴다(DP3).

3.검증 결과

판정 방향과 어긋나는 시험 문장 10개와 허용되지 않은 숫자가 있는 시험 문장 5개는 모두 출력 검사에서 차단됐다. 두 측정의 출력 검사 통과율은 각각 0%였다. 이 결과는 미리 정의한 표현 범위에 대한 것으로, 모든 한국어 문장의 의미를 이해한다는 뜻은 아니다.

4.보완 계획

  • 단기 개선안: 속도 조절을 뜻하는 한국어 표현을 더 수집해 시험 문장과 차단 사유를 보강한다.
  • 장기 개선안: 실제 사용 기록이 쌓이면 사람이 문장 방향을 판정한 결과와 출력 검사 결과를 비교해 누락과 오차단을 줄인다.

Appendix. DP3 상세 설계 내역

A

A1.이 설계 결정이 다루는 품질 문제

  • 실시간 출력마다 사람이 검토할 수 없다 → 제어가능성
  • 모델 미지원, 다운로드 전, 지연이나 오류에도 코칭이 이어져야 한다 → 제어가능성
  • 판단 근거와 생성 문장이 같은 사실을 사용해야 한다 → 설명용이성
  • 같은 시험 문장에 출력 검사 규칙이 일관되게 동작해야 한다 → 테스트가능성

A2.채택안의 통제 단계 (판단 권한 제한부터 기록까지 순서대로 적용)

단계하는 일제어 유형
1. 격리판단은 규칙에 맡기고 LLM은 문장만 만들도록 권한을 제한한다.예방
2. 출력 검사형식(길이), 방향(판정과 모순이면 차단), 숫자(관측에 없는 숫자면 차단)교정
3. 기본 문구검사에 걸리거나 LLM이 실패하면 "속도 줄이기" 같은 짧은 문구로 바꿔 내보낸다보완
4. 안전 분리위험 심박 권고는 LLM을 거치지 않는다.안전 전환
5. 사용자 개입과 기록말하기 테스트로 판정 기준을 조정하고, 설정에서 LLM 사용을 켜고 끄며, 모든 호출 경로와 차단 사유를 세션에 기록한다.교정, 보완, 사후 확인

A4.용어 대조(심사용)와 근거 문헌

개입 가능성 = intervenability(ISO/IEC 25059 제어가능성의 핵심) / 맡기는 일 자체를 좁히는 통제 = architectural containment(구조적 격리) / 실패 시 기본 문구로 전환 = fail-safe fallback / 사람 개입 = HITL(루프 안 교정), HOTL(루프 위 감독) / 사후 확인 = audit

근거 문헌: ISO/IEC 25059(제어가능성 정의) / LLM 가드레일 계층 방어 서베이(구조적 격리가 가장 강한 층) / LLM 단독 판단 회피 권고 / 생성 결과 검사와 실패 경로 분리를 다룬 가드레일 연구

상세 설계와 참고 문헌은 별도의 DP3 설계 문서에 기록했다.
