DP3. 제어가능성 — LLM의 권한을 제한하는 구조

생성 문장이 정해진 형식이나 사실의 범위를 벗어나거나 LLM을 사용할 수 없는 상황에 대응하는 두 가지 설계안을 비교한다.

DP3. 설계 문제 정의

3

1.배경

  • 이 앱은 코칭 문장을 생성하는 데 기기에서 실행되는 LLM을 사용한다.
  • LLM은 자연스러운 문장을 만들 수 있지만 출력이 항상 같지는 않으며, 요청한 형식이나 제공된 숫자의 범위를 벗어날 수 있다.
  • 코칭은 달리는 중에 실시간으로 전달되므로 사람이 문장마다 확인할 수 없다. LLM이 맡는 범위와 실패했을 때의 대응을 시스템 구조로 정해야 한다.

2.문제점

  • 판단과 표현의 책임 범위를 정해야 한다. 코칭 방향과 숫자까지 LLM에 맡길지, 시스템이 사실을 먼저 확정하고 LLM에는 표현만 맡길지 결정해야 한다.
  • LLM을 사용할 수 없는 상황도 고려해야 한다. 지원되지 않는 기기, 모델 미설치, 응답 지연이나 실행 실패에도 규칙 기반 코칭을 제공할 수 있어야 한다. 다만 모델 상태를 확인하는 동안에는 생성 코칭을 보류한다.
  • 위험 심박 안내는 문장 생성을 기다리면 안 된다. 설정한 임계값을 넘으면 생성 결과와 관계없이 즉시 안내할 별도 경로가 필요하다.
  • 자동 대응의 근거를 사후에 확인할 수 있어야 한다. 생성 문장이 차단되거나 기본 문구로 전환된 이유를 기록으로 남겨야 한다.

구조

규칙이 코칭 방향과 사용할 숫자를 확정하면 LLM은 그 내용을 문장으로 표현한다. 생성된 문장은 형식·방향·숫자 검사를 거치며, 검사를 통과하지 못하거나 LLM을 사용할 수 없으면 "속도를 줄이세요"와 같은 기본 문구로 전환한다. 위험 심박 안내는 LLM을 거치지 않으며, 모든 LLM 호출 경로와 차단 사유를 기록한다.

심박과 페이스를 프롬프트로 주고 LLM이 코칭 방향과 문장을 함께 정한다. 프롬프트 지시와 간단한 출력 필터로 잘못된 문장을 줄인다.
장점

실패 대응 ★★★★★

설명용이성 ★★★
문맥을 풍부하게 표현할 수 있지만 판단 근거와의 연결은 별도로 확인해야 한다.

DP3. 설계 결정과 근거

3

1.최종 채택 구조

1안인 규칙 판정과 LLM 표현 한정 구조를 채택했다.

2.채택 근거

  • 잘못된 출력을 자동으로 차단한다. 생성 문장이 확정된 방향·형식·숫자의 범위를 벗어나면 기본 문구로 전환한다. 위험 심박 안내는 문장 생성과 분리해 LLM을 거치지 않는다.
  • LLM과 독립된 통제 기준이 있다. 시스템이 생성 문장을 대조할 방향·형식·숫자를 먼저 확정한다. 판단과 표현을 모두 LLM에 맡기는 2안은 결과를 독립적으로 확인할 기준을 별도로 마련해야 한다.
  • LLM을 사용할 수 없어도 코칭을 이어 갈 수 있다. 모델 미지원·미설치·실행 오류가 확인되면 기본 문구를 사용한다. 2안은 별도 대체 경로가 없으면 코칭이 중단될 수 있다.
  • 통제 과정이 기록으로 남는다. 생성 문장이 차단되거나 기본 문구로 전환된 이유를 세션에 기록하고 리포트에서 확인할 수 있게 한다.
  • DP2와 같은 책임 분리 원칙을 따른다. 규칙이 판단을 담당하므로 설명을 실제 판단과 연결할 수 있고(DP2), 시스템은 생성 문장을 검사할 기준도 유지할 수 있다(DP3).

3.검증 결과

판정 방향과 어긋나는 시험 문장 10개와 허용되지 않은 숫자가 있는 시험 문장 5개는 모두 출력 검사에서 차단됐다. 두 측정의 출력 검사 통과율은 각각 0%였다. 이 결과는 미리 정의한 표현 범위에 대한 것으로, 모든 한국어 문장의 의미를 이해한다는 뜻은 아니다.

4.보완 계획

  • 단기 개선안: 속도 조절을 나타내는 한국어 표현을 추가로 수집해 시험 문장과 차단 사유를 보강한다.
  • 장기 개선안: 실제 사용 기록이 쌓이면 사람이 문장 방향을 판정한 결과와 출력 검사 결과를 비교해 누락과 오차단을 줄인다.

Appendix. DP3 상세 설계 내역

A

A1.이 설계 결정이 다루는 품질 문제

  • 실시간 출력마다 사람이 검토할 수 없다 → 제어가능성
  • 모델 미지원, 다운로드 전, 지연이나 오류에도 코칭이 이어져야 한다 → 제어가능성
  • 판단 근거와 생성 문장이 같은 사실을 사용해야 한다 → 설명용이성
  • 같은 시험 문장에 출력 검사 규칙이 일관되게 동작해야 한다 → 테스트가능성

A2.채택안의 통제 단계 (판단 권한 제한부터 기록까지 순서대로 적용)

단계하는 일제어 유형
1. 격리판단은 규칙에 맡기고 LLM은 문장만 만들도록 권한을 제한한다.예방
2. 출력 검사문장의 길이와 형식을 확인하고, 판정과 모순되는 방향이나 관측값에 없는 숫자가 포함되면 차단한다.교정
3. 기본 문구출력 검사를 통과하지 못하거나 LLM 실행에 실패하면 "속도를 줄이세요"와 같은 기본 문구로 전환한다.보완
4. 안전 분리위험 심박 권고는 LLM을 거치지 않는다.안전 전환
5. 사용자 개입과 기록사용자는 말하기 테스트로 개인 경계를 조정하고 설정에서 LLM 사용 여부를 바꿀 수 있다. 시스템은 모든 호출 경로와 차단 사유를 세션에 기록한다.교정, 보완, 사후 확인

평가 조건: 기기에서 LLM을 실행하고 실시간으로 코칭 문장을 제공하며, LLM을 사용할 수 없는 상황에도 코칭을 이어 가야 한다는 조건에서 두 안을 비교했다. 사람이 모든 출력을 미리 검토할 수 있는 서비스라면 2안의 평가가 달라질 수 있다.

A4.용어 대조(심사용)와 근거 문헌

ISO/IEC 25059에서 제어가능성의 핵심으로 다루는 개념은 개입 가능성(intervenability)이다. 모델에 맡기는 일의 범위를 구조적으로 좁히는 방식은 architectural containment(구조적 격리), 실패 시 기본 문구로 전환하는 방식은 fail-safe fallback에 해당한다. 사람의 개입은 HITL(루프 안 교정)과 HOTL(루프 위 감독), 사후 확인은 audit에 대응한다.

근거 문헌은 ISO/IEC 25059의 제어가능성 정의, LLM 가드레일의 계층 방어와 구조적 격리를 다룬 서베이, LLM 단독 판단 회피 권고, 생성 결과 검사와 실패 경로 분리에 관한 연구다.

상세 설계와 참고 문헌은 별도의 DP3 설계 문서에 기록했다.
