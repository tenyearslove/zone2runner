최종 아키텍처 (2/2) — 입력에서 코칭까지

3

읽는 순서: 실제 센서나 시험 입력(A1) → 허용 범위와 수신 시각 검사(A2) → 최근 신호 정리(A3) → 존 판정·개인 경계·분석(A4~A6) → 코칭 문장 표현(A7) → 방향과 숫자 검사 및 안전 규칙(A8)이다. RunEngine(A9)이 이 순서를 매초 실행한다. 규칙이 판정과 문장에 사용할 값을 먼저 확정하고, LLM은 문장만 만든다.

과제 소개 요구사항 설계 구현/검증 결론

모듈 B·C: 설명과 분석 서비스

3

설명 모듈(B)은 판정에 실제로 사용한 값으로 세션과 개인화 설명을 만들고 저장한다. 세션 중 LLM을 호출하면 입력값, 프롬프트, 채택·차단·기본 문구 경로와 걸린 시간을 함께 기록한다. 분석 모듈(C)은 한 세션의 구간·경사·워밍업과 여러 세션의 비교·추세를 계산한다.

과제 소개 요구사항 설계 구현/검증 결론

모듈 D·E: 운영 서비스와 저장

3

운영 모듈(D)은 폰·워치 화면, 음성, 세션 제어를 제공한다. 사용자는 말하기 테스트로 개인 경계를 조정하고, 설정에서 코칭 방식을 바꾸며, 리포트에서 LLM 사용 기록을 확인한다. 저장 모듈(E)은 세션, 개인 경계, 프로필과 설정을 기기에 보관한다.

과제 소개 요구사항 설계 구현/검증 결론

모듈 F: 개인화와 반복 검증

3

개인 적응(F1)은 말하기 테스트 응답이 들어올 때 베이지안 방식으로 경계를 갱신하고 조정한 경계를 다음 세션의 시작값으로 저장한다. 반복 검증 구조(F2)는 가상 센서 입력과 고정된 시험 문장으로 QA1~QA4를 반복 확인하고, 같은 설정과 시드의 입력이 재현되는지 검증한다. Nano 모델 관리 모듈(A7-1)은 모델 상태를 확인하고 세션 밖에서 다운로드를 요청한다.

■세 설계 결정이 한 아키텍처에 모이는 방식

DP1의 개인 경계 갱신, DP2의 규칙 중심 판정과 근거 기록, DP3의 LLM 출력 검사가 하나의 실행 흐름으로 이어진다. QA4 강건성은 입력 검사와 경계 여유 구간에, QA5 테스트가능성은 입력 교체와 시드 기반 시뮬레이션에 공통 구조로 반영했다.
